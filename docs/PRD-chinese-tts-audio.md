## 1. 목적과 사용자 가치

중국어 학습자가 정답을 확인할 때 A열 표제어의 발음을 듣고, 필요하면 같은 발음을 반복해서 들을 수 있게 한다. 성조와 다음자 발음을 확인하는 단어 학습부터 문장의 끊어읽기를 듣는 학습까지 같은 재생 경로를 사용한다.

예를 들어 모드1에서 `经济` 카드를 뒤집으면 병음·뜻이 나타난 뒤 중국어 발음이 한 번 들린다. 사용자가 스피커를 누르면 처음부터 다시 듣는다. 모드2에서 틀렸을 때는 사용자가 입력한 오답이 아니라 공개된 정답 표제어를 읽는다.

여기서 **중국어 문제는 인증된 프로필의 `contentType === "zh"`인 문제**다. 한자 포함 여부, 프로필 이름·ID, 문제 모드로 중국어 여부를 추정하지 않는다.

범위 밖: 발음 녹음·평가, 음성 인식, 듣고 맞히는 새 모드, 음색·속도·자동재생 사용자 설정, 영어 등 다국어 음성, 예문 생성, 음성 다운로드 UI, 전체 단어 선생성, 등록 직후 백그라운드 생성, 오프라인 음성 보장.

### 음성 생성·보관 정책

1. 처음 듣는 표제어는 정답 공개 흐름에서 요청할 때 합성한다. 따라서 첫 재생에는 합성 대기가 생길 수 있다.
2. 정상 생성한 MP3는 R2에 저장한다. 이후 세션·기기를 바꿔도 같은 프로필의 동일 내용·발음 설정이면 저장한 파일을 재생한다.
3. 표제어·병음·모델·음색·속도·발음 처리 버전이 바뀌면 새 파일을 생성한다. 원문과 발음 설정은 함께 식별하며 시트에 오디오 URL·상태 열을 추가하지 않는다.
4. 기존 단어와 시트에서 직접 추가한 문장도 같은 요청 경로로 처리한다. 등록 화면을 거치지 않았어도 음성을 만들 수 있다.
5. 음성 파일은 자동 만료시키지 않는다. 단어 삭제나 설정 변경으로 사용하지 않게 된 파일도 즉시 삭제하지 않으며, 운영 정리 시 별도로 제거한다.
6. 등록 직후 선생성은 음색 확정·첫 버전 검증 후 추가한다. 이때도 등록 성공과 음성 생성 성공은 독립적으로 처리하고, 준비되지 않은 음성은 요청 시 생성하는 경로를 유지한다.

R2는 파일 보관소이고 브라우저 Blob 캐시는 같은 세션의 반복 재생용이다. 첫 버전에는 Worker Cache API 계층을 추가하지 않는다. R2 파일은 Worker 인증을 통해서만 전달하며 공개 다운로드 경로를 만들지 않는다.

### 문장 지원의 경계

이미 A열에 있는 200자 이하 문장은 읽을 수 있어야 한다. 문장부호·숫자·공백을 포함한 텍스트를 TTS가 거부하거나 잘라 읽어서는 안 된다. 긴 표제어에서도 카드와 재생 버튼이 가려지지 않아야 한다.

현재 중국어 등록 검증은 A열에 한자만, B열에 병음을 요구한다. 따라서 **문장부호가 있는 문장 등록**, 문장에 적합한 모드2 채점, 문장 전용 학습 UI는 별도 작업이다. 이번 기능이 등록 제한까지 해제한다고 설명하지 않는다. 문장 TTS 검증은 시트 조회와 같은 형태의 테스트 데이터로 수행한다.

## 3. 화면별 동작

기능이 운영 설정에서 활성화되고 텍스트가 유효한 경우의 정책이다.

| 화면·사건 | 스피커 | 자동 재생 | 음성 요청 시작 |
|---|---|---|---|
| 모드1 앞면 | 없음 | 없음 | 없음 |
| 모드1 플립 중 | 조작 불가 | 없음 | 플립 클릭 뒤 현재 표제어 준비 가능 |
| 모드1 플립 완료 | 병음 옆. 병음이 없으면 독립된 같은 줄 | 최초 공개에 1회 시도 | 준비하지 못했다면 이때 요청 |
| 모드2 입력 중 | 없음 | 없음 | 없음 |
| 모드2 정답 | 결과 화면 없음 | 없음 | 없음 |
| 모드2 오답 결과 | 정답 표제어 옆 | 결과 화면 진입에 1회 시도 | 결과 공개 직후 |
| `generic` 전체 | 없음 | 없음 | 없음 |
| 다음 문제·종료·완료·로그인 복귀 | 이전 버튼 제거 | 이전 음성 즉시 중단 | 이전 요청 취소 |

### 3.1 모드1

1. 앞면을 클릭하거나 키보드로 활성화하면 기존 0.55초 플립이 시작된다.
2. 플립이 끝난 후 현재 문제의 자동재생 기회를 한 번 소비한다. 음성 준비가 늦으면 같은 뒷면에 머무는 동안 준비 완료 후 재생한다.
3. O/X는 기존대로 공개 시 사용할 수 있다. 음성 생성이나 재생 완료를 기다리지 않는다.
4. 사용자가 플립 완료 전 판정해 다음 문제로 이동하면 이전 음성은 재생하지 않는다.
5. 모션 줄이기 설정에서는 플립을 생략하고 뒷면 표시 직후 같은 정책을 적용한다.

### 3.2 모드2

오답 결과가 표시된 순간에만 정답의 A열을 읽는다. 병음·뜻·사용자의 오답·안내 문구는 읽지 않는다. 빈 입력 오답도 같은 규칙을 적용한다. `다음`은 음성 준비·재생 중에도 즉시 동작한다.

### 3.3 수동 반복 재생

버튼을 누르면 현재 표제어를 처음부터 재생한다. 재생 중 다시 누르면 기존 소리를 끊고 처음부터 시작한다. 로딩 중 연속 클릭은 같은 준비 작업 하나로 합친다. 수동 재생이 먼저 시작된 경우 뒤늦은 자동재생은 추가로 시작하지 않는다.

음성 버튼은 판정·플립·폼 제출을 발생시키지 않으며 정답 수와 학습 기록을 바꾸지 않는다.

## 4. 재생 상태와 오류 UX

| 상태 | 표시와 조작 | 후속 동작 |
|---|---|---|
| 대기·준비 완료 | 스피커 아이콘, `aria-label="발음 듣기"` | 누르면 재생 |
| 준비 중 | 같은 자리의 작은 로딩 표시, `aria-busy="true"` | 중복 클릭은 합치고 학습 버튼은 활성 유지 |
| 재생 중 | 강조색 스피커 | 누르면 처음부터 재생 |
| 자동재생 차단 | 일반 스피커로 복귀, 토스트 없음 | 준비된 음성을 다음 스피커 클릭에서 재생 |
| 자동 요청 실패 | 일반 스피커로 복귀, 토스트 없음 | 사용자가 누르면 새로 한 번 요청 |
| 수동 요청 실패 | 버튼 근처 `발음을 불러오지 못했어요. 다시 눌러 주세요.` | 버튼 재시도 가능, 다음 문제에서 메시지 제거 |
| 수동 요청 뒤 브라우저 차단 | `발음이 준비됐어요. 다시 눌러 주세요.` | 다음 클릭에서 준비된 음성을 즉시 재생 |
| R2 조회 실패 | 자동 요청이면 조용히, 수동이면 일반 음성 실패 안내 | 파일이 없는 것으로 추정해 재합성하지 않음. 학습은 계속 가능 |
| 합성 성공 후 R2 저장 실패·대기 초과 | 생성된 음성은 정상 재생, 저장 오류는 화면에 표시하지 않음 | 같은 세션은 Blob 재사용. 이후 요청에서 R2에 파일이 없으면 다시 생성 가능 |
| 200자 초과 | 자동 요청 없음. 비활성 아이콘 + `발음은 200자까지 지원해요.` | 학습·판정은 계속 가능 |
| 빈 표제어 등 읽을 수 없는 데이터 | 자동 요청 없음. 비활성 아이콘 + `읽을 표제어가 없어요.` | 학습 오류로 승격하지 않음 |
| 운영 기능 비활성 | 스피커 없음 | 기존 학습 화면 유지 |

`Audio.play()`는 사용자 조작 이후에도 브라우저 정책에 따라 거부될 수 있다. 따라서 “학습 시작을 눌렀으므로 자동재생 허용”을 전제로 삼지 않는다. 최초 수동 클릭에 음성 다운로드가 필요했다면, 다운로드 후 다시 클릭해야 하는 경우를 위 상태로 처리한다. [브라우저 재생 정책](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)

네트워크 단절·제공자 오류·타임아웃·저장소 장애는 음성 기능에만 영향을 준다. 저장된 파일을 정상 조회하면 제공자 장애 중에도 해당 음성을 재생할 수 있다. 자동 재시도·오류 토스트·학습 기록 재시도 큐 적재는 하지 않는다. R2 쓰기만 실패하면 이미 생성된 음성을 재생하고 저장 실패를 학습 오류로 승격하지 않는다. **앱 인증 실패 `401`은 예외**로, 기존 공통 인증 계약대로 로그인으로 이동하고 음성도 정지한다. 제공자 API 키 오류를 앱의 `401`로 전달하지 않는다.

탭이 숨겨지거나 화면을 떠나면 준비·재생을 중단한다. 돌아왔을 때 자동으로 이어서 재생하지 않고 수동 버튼을 제공한다. 이때 그 문제의 자동재생 기회는 이미 소비된 것으로 본다.

## 5. 음성 콘텐츠·발음 품질

### 5.1 읽는 대상

- `word.hanzi`를 TTS의 `text`로 사용한다. 필드명은 기존 A열 운반자 계약을 유지한다.
- `word.pinyin`은 선택적 발음 참고 데이터다. 첫 버전에서는 화면 표시와 저장 파일 식별에 사용하며 Qwen에 보내지 않는다. 빈 B열도 재생할 수 있다.
- 공백 트림·NFC 정규화 후 길이를 센다. 본문 안 공백·문장부호·숫자는 의미를 유지한다. 201자 이상을 임의로 자르거나 여러 과금 요청으로 나누지 않는다.
- 표준 중국어로 읽으며, 한국어 뜻을 함께 읽거나 제공자가 해설을 덧붙이지 않게 한다.

### 5.2 병음의 보장 범위

**첫 버전은 A열 원문을 합성하며 B열 병음을 강제 적용하지 않는다.** 선택 모델의 `hot_fix` 발음 교정은 공식적으로 미지원이다. SSML은 음색별 지원 조건이 있고 기본 음색 `longanfengyue`의 지원이 확인되지 않았으므로 비활성화한다. 자연어 말투 지시를 정확한 병음 지정으로 취급하지 않는다. [Qwen 발음 교정 제약](https://docs.qwencloud.com/api-reference/speech-synthesis/cosyvoice/client-events), [SSML 지원 조건](https://docs.qwencloud.com/developer-guides/speech/ssml)

B열이 없으면 진단 상태는 `absent`, 있으면 `ignored / provider_hint_unsupported`다. 화면의 병음은 그대로 유지하고 힌트 미적용을 사용자 오류로 표시하지 않는다. 병음을 바꿔도 의도한 발음으로 바뀐다는 보장은 없지만, 내용 변경을 구분하기 위해 정규화한 병음은 R2 객체 키에 계속 포함한다.

따라서 `行 / xíng`과 `行 / háng`은 같은 A열을 합성하므로 두 발음을 구별해 출력한다는 기존 요구를 이번 범위에서 제외한다. 문맥이 있는 다음자와 경성·변조·문장 운율은 실제 청취로 확인한다. 병음 분해기·SSML 강제 지정은 지원 음색 검증 후 후속으로 추가한다. 구체적인 정책은 [아키텍처 §5](architecture/chinese-tts-audio.md#5-병음-힌트-처리)를 따른다.

### 5.3 제공자 확정과 이용 조건

**2026-09-15 소유자 결정: QwenCloud의 `qwen-audio-3.0-tts-flash` 사용, API 키 발급 완료.** 기존 MiniMax 선택 기록을 대체한다. 이름이 비슷한 `qwen3-tts-flash`와는 다른 모델이다. 이번 구현에는 Qwen adapter 하나를 포함하고 제공자 경계는 유지한다.

구현 기본 음색은 공식 목록의 표준 중국어 음색 `longanfengyue`, 속도는 1.0이다. 음색은 아직 청취로 확정하지 않았다. 국제 DashScope endpoint를 기본 경로로 사용하며 발급한 키의 이 endpoint·모델 접근은 출시 전에 확인한다. 키 발급을 Worker 시크릿 주입·과금 계정 준비·연결 성공으로 기록하지 않는다. [모델·요금](https://www.qwencloud.com/models/qwen-audio-3.0-tts-flash), [공식 음색 목록](https://docs.qwencloud.com/developer-guides/speech/voice-list/qwen-audio-tts)

공시 가격은 **1만 과금 문자당 $0.15**다. QwenCloud 화면의 Free Tier 표시는 확인했으나 계정별 무료 제공량·유효기간은 미확인이다. 무료 제공을 운영 전제로 삼지 않는다. 요금은 제공자의 실제 `usage.characters` 계량으로 확인하며, 원문 코드 포인트 수와 과금 문자 수를 동일시하지 않는다. SDK 문서의 길이 계산은 한자를 2로 세므로 단순 한자 수만으로 비용을 확정하지 않는다. [문자 계산 규칙](https://docs.qwencloud.com/api-reference/speech-synthesis/cosyvoice/python-sdk), [과금 사용량 필드](https://docs.qwencloud.com/api-reference/speech-synthesis/cosyvoice/server-events)

예를 들어 실제 계량이 4만 과금 문자라면 합성료는 $0.60이며 R2 비용은 별도다. 생성·저장된 파일의 재사용에는 새 합성 호출이 없다. API 키 원문은 문서·이슈·저장소에 넣지 않는다.

## 6. 접근성과 화면 품질

- 버튼 터치 영역 최소 44×44px, 인라인 SVG 20px, 기존 색·포커스 토큰 사용.
- 일반 상태의 접근성 이름은 `발음 듣기`. 로딩·오류 상태는 짧은 한국어 설명을 연결한다. 수동 오류만 `aria-live="polite"`로 알린다.
- `<button>` 안에 스피커 `<button>`을 넣지 않는다. 모드1 앞면 클릭 영역과 뒷면 제어 영역을 분리한다.
- 공개 전 뒷면·스피커가 키보드 탐색이나 접근성 트리에 노출되지 않게 한다. CSS로 뒤집어 숨기는 것만으로 처리하지 않는다.
- 공개 전 앞면·입력란에 있던 키보드 초점은 공개 후 재생 버튼으로 옮긴다. 사용할 수 없거나 `generic`이면 첫 판정 버튼 또는 `다음`으로 옮긴다. 사용자가 이미 다른 제어로 옮긴 초점을 뒤늦게 빼앗지 않는다. 키보드로 공개·재생·판정까지 수행할 수 있어야 한다.
- 긴 표제어·병음은 줄바꿈하며 카드 내부 스크롤을 허용한다. `O/X`, `다음`, `종료`가 가려지면 안 된다. 390px 너비와 200% 확대에서 확인한다.
- 로딩·실패 때문에 카드 높이가 반복해서 튀지 않도록 컨트롤과 메시지 영역을 확보한다.

## 7. 성능과 비용 목표

아래 지연 수치는 **출시 검증 목표이며 현재 측정값이 아니다**. 서울에서 사용할 실제 모바일 브라우저·네트워크로 단어/문장을 구분해 측정한다.

| 항목 | 목표·한계 |
|---|---|
| 준비된 음성의 수동 반복 재생 | 클릭→재생 시작 p95 200ms 이내, 추가 API 요청 0회 |
| R2 저장 파일 재생 | 공개 완료→재생 시작 p95 1초 이내, 제공자 호출 0회 |
| 신규 합성·저장, 20자 이하 | 공개 완료→재생 시작 p95 4초 이내 |
| 신규 합성·저장, 21~200자 | 공개 완료→재생 시작 p95 10초 이내 |
| 요청 대기 상한 | R2 조회 2초 + 합성 12초 + 저장 단계 2초, 클라이언트 준비 20초. 저장 대기 초과는 생성된 음성 반환 |
| 학습 진행 | 오디오 작업을 기다리는 `await`·버튼 잠금 없음 |
| 동시 재생 | 앱의 현재 탭에서 최대 1개. 다른 탭까지 조정하지 않음 |

브라우저 자동재생 차단은 합성 실패와 분리해 집계한다. Worker는 R2 조회/합성/저장 지연과 저장 결과를 측정할 수 있지만 실제 스피커 재생 성공은 알 수 없으므로, 재생 지연은 브라우저 검증 기록에서 측정한다. 이 버전에 새 사용자 분석 수집 API를 추가하지 않는다.

비용은 `실제 합성한 과금 문자 수 × 제공자 단가 + R2 저장량·읽기·쓰기 요금`으로 계산한다. 정상 보관 후의 반복 재생에는 TTS 합성 비용이 추가되지 않는다. 세션 문제 수는 현재 1~500으로 설정 가능하므로 60문제를 고정 상한으로 가정하지 않는다. 모든 요청이 새로운 내용·설정인 예시로 하루 60회·평균 4자·30일이면 7,200자, 평균 50자면 90,000자의 원문이다. 이는 과금 문자 수와 구분한다. 실제 합성 비용은 신규 파일·설정 변경·저장 실패·동시 최초 요청 수를 반영해 제공자 계량으로 확인한다.

저장 크기의 예시로 파일당 100KB를 가정하면 1만 개는 약 1GB다. 실제 크기는 문장 길이·인코딩에 따라 달라지고 이전 버전의 파일도 저장량에 포함한다. R2 Standard의 무료 할당량은 계정 전체 이용량을 기준으로 확인한다. [R2 요금](https://developers.cloudflare.com/r2/pricing/)

지속 저장이 전역 중복 합성이나 월 지출 상한까지 보장하지는 않는다. 서로 다른 요청이 동시에 최초 합성을 시작하면 중복 과금이 생길 수 있다. 출시 시 선택 계정의 예산 알림·이용 한도를 확인하고, 음성 기능만 끌 수 있는 운영 설정을 둔다.

## 9. 청취 검증과 출시 조건

선택한 Qwen 모델·음색·속도로 20개 표본을 생성한다: 일반 단어 3개, 문맥이 있는 다음자 6개, 경성·`ü`·변조 5개, 짧고 긴 문장 6개. 최소 표본에 `经济`, `银行 / 行走`, `长大 / 长短`, `重要 / 重复`, `妈妈`, `女儿`, `你好`, `不对`, `一个`, `今天下午三点，我们一起去图书馆学习。`, `银行的行长正在开会。`를 포함한다. 고립된 `行`의 두 병음은 제한 사항 확인 사례로 따로 기록하며 발음 분리 성공을 필수 통과 조건으로 삼지 않는다.

평가자는 표준 중국어 발음을 판별할 수 있는 사람으로 정한다. 텍스트 누락·추가와 목표 다음자 오독은 표본 전체에서 0건이어야 한다. 문장 자연스러움은 문장별 5점 척도 평균 4점 이상을 출시 목표로 둔다. 자동 인식 결과만으로 합격 판정을 대체하지 않는다.

출시 전 필요한 결정·증거:

| 항목 | 제안 또는 필요한 결과 | 소유 |
|---|---|---|
| 제공자·모델 | QwenCloud / `qwen-audio-3.0-tts-flash` 확정 완료 | 소유자 + 구현 담당 |
| 음색 | `longanfengyue` 기본값, 출시 전 청취 검증 | 청취 평가자 |
| 속도 | 단어·문장 공통 1.0. 변경 시 전체 표본 재검증 | 소유자 |
| 계정·키·요금 | API 키 발급 완료. 국제 endpoint·모델 접근, 무료량/과금 조건, `DASHSCOPE_API_KEY` 주입 확인 필요 | 운영 담당 |
| 음성 저장소 | 운영/검증용 비공개 R2 버킷·바인딩, 자동 만료 없음 확인 | 운영 담당 |

| 구현 검증 | AC-01~24, 모바일 실기기, 기존 빌드·테스트·린트 | 구현 담당 |

원안의 제공자 결정 조건은 Qwen 모델 확정으로 충족했다. 계정·실제 음질·지연·출시 검증은 별도 확인 항목이며, 제공자를 다시 선택하는 조건으로 구현을 막지 않는다. 실제 합성 전 계정의 사용 가능 잔액과 비용 조건을 확인한다.

## 10. 기존 문서 반영 계획

구현 시 [PRD.md](PRD.md) §11에서 TTS를 비목표에서 제외하고 §7.3·§9.2에 API·음성 흐름을 연결한다. [PRD-general.md](PRD-general.md)에는 B열의 표시·저장 키 용도와 첫 버전의 병음 미적용 정책과 `/api/words`의 음성 지원 정보를 추가한다. [design-prd.md](design-prd.md) §4.2·§4.3·§4.6에는 버튼·상태·콘텐츠 분기를 반영한다. 기존 PRD의 최종 정리는 TTS-17에서 수행한다. TTS-16은 서버·화면 완료 후 자동 회귀를 검증하고 TTS-15의 실제 환경 준비를 기다리지 않는다. 이번 초안 단계에서 기존 문서의 확정 상태를 소급해 변경하지 않는다.
