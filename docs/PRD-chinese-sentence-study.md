# 중국어 문장 학습 PRD

> 작성일: 2026-09-24 · 상태: #173~#177 구현·병합 완료, #178 통합 검증·문서 정리 중 · 대상: `contentType: zh`
>
> 단어와 문장을 같은 시트·학습 흐름에서 다룬다. 이 문서는 문장 등록·병음 검증·중국어 채점·긴 콘텐츠 표시의 변경 계약이다. 구현 후 해당 범위에서 기존 PRD와 등록 킷의 한자 전용 규칙을 대체한다. TTS 제공자·저장·인증 계약은 [TTS PRD](PRD-chinese-tts-audio.md)를 유지한다.

## 1. 목적과 현재 문제

`我今天很忙。`를 병음·뜻과 함께 등록하고, 문장 전체를 보고 뜻을 회상하거나 뜻을 보고 중국어를 입력하고, 정답 공개 후 발음을 들을 수 있어야 한다. 기존 단어와 같은 모드별 진도·복습 규칙을 사용한다.

구현 전에는 프런트·Worker·추출 킷이 한자 전용 입력과 엄격한 병음 일치, 공백만 완화한 채점을 사용했다. #173~#177에서 문장 입력 계약, 비차단 병음 검토 경고, `zh` 문장부호 채점, 긴 문장 UI, TTS 원문·길이 회귀를 구현했다. #178은 동일한 fixture 원문이 등록부터 원문 행 기록까지 이어지는지 통합 검증하고 문서의 구규칙을 정리한다. 실제 제공자의 문장 발음 품질은 여전히 별도 청취가 필요하다.

## 2. 범위와 유지할 계약

- 단어·구·문장을 모두 A열의 학습 항목으로 취급한다. 문장 타입 필드, 신규 시트 열, 새 퀴즈 모드를 추가하지 않는다.
- JSON `version: 1`, `hanzi/pinyin/meaning`, 시트 A~G열, `tab + 원문 A열` 행 식별, 등록 배치 최대 100건, 프로필·세션·졸업·복습 규칙을 유지한다.
- `generic`의 검증·채점 정책은 유지한다. 중국어 여부는 프로필의 `contentType`으로 결정한다.
- 번역 동의어·어순 대체·의미 기반 채점, 간번체 자동 변환, 병음 답안, 자동 예문·문장 생성, 발음 평가, TTS 분할 합성은 범위 밖이다. 사용자가 제공한 문장 자체를 A열 학습 항목으로 등록·학습하는 것은 범위 안이다.

## 3. 등록과 데이터 계약

### 3.1 A열 중국어 원문

신규 등록은 NFC와 앞뒤 공백 제거 후 1~200 Unicode 코드 포인트이며 한자를 최소 1자 포함해야 한다. UTF-16 코드 유닛 길이를 사용하지 않는다. 내부 공백·문장부호는 원문에 보존한다.

허용 문자는 기존 한자 범위 U+4E00~U+9FFF, ASCII 영문자·숫자, 전각 영문자·숫자, 일반 공백 U+0020·전각 공백 U+3000, 아래 문장부호다. 이 목록 밖의 문자, 탭·줄바꿈·제어문자·이모지는 등록 오류다. 확장 한자 범위 확대는 이번에 포함하지 않는다.

```text
，。！？；：、,.!?;:（）()【】[]《》〈〉“”‘’「」『』"'…—-·／/％%＋+＝=．
```

원문 속 숫자·영문은 보존한다. `我有2本书。`, `我用AI学习中文。`도 등록한다. 한자가 없는 `Hello!`, `123`은 차단한다. 201자 이상이면 길이를 안내하며 자동 절단하지 않는다.

### 3.2 B열 병음과 C열 뜻

- 병음·뜻은 필수다. 병음은 NFC·앞뒤 트림 후 최대 1,000 코드 포인트다. 뜻은 기존 비어 있지 않음 검증을 유지한다.
- 병음은 기존 성조 부호가 있는 라틴 문자·ü·공백·아포스트로피와 위 문장부호를 허용한다. 탭·개행·제어문자와 숫자 성조(`ni3 hao3`)는 오류다. 최소 하나의 성조 부호를 요구하는 기존 형식 정책을 유지한다. 경성 음절은 다른 유성조 음절과 함께 쓸 수 있다.
- 숫자는 병음에서 발음대로 풀어 적는다(원문 `2本` → 병음 `liǎng běn`). 원문 영문 약어는 병음에서 그대로 적을 수 있도록 ASCII 알파벳 전체를 허용한다. 무성조 병음 전체를 허용하는 정책은 아니다.
- **형식 오류는 차단**, 한자-병음의 의미적 불일치·자동 검증 불가만 **비차단 경고**로 바꾼다. 단어·문장 자동 분류에 기대지 않고 모든 `zh` 항목에 같은 정책을 적용한다. 이는 기존 단어의 의미 불일치 차단도 경고로 완화하는 의도적인 변경이다.
- 기존 문자 후보 검사를 안전하게 적용할 수 있으면 활용하되, 숫자·영문 혼합이나 변조를 확정할 수 없으면 `병음을 자동 확인하지 못했어요. 원문과 함께 확인하세요.`라고 표시한다. 검증하지 못한 값을 검증 완료로 표시하지 않는다. 조합 탐색은 긴 입력에서 폭발하지 않도록 연산 상한 또는 유한한 동적 탐색을 둔다.
- 등록 미리보기의 경고는 오류·중복과 구분한다. 경고 행은 제출 가능하고 정상/경고/차단/중복 개수가 실제 전송 대상과 일치한다. 직접 수정 후 경고도 재평가한다. 서버와 Python 킷은 형식 검증을 맡고 발음 정확성을 보장한다고 설명하지 않는다.

### 3.3 저장·중복·기존 시트

신규 원문은 §3.1 정규화 후 저장한다. 신규 배치와 선택 탭의 중복 비교는 같은 NFC·앞뒤 트림 기준을 사용하고, 문장부호 제거 등 채점 정규화를 중복 판단에 사용하지 않는다. 기존 행은 수정하지 않는다. `你好`와 `你好。`는 별도 항목이다.

기존 시트에서 읽은 A열 키는 학습 기록·재시도 큐·정답 갱신 시 원래 값으로 전달한다. 읽기 경로에 신규 등록 제한을 적용하여 기존 긴 항목을 숨기거나 실패시키지 않는다. 직접 시트에 입력한 200자 초과 항목은 표시·학습 가능하고 TTS만 길이 안내 후 요청하지 않는다.

## 4. 중국어 모드2 채점

`contentType`을 채점 경계까지 명시적으로 전달한다. `zh`는 NFC → 영문 소문자화 → 모든 공백 제거 → 아래 부호 제거 후 문자열이 같으면 정답이다. 정규화 후 입력 또는 정답이 비면 오답이다.

```text
，。！？；：、,.!?;:（）()【】[]《》〈〉“”‘’「」『』"'…
```

목록을 고정하고 Unicode 문장부호 전체를 무차별 제거하지 않는다. `-`, `—`, `·`, `/`, `／`, `%`, `％`, `+`, `＋`, `=`, `＝`, `．`는 의미를 바꿀 수 있어 유지한다. ASCII 마침표 `.` 또는 쉼표 `,`가 ASCII/전각 숫자 두 개 사이에 있으면 소수·숫자 구분 기호로 보아 유지한다. 전각 숫자·영문과 반각을 자동 동치로 취급하지 않는다.

일반 문장부호의 생략·전각/반각 차이는 허용하지만 한자·숫자·어순·부정어 누락은 허용하지 않는다. 문장부호로 달라지는 의문/평서 의미 자체는 이 모드의 평가 대상에서 제외한다. 입력 원문은 결과의 `내 답`에 보존한다. 등록 키, 기록 API, TTS 텍스트에 채점 정규화 결과를 사용하지 않는다.

| 정답 | 입력 | 결과 |
|---|---|---|
| 你今天忙吗？ | 你今天忙吗 | 정답 |
| 你好，世界！ | 你好, 世界! | 정답 |
| 我不喜欢咖啡。 | 我喜欢咖啡 | 오답 |
| 我有2本书。 | 我有3本书 | 오답 |
| 价格是3.5元。 | 价格是35元 | 오답 |
| 增长了5%。 | 增长了5 | 오답 |
| 你好。 | 。？！ | 오답 |

`generic`은 기존 NFC·소문자화·공백 제거만 적용한다. 예를 들어 `hello!`와 `hello`는 계속 다르다.

## 5. 화면과 입력

- 짧은 단어의 기존 강조 표현은 유지한다. 긴 원문은 길이/가용 너비에 따라 크기를 낮추고 줄바꿈한다. 320px·375px 모바일 폭과 데스크톱에서 200자 원문·1,000자 병음·긴 뜻·긴 오답을 끝까지 읽을 수 있어야 한다.
- 모드1 앞/뒷면과 모드2 입력/오답 결과 모두 확인한다. 가로 넘침·텍스트 잘림·겹침을 없애고 필요한 경우 내용 영역을 세로 스크롤한다. 판정·다음·발음 버튼에 접근할 수 있어야 한다.
- 중국어 모드2 입력은 여러 줄 표시 가능한 textarea로 전환한다. Enter는 제출, Shift+Enter는 개행, IME 조합 중 Enter는 제출하지 않는다. 모바일은 명시적 제출 버튼을 제공한다. 문제 전환 시 입력·높이·스크롤·포커스 상태를 적절히 초기화한다.
- 학습 모드 이름·힌트·등록 안내는 `중국어 → 뜻`, `뜻 → 중국어`, `단어·문장`처럼 범위를 드러낸다. 기존 시트 헤더나 데이터 필드명을 강제로 바꾸지 않는다.
- 진행 중인 #169 Speaker Position 디자인과 충돌을 점검하고 발음 버튼 위치·키보드 접근·공개 시점을 유지한다. #169는 작업 시작의 필수 선행 조건은 아니며 최종 병합 시 최신 상태를 확인한다.

## 6. 문장 TTS

기존 API·제공자·R2 캐시와 정답 공개 후 자동 1회/수동 반복 정책을 재사용한다. 문장부호·숫자가 있는 A열 원문을 전달하며 채점용 텍스트를 보내지 않는다. B열은 현재 제공자가 발음 힌트로 사용하지 않는다는 기존 계약을 유지한다.

200자 이하 입력의 통합 성공·실패·재사용을 검증한다. 200자 초과 기존 항목에서는 자동 요청 없이 발음 길이 제한을 안내하고 학습을 계속한다. 다음 문제·종료 시 이전 요청과 재생을 정리하고 느린 응답이 새 문제에서 재생되지 않게 한다. 실패·자동재생 차단은 판정·기록을 막지 않는다. 실제 유료 합성·휴대폰 청취를 수행하지 않았다면 자동 테스트 성공과 분리하여 미검증으로 기록한다.

## 7. 수용 시나리오와 검증

공통 fixture에는 한자 단어, 문장부호 있는 문장, 문장부호 없는 긴 문장, 숫자·영문 혼합, 다음자·변조 병음, 경고 행, 200/201 코드 포인트 경계, 병음 1,000/1,001 경계, 불허 문자·빈 값·중복, 기존 장문, generic을 포함한다. JS와 Python에서 같은 등록 허용/차단 결과를 확인한다.

1. `我今天很忙。 / wǒ jīntiān hěn máng. / 나는 오늘 매우 바쁘다.`를 킷 생성 → 검증 → 미리보기 → 서버 등록 → 시트 조회 → 학습까지 통과시킨다.
2. 모드1 공개 후 문장·병음·뜻을 읽고 판정하며, 모드2 문장부호 생략 정답이 원문 행에 1회 기록된다.
3. 한자/숫자 누락 오답은 기존 진도 정책을 따른다. 경고를 수정하거나 그대로 제출해도 중복 등록·오전송하지 않는다.
4. 320px·375px에서 최대 길이와 긴 뜻·오답·키보드가 있는 상태의 버튼 접근을 확인한다. IME Enter는 제출 0회, 조합 완료 후 제출은 1회다.
5. 기존 단어·generic·TTS 비활성·재시도 큐·복습 동작에 회귀가 없다.

각 이슈에서 관련 테스트를 작성하고 최종 합류에서 `npm test`, `npm run build`, `npm run lint`와 Python 킷 검사, 화면 수동 검증을 수행한다. 외부 시트/TTS는 자동 테스트에서 mock을 사용하며 실제 환경 확인 여부를 별도 기록한다.
