# 탭 선택 학습 PRD

> 작성일: 2026-09-25 · 상태: 구현 완료(#188·#189 병합, 문서 정합 #190) · 대상: 전 프로필(`zh`·`generic`)
>
> 홈에서 학습을 시작할 때 **전체 탭** 또는 **고른 탭 n개(1개 이상)** 를 학습 범위로 정한다. PRD.md §11의 v2 후보 "탭 선택 학습 (현재는 항상 전체 통합)"을 편입한다. 이 문서는 범위 선택의 변경분만 정의하며, 언급이 없는 학습 모델·세션·기록 규칙은 PRD.md·PRD-general.md·design-prd.md를 그대로 따른다.

## 1. 목적과 현재 문제

탭은 출처별 분류(`HSK4`, `회화수업`, `교재5과`)인데, 이 PRD 이전에는 세션이 항상 전 탭 통합 큐였다(개정 전 PRD.md §4.1·§6.1 — 두 절은 이 PRD 편입으로 개정됐고, 현재 사양은 §3 이하다). 수업 직전에 그 수업 탭만 돌리거나, `교재5과`·`교재6과`처럼 관련 탭 몇 개에 집중할 방법이 없었다. 시트를 복제하거나 다른 탭 이름에 `_`를 붙여 숨기는 우회는 진도 열을 쪼개거나 시트 원본을 바꾼다.

현재 구조상 비용이 작다. `GET /api/words`가 모든 단어를 `tab` 필드와 함께 시트 탭 순서대로 반환하고, 홈(`src/screens/HomeScreen.tsx`)이 그 목록으로 `computeHomeStats`와 `buildSessionQueue`를 계산한다. 범위 선택은 이 두 함수에 들어가기 전 단어 목록을 거르는 문제로 줄어든다.

## 2. 범위와 유지할 계약

- 범위는 두 가지다: **전체**(현행과 동일) / **탭 선택**(1개 이상 n개).
- 서버 API·시트 계약(A~G열, `tab + A열` 행 식별, `_` 접두 탭 제외, `_정보` 설정)은 **변경하지 않는다**. 범위는 클라이언트에서만 적용한다.
- 탭 선택 범위에서는 **선택하지 않은 탭의 단어를 큐에 전혀 넣지 않는다.** 복습 대기라도 마찬가지다. 다른 탭 복습을 몫만큼 섞는 규칙은 두지 않는다.
- 상태 머신·졸업·복습 간격, 복습 몫 30%, 학습 중 정렬·무작위 타이브레이커, 오답 비재출제, 문제 단위 즉시 기록, 재시도 큐는 모두 불변이다. 달라지는 것은 **큐를 만드는 단어 집합**뿐이다.
- 세션 상한은 시트의 `문제수` 설정 하나를 선택 범위 전체에 적용한다. 탭별 상한이나 탭 간 균등 배분은 두지 않는다. 고른 탭들을 합친 단어 집합에 기존 산식을 그대로 적용한다.
- 탭별 진도 통계 화면, 학습 화면·완료 화면의 탭 표기, 탭 이름 변경·삭제 UI는 범위 밖이다.

## 3. 학습 범위 모델

```ts
type StudyScope = { kind: "all" } | { kind: "tabs"; tabs: string[] };
```

- **탭 목록**은 `/api/words` 응답의 `words[].tab`을 처음 등장한 순서로 중복 제거해 만든다. 서버가 시트 탭 순서대로 이어 붙여 반환하므로 시트의 탭 순서와 같다. `GET /api/tabs`를 추가로 호출하지 않는다.
  - 헤더만 있고 단어가 0개인 탭은 목록에 나오지 않는다. 학습할 것이 없으므로 의도된 동작이다.
- **범위 적용**: `kind === "tabs"`이면 `tabs`로 만든 `Set`에 `word.tab`이 포함된 단어만 남긴다. 탭 이름은 정확히 일치해야 한다(트림·대소문자 무시 없음). 시트 탭 이름이 곧 키다. `tabs`의 순서는 결과에 영향이 없고, 저장·표시할 때는 시트 순서로 정렬한다.
- `tabs`가 빈 배열이면 문제 수는 0이다. 유효한 범위가 아니라 "선택 중" 상태이며, §4.2의 규칙으로 시작을 막는다.
- **모든 탭을 고른 경우와 전체는 다르다.** 전체는 이후 새로 생긴 탭도 자동으로 포함하고, 탭 선택은 저장된 탭 이름만 포함한다. 두 상태를 하나로 합치지 않는다.
- 거른 목록을 **기존 `computeHomeStats`와 `buildSessionQueue`에 그대로 넘긴다**. 두 함수의 시그니처와 산식은 바꾸지 않는다. 홈 표시 수치와 실제 큐 길이가 같은 입력·같은 산식에서 나와야 한다는 불변식(#128, `HomeScreen.tsx`)은 필터 함수 하나를 양쪽에서 공유하는 방식으로 지킨다. 필터를 두 번 따로 적지 않는다.
- 같은 A열 값이 여러 탭에 있으면 이미 독립 단어다(PRD.md §4.2). 두 탭을 함께 고르면 두 행이 각각 후보가 된다. 한 탭만 고르면 그 탭의 행만 출제된다.

## 4. 홈 화면

### 4.1 범위 선택 UI

- 위치: 현황 카드와 "오늘 세션 · n문제" 줄 사이(스페이서 아래, 미전송 인디케이터 위). 선택을 바꾸면 아래 세션 수와 시작 버튼이 바로 바뀐다.
- 형태: **2분할 세그먼트 `전체 | 탭 선택`**. `탭 선택`이면 그 아래에 **탭 칩 목록(다중 선택 토글)** 을 펼친다.
  - 칩 하나가 탭 하나다. 라벨은 `탭이름 · n`이며, n은 그 탭만 골랐을 때의 세션 문제 수다. 0이면 `탭이름 · 0`으로 흐리게 표시하되 선택은 가능하다.
  - 칩을 누르면 선택이 토글된다. 선택된 칩은 `accent` 테두리·배경과 체크 표시로, 선택되지 않은 칩은 `bg-panel`·`text-muted`로 구분한다. 색만으로 구분하지 않는다.
  - 칩 목록은 시트 탭 순서로 줄바꿈 배치한다. 칩이 3줄을 넘으면 목록 영역에 최대 높이를 두고 세로 스크롤한다. 시작 버튼이 화면 밖으로 밀리면 안 된다.
  - 칩 목록 위에 `모두 선택` / `선택 해제` 저강조 텍스트 버튼 하나를 둔다. 하나라도 선택되지 않은 칩이 있으면 `모두 선택`, 전부 선택돼 있으면 `선택 해제`로 표시한다.
  - 칩 라벨의 n은 탭별 값이다. 여러 탭을 고른 결과 문제 수는 합이 아니라 합집합에 상한·배분을 적용한 값이며, 아래 세션 수 줄에만 표시한다.
- 기존 `Dropdown` 컴포넌트(#56)는 단일 선택 전용이라 쓰지 않는다. 칩 목록은 새 컴포넌트로 만든다.
- `탭 선택`으로 처음 바꿀 때의 초기 선택: 이 프로필의 마지막 탭 선택이 있으면 그 탭들, 없으면 세션 문제 수가 가장 많은 탭 1개(동률이면 시트 순서상 앞선 탭)다.
- 탭이 1개뿐인 프로필은 선택 UI를 숨기고 전체로 동작한다(전체와 결과가 같다).
- 로딩·에러 상태에서는 선택 UI를 숨긴다. 현황 카드와 같은 조건(`status === "ready"`)에서만 렌더한다.
- 스타일은 design-prd §1 토큰을 따른다. 포커스 링은 `.dropdown-trigger`와 같게 한다. 긴 탭 이름은 칩 안에서 말줄임 처리한다. 구체 값은 design-prd §3 개정에서 확정한다.
- 접근성: 세그먼트는 `role="radiogroup"`/`radio`로 방향키 이동을 지원한다. 칩은 `role="group"`(라벨 `학습할 탭`) 안의 `aria-pressed` 토글 버튼이며, Tab 이동과 Space/Enter 토글을 지원한다.

### 4.2 범위에 따른 표시

- 현황 카드 3개(복습 대기·학습 중·졸업), "오늘 세션 · n문제", 시작 버튼 활성 여부와 라벨이 **모두 선택된 범위 기준**으로 계산된다.
- 세션 수 줄 앞에 범위를 붙인다. 전체이면 현행 문구, 탭 1개이면 `HSK6 · 오늘 세션 · n문제`, 탭 2개 이상이면 `HSK6 외 2개 탭 · 오늘 세션 · n문제`(첫 이름은 시트 순서 기준)다.
- 탭 선택 범위에서는 선택하지 않은 탭의 단어를 수치·큐 어디에도 포함하지 않는다(§2).
- 선택된 탭이 0개이면 시작 버튼을 비활성화하고 라벨을 `탭을 선택하세요`로 바꾼다. 세션 수 줄은 숨긴다. 카드는 0으로 표시한다.
- 선택 범위 안에서 할 것이 없으면 기존처럼 시작 버튼을 비활성화하고 `오늘 할 것 없음`으로 표시한다.

### 4.3 선택 기억

- 마지막 범위를 localStorage `vocab-study:study-scope`에 **프로필 id별로** 저장한다: `{ [profileId]: StudyScope }`. 프로필 전환(`clearPassword`)으로 지우지 않는다. 다시 그 프로필로 로그인하면 이전 범위가 복원된다.
- `탭 선택`의 저장값은 세그먼트를 `전체`로 바꿔도 따로 보존한다. 다시 `탭 선택`을 누르면 이전 칩 선택이 돌아온다. 저장 형식은 `{ kind, tabs }`에 마지막 탭 선택을 함께 두는 등 구현에서 정하되, 이 동작을 지켜야 한다.
- 선택 0개 상태는 저장하지 않는다. 0개인 채로 홈을 떠나면 마지막으로 비어 있지 않았던 선택이 남는다.
- 처음 진입했거나 저장값이 없거나 손상됐으면 **전체**로 시작한다. 기존 사용자의 첫 화면은 현행과 같다.
- 저장된 탭 중 이번 응답의 탭 목록에 없는 탭(탭 이름 변경·삭제, 단어 0개)은 조용히 빼고 저장값도 갱신한다. 남은 탭이 없으면 **전체**로 되돌린다. 오류 문구는 띄우지 않는다.
- 홈 진입마다 `/api/words`를 다시 조회하는 규칙(design-prd §3)은 그대로이며, 복원한 범위는 새 응답으로 다시 검증한다.

## 5. 세션 시작과 이후 흐름

- `handleStart`는 범위로 거른 단어로 `buildSessionQueue`를 호출한다. 큐는 시작 시점에 확정되며(PRD.md §6.1), 세션 도중 범위를 바꾸는 경로는 없다.
- 학습·완료 화면, `POST /api/answer`·`/api/review-fail`, 재시도 큐, TTS는 변경하지 않는다. 문제 객체가 이미 `tab`을 운반한다.
- 완료 후 홈으로 돌아오면 같은 범위가 유지되고 수치가 재조회로 갱신된다.
- 등록 화면에서 탭을 새로 만든 뒤 홈으로 돌아오면, 그 탭에 단어가 있을 때 칩 목록에 나타난다. 전체 범위에는 자동 포함되고, 탭 선택 범위에는 사용자가 칩을 켜야 포함된다. 등록 화면이 홈 범위를 바꾸지는 않는다.

## 6. 수용 시나리오와 검증

1. 기존 사용자가 처음 홈에 들어오면 `전체`가 선택돼 있고 현황·세션 수·큐가 변경 전과 같다(회귀 없음).
2. `탭 선택`에서 `HSK6`만 켜면 카드·세션 수가 HSK6 단어만으로 다시 계산되고, 시작한 큐의 모든 문제가 `tab === "HSK6"`이다.
3. `교재5과`·`교재6과`를 함께 켜면 큐의 모든 문제가 두 탭 중 하나에 속하고, 세션 수는 두 탭 합집합에 상한·복습 몫을 적용한 값이다. 칩별 n의 합과 다를 수 있다. 세션 수 표시와 큐 길이는 항상 같다.
4. 선택하지 않은 탭에 복습 대기가 있어도 그 단어는 큐에 들어가지 않고, 카드·세션 수에도 잡히지 않는다.
5. 칩을 모두 끄면 시작 버튼이 `탭을 선택하세요`로 비활성화된다. `모두 선택`/`선택 해제`가 상태에 맞게 표시·동작한다.
6. 모든 탭을 켠 탭 선택 범위는 이후 새로 생긴 탭을 포함하지 않고, 전체 범위는 포함한다.
7. 새로고침·세션 완료·프로필 전환 후 재로그인해도 프로필별 마지막 범위와 칩 선택이 복원된다. `전체`로 바꿨다가 다시 `탭 선택`을 누르면 이전 칩 선택이 돌아온다. 다른 프로필의 범위와 섞이지 않는다.
8. 저장된 탭 3개 중 1개의 이름을 시트에서 바꾸면 나머지 2개만 선택된 채 복원된다. 모두 사라지면 전체로 돌아간다. 오류는 표시하지 않는다.
9. 탭이 1개인 프로필에는 선택 UI가 없다. 로딩·에러 상태에서도 선택 UI가 없다.
10. 같은 A열 값이 두 탭에 있을 때 한 탭만 고르면 그 탭의 행만, 둘 다 고르면 두 행이 각각 출제·기록 대상이 된다.
11. 320px·375px 폭에서 탭 10개 이상·긴 탭 이름일 때 칩이 가로로 넘치지 않고(줄바꿈·말줄임), 칩 목록이 최대 높이에서 스크롤되며, 시작 버튼이 화면 안에 남는다. 키보드만으로 세그먼트 전환과 칩 토글이 가능하다.

단위 테스트: 탭 목록 도출(순서·중복 제거·빈 입력), 다중 탭 필터(0개·1개·n개·전체와의 차이), 저장값 파싱·손상·일부/전부 누락 탭 정리, 홈 수치와 큐 길이 일치(`HomeScreen.test.tsx`). 기존 `sessionQueue`·`homeStats` 테스트는 수정 없이 통과해야 한다. 최종 확인은 `npm test`, `npm run build`, `npm run lint`로 하고, 모바일 폭 화면은 직접 확인한다.
