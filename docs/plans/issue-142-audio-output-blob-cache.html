3설계

1. 공개 진입점과 소유 경계

createTtsAudioOutput(deps?): TtsAudioOutput와 createTtsBlobCache(): TtsBlobCache를 각 소유 파일에서 export한다. Audio 의존성은 createAudio, createObjectURL, revokeObjectURL이며 기본값은 브라우저 native API다. 좁은 Audio 포트는 해당 파일의 전용 타입으로 표현해 더블이 구현할 수 있게 한다. 모듈 import 시 브라우저 전역을 평가하지 않고 output당 Audio를 최대 하나만 생성한다(첫 play에서 지연 생성 가능). 전역 singleton은 두지 않는다. 반환 타입은 #135의 기존 포트와 호환해야 한다.

Audio는 Blob·URL·source 세대·리스너·재생 결과만 다룬다. 캐시는 불투명한 문자열 키와 Blob만 다룬다. 프로필/revision/text/pinyin의 키 조합·정규화, 질문 ID, 공개 기회, fetch/timeout, React, visibility/pagehide 이벤트는 다음 소유 이슈에 남긴다. MP3 검사와 2MiB 응답 제한을 캐시에 중복 구현하지 않는다.

2. 동기 재생과 source 교체

  1. play(blob) 진입 시 disposed 여부를 확인하고 source 세대를 증가시킨다. 기존 미완료 공개 결과를 cancelled로 끝내며 오래된 native Promise의 reject handler는 유지한다.
  2. 기존 source의 listener를 해제하고 pause → removeAttribute('src') → load → revokeObjectURL 순서로 정리한다. URL은 audio에서 분리된 다음 정확히 한 번 해제한다. src = '' 대신 속성 제거를 사용한다.
  3. 현재 Blob의 URL을 하나 생성하고 새 source 레코드에 소유권을 기록한다. 새 src를 연결하고 currentTime = 0으로 시작 위치를 설정한 뒤 native audio.play()를 메서드 반환 전, 같은 호출 스택에서 실행한다. 앞에 await, microtask, timer, canplay 대기를 넣지 않는다. 같은 Blob을 연속 호출해도 이 경로로 처음부터 다시 재생한다.
  4. 반환 Promise는 native 시작 결과를 TtsPlayResult로 변환한다. 최신 source의 resolve는 started, name === 'NotAllowedError'는 blocked, 나머지 native 실패·동기 setup 실패는 error다. 교체/stop/dispose로 무효화된 작업은 원래 오류 종류와 관계없이 cancelled다. 공개 Promise는 정상적으로 결과를 resolve하며 실패를 던져 학습 진행을 중단시키지 않는다.

3. 이전 이벤트와 Promise 격리

각 source 레코드는 generation, URL, 진행 중인 결과의 일회성 settle, listener 제거 함수를 가진다. native Promise와 listener closure 모두 해당 레코드가 현재 것인지 확인한다. stale 완료가 최신 URL을 revoke하거나 이벤트를 전달할 수 없어야 한다.

같은 요소에 새 listener를 붙였다는 사실만으로 이전 DOM 이벤트가 구분되지는 않는다. 이벤트에는 source 세대가 없다. 따라서 세대 검사에 더해 source 분리 시 load로 이전 media task를 폐기하고, 이벤트 수신 시 현재 source/URL 및 ended 또는 error의 실제 요소 상태를 확인한다. WHATWG load 알고리즘은 대기 media task 제거와 진행 중 play Promise 처리를 규정한다. 이는 설계 근거이며 더블만으로 모든 모바일 엔진 동작을 검증한 것으로 간주하지 않는다.

유효한 ended/error에서는 먼저 해당 source의 자원을 정리한 뒤 구독자에게 알린다. native play 시작 전 error는 공개 결과 error로 한 번 전달하고, started 이후 오류는 error 이벤트로 전달해 동일 실패의 이중 통지를 피한다. 매우 빠른 ended가 미완료 play보다 앞서면 공개 결과는 cancelled로 완료하고 ended를 전달하며 늦은 started는 무시한다. 구독 callback 안에서 replay/stop/dispose가 재진입해도 뒤늦은 이전 정리가 새 source를 건드리지 않게 한다. unsubscribe는 멱등이고 dispose 후 신규 구독은 no-op이다.

4. stop과 dispose

stop()은 source 세대를 무효화하고 미완료 결과를 cancelled로 끝낸 뒤 현재 audio 연결·URL·source listener만 정리한다. 같은 output은 다시 play할 수 있으며 소비자 구독은 유지한다. dispose()는 stop 정리와 소비자 구독 해제를 수행하고 영구 종료한다. 종료 뒤 play는 cancelled를 반환하며 Audio/URL을 새로 만들지 않는다. 반복 stop/dispose는 안전하다. blocked·error·ended에서도 사용이 끝난 URL을 정리하지만 Blob 캐시에는 접근하지 않는다.

MDN play 계약에 따라 NotAllowedError를 별도 결과로 구분한다. blocked 이후 받은 Blob의 보존과 수동 재시도는 캐시 및 controller가 담당하며, Audio 자체가 자동 재시도하지 않는다.

5. Blob LRU와 pin 규칙

연산결정한 동작
저장 구조삽입 순서를 가진 Map의 각 항목에 Blob과 pinned 여부를 보관한다. 합계는 Blob.size로 계산하며 20개 및 8 × 1024 × 1024 bytes를 동시에 지킨다. 경계와 같으면 허용한다. URL은 보관/생성하지 않는다.
gethit이면 MRU로 이동하고 Blob을 동기 반환한다. miss는 undefined이며 기존 순서를 바꾸지 않는다.
set저장 성공 시 MRU가 된다. 삽입/교체 후 개수와 바이트를 먼저 계산하고 필요한 unpinned LRU 희생 항목을 선정한다. 둘 다 만족할 수 있을 때만 한 번에 반영한다. 실패는 stored:false이며 기존 Blob·순서·용량을 그대로 보존한다. 같은 key를 교체할 때 기존 크기를 빼서 중복 집계하지 않는다.
pin / unpin존재하는 항목에 대한 멱등 boolean 보호다. 중복 pin은 참조 횟수를 쌓지 않고, 한 번의 unpin으로 해제한다. 없는 key는 no-op이며 미래 pin 예약을 만들지 않는다. get/set 성공 뒤 pin을 호출하고 준비→재생 동안 유지하는 책임은 controller다. pin/unpin 자체는 LRU 순서를 바꾸지 않는다.
pin된 key의 set같은 Blob identity는 stored:true로 MRU 갱신한다. 다른 Blob으로 교체하면 보호 중인 자원을 바꾸므로 stored:false로 거절한다. 교체가 필요하면 소비자가 먼저 unpin한다. 이 선택을 JSDoc과 테스트에 명시한다.
용량 부족Blob 하나가 8MiB 초과이거나 pin 때문에 공간 확보가 불가능하면 stored:false다. 일부 항목만 먼저 지우지 않으며, 받은 Blob을 cache 밖에서 즉시 재생하는 것은 가능하다. 캐시의 상한은 LRU에 저장된 Blob에 대한 상한이다.
clear / disposeclear는 pin 여부와 관계없이 전체 Blob·pin·합계를 초기화하고 재사용 가능하다. dispose는 clear 후 영구 종료하여 get=undefined, set=stored:false, 나머지 연산=no-op이 된다. Audio.stop과 연결하지 않는다.

pin의 멱등성·교체 정책과 clear/dispose 차이는 기존 포트가 열어 둔 세부사항을 이번 구현에서 고정한 것이다. 공통 시그니처를 변경하지 않고 소유 모듈 JSDoc과 이 계획으로 #143에 전달한다.

6테스트 계획

  • 계획 단계에서 실행 완료: npm test -- src/lib/ttsTypes.test.ts — 1 파일, 2 테스트 통과. 최초 sandbox 실행은 공용 node_modules/.vite-temp 쓰기 권한으로 시작 실패했으며, 해당 권한으로 재실행해 통과했다. 이는 기존 계약의 기준선이며 아직 없는 두 모듈의 통과 결과가 아니다.
  • Audio 동기성/반복: play 메서드가 반환하기 전 native spy가 이미 호출되었는지 검사한다. 같은 Blob 5회 재생 시 Audio 생성 1회, 매번 이전 pause→detach/load→revoke 이후 새 src·0초·play, 동시 재생 1개 이하, 활성 URL 최대 1개를 검증한다.
  • 경쟁: A play 대기→B play→A resolve/reject(NotAllowedError 포함), A stop/dispose 후 늦은 완료, 이전 listener callback, A의 대기 media event 후 source 교체를 각각 재현한다. A 공개 결과는 cancelled, B 자원과 구독 상태는 유지되며 미처리 rejection이 없어야 한다. 단순히 이벤트를 전혀 보내지 않는 더블로 검증을 대신하지 않는다.
  • 현재 이벤트: 정상 ended, native reject, 시작 전/후 media error를 검사한다. 현재 ended/error는 한 번만 전달되고 오래된 이벤트는 전달하지 않는다. callback 안에서 replay/stop/dispose해도 새 URL은 살아 있어야 한다.
  • 차단/실패/정리: NotAllowedError는 blocked, 기타 오류는 error, invalidated 오류는 cancelled다. URL 생성 실패는 revoke 0회, 생성 후 setup 실패는 detach 후 정확히 1회 revoke한다. stop 후 재사용, 반복 dispose, dispose 후 play/subscribe, unsubscribe를 검증한다. 모든 재생을 정리한 뒤 create URL 수 = revoke URL 수여야 한다.
  • 캐시 개수/바이트: 20개→21번째, 정확히 8MiB, +1byte, 개수 여유가 있지만 바이트 초과, 바이트 여유가 있지만 개수 초과, 두 조건 동시 초과를 검사한다. 여러 작은 항목을 한 번에 축출해야 하는 사례도 포함한다.
  • LRU/교체: get hit와 set 성공이 MRU를 갱신하는지, miss/실패 set/pin/unpin은 순서를 바꾸지 않는지 확인한다. 동일 key의 작은/큰 Blob 교체에서 크기 차이만 집계하고 한도가 누적 오차 없이 유지되는지 검사한다.
  • pin/해제: 가장 오래된 항목 pin 보호, 모두 pin된 경우 삽입 거부, 일부 후보가 있어도 공간 부족이면 전체 보존, 중복 pin→unpin, 없는 key pin no-op, pin된 동일/다른 Blob 교체, unpin 후 축출, clear 후 재사용 및 dispose 후 영구 종료를 검사한다.
  • 두 자원 수명 분리: cache.set/get으로 준비한 Blob을 Audio가 blocked로 반환한 뒤 stop해도 cache.get은 동일 Blob이다. 같은 Blob을 다시 play할 수 있다. Audio.dispose가 cache를 지우지 않고 cache.dispose는 Audio URL API를 호출하지 않는다.
