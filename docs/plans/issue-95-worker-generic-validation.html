#95기능 개선

등록 일반화 — Worker generic 검증 분기 + 탭 0개 기본 헤더 부트스트랩

damdam6/vocabulary-study 브랜치 feat/95-worker-generic-validation ← main 라벨 enhancement 2026-07-28

1요약

등록 재검증(parseRegisterWords)이 한자 유니코드 범위·병음 성조 형식을 하드코딩해 generic 프로필 단어가 아무것도 통과하지 못한다. 등록 일반화 플랜(docs/plans/registration-generalization.md §3.2·§3.3, 작업 B)에 따라 검증을 contentType으로 파라미터화하고(zh 경로 불변), 라우트가 인증 프로필의 contentType을 전달하며 400 문구를 타입별로 분기한다. 아울러 학습 대상 탭이 0개인 스프레드시트에서 첫 등록이 불가능하던 400("헤더를 복사할 기존 탭이 없습니다")을 제거하고, contentType별 기본 헤더(A~F)로 첫 탭을 부트스트랩한다. 와이어 계약(hanzi/pinyin/meaning = A/B/C열 운반자)과 응답 형태는 불변, 클라이언트(src/)는 작업 C 소관이라 건드리지 않는다.

2현황 분석

등록 파이프라인 3단계 중 Worker 재검증(3단계)의 zh 결합 지점:

  • worker/lib/register.ts:19 — HANZI_RE = /^[一-鿿]+$/u(U+4E00–9FFF 기본 블록)와 worker/lib/register.ts:31의 hasValidToneFormat(성조 부호 필수·숫자 금지·허용 문자 집합)이 parseRegisterWords(worker/lib/register.ts:46)에서 무조건 적용된다. hanzi/pinyin/meaning 세 필드 전부 트림 후 비공백을 요구한다(worker/lib/register.ts:61).
  • worker/routes/register.ts:38 — 라우트는 프로필 스레딩(#73)으로 profile.sheetId는 쓰지만 parseRegisterWords(rawWords)에 profile.contentType을 넘기지 않고, 400 문구(worker/routes/register.ts:42-45)가 "한자는 유니코드 U+4E00–U+9FFF, 병음은 성조 부호 필수"로 zh 전제다.
  • worker/routes/register.ts:62-64 — 미존재 탭 + createTab일 때 학습 대상 탭(getWordTabTitles = _ 접두 제외, worker/lib/words.ts:12)이 0개면 400 "헤더를 복사할 기존 탭이 없습니다" — 새 스프레드시트(또는 전 탭 _ 접두)에서는 첫 등록이 영영 불가능하다.
  • 프로필 타입은 이미 준비돼 있다: ContentType = "zh" | "generic"(worker/lib/profiles.ts:10), 생략 시 "zh" 폴백(worker/lib/profiles.ts:165). getProfiles·다이제스트 캐시는 isolate 수명 동안 첫 성공 구성을 고정하므로 테스트 격리는 "파일 = isolate" 규약을 따른다(worker/test-utils.ts:3, worker/index.sheet-isolation.test.ts:12).
  • 기존 테스트: worker/lib/register.test.ts(파서 단위, 폴백 zh), worker/routes/register.test.ts(라우트 통합 — APP_PASSWORD+SHEET_ID 폴백 env → contentType "zh", Sheets mock이 1:1/A2:A GET·A1/A{n}:C{m} PUT·addSheet batchUpdate를 지원). 시트 격리는 worker/index.sheet-isolation.test.ts의 mock URL 전수 기록 패턴이 선례다.

3설계

  • 파서 파라미터화 — parseRegisterWords(raw, contentType: ContentType = "zh"). 공통 검사(배열·1~100건·항목 객체·세 필드 문자열 타입·트림·배치 내 A열 중복 금지)는 그대로 두고, 필드 규칙만 분기한다: zh는 기존 코드 그대로(세 필드 비공백 + HANZI_RE + 성조 형식), generic은 hanzi·meaning 비공백만(자유 텍스트 — 범위 검사 없음), pinyin은 문자열이면 됨(트림 후 빈 문자열 허용 → B열 빈칸). 기본값 "zh"는 프로필 파서의 contentType 생략 폴백과 같은 방향이라 미전달 호출도 엄격한 쪽으로 떨어진다.
  • 기본 헤더 상수 — DEFAULT_TAB_HEADERS: Record<ContentType, string[]>: zh 한자|병음|뜻|모드1|모드2|복습, generic 표제어|보조 표기|뜻|모드1|모드2|복습 (A~F만 — G열 이후는 타임스탬프 append 영역이라 헤더 없음, 플랜 §3.3). 헤더 행은 표시용(전 탭 1행 스킵)이라 파싱 영향 없음.
  • 라우트 — parseRegisterWords(rawWords, profile.contentType) 전달. 400 문구를 contentType별로 분기: zh 문구는 현행 유지, generic은 "표제어(hanzi)·뜻(meaning) 비공백, 보조 표기(pinyin)는 문자열(빈칸 허용), 배열 내 표제어 중복 금지, 최대 100건" 취지로 정확하게. 응답 형태 {tab, created, added, skipped} 불변.
  • 탭 0개 부트스트랩 — 미존재 탭 + createTab 분기에서: 학습 대상 탭 0개면 DEFAULT_TAB_HEADERS[profile.contentType]을, 1개 이상이면 현행대로 첫 탭 1행을 복사해 addSheet 후 A1에 쓴다. 기존 400("헤더를 복사할 기존 탭이 없습니다")은 제거. createTab 없는 미존재 탭 400은 유지. 시트 계약 불변: append-only, A~C열 명시 range, valueInputOption=RAW, 탭 이름 규칙.
  • 기각한 대안 — contentType별 별도 파서 함수(공통 검사 중복·드리프트 위험), 와이어 필드명 중립 개명(words·answer API와 계약 분열 — 플랜 §8 Q2로 기각 확정), 부트스트랩 시 헤더 없는 탭 생성(시트 가독성 저하 — §8 Q6 기각).
