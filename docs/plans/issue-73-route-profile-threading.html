전 라우트 프로필 스레딩 — profile.sheetId 적용 + GET /api/words 응답 profile 블록

damdam6/vocabulary-study 브랜치 feat/73-route-profile-threading ← main 라벨 enhancement 2026-07-27

1요약

#71에서 인증이 프로필 해석(resolveProfile)으로 전환됐지만, 해석된 프로필은 아직 /api/health 응답에만 쓰이고 5개 라우트는 여전히 env.SHEET_ID를 직접 참조한다. 이번 작업은 index.ts의 라우트 디스패치를 인증 블록 안으로 옮겨 프로필을 전 핸들러에 전달하고(통일 시그니처 (request, env, profile)), 모든 Sheets 호출을 profile.sheetId로 전환하며, GET /api/words 응답 최상위에 공개 profile 블록을 추가한다. answer의 모드 검증·졸업 판정 M화는 별도 이슈로 여기서는 스레딩만 한다.

2현황 분석

  • 프로필이 블록 스코프에 갇혀 있음: worker/index.ts:16-43에서 resolveProfile 결과가 /api/* 인증 게이트와 /api/health(39행)에만 쓰이고, 라우트 디스패치(45~88행)는 그 블록 밖이라 프로필에 접근할 수 없다.
  • 라우트별 env.SHEET_ID 직접 참조 14곳: worker/routes/words.ts:11,14 · answer.ts:54,59,74 · review-fail.ts:39,49 · tabs.ts:6 · register.ts:46,60,61,62,68,77. lib 계층은 #72에서 이미 sheetId 파라미터화 완료(lib/sheets.ts, lib/words.ts의 getWordTabTitles/findWordRow/findRowNumber) — 남은 참조는 전부 라우트의 주입부다. lib/profiles.ts:101-114의 폴백 합성만 정당한 참조로 남는다.
  • 시그니처 불일치: handleGetWords(env) · handleAnswerPost(request, env) · handleReviewFail(env, request)(역순!) · handleGetTabs(env) · handleWordsRegister(request, env).
  • 공개 프로필 블록 준비 완료: worker/lib/profiles.ts:34의 toPublicProfile이 sheetId·password 제외 불변식을 이미 한곳에서 보장하고 health가 사용 중 — words가 그대로 재사용하면 된다.
  • 클라이언트 영향 없음: src/lib/wordsApi.ts:15는 data.words만 파싱하므로 최상위 profile 추가는 무해. profile.modes 소비는 후속 이슈.
  • 테스트 규약: getProfiles·다이제스트 캐시가 isolate 수명 동안 첫 구성을 고정하므로 "테스트 파일 = isolate = 프로필 구성 1개" 규약(index.test.ts 폴백 · index.profiles.test.ts 2프로필 · index.config-error.test.ts 오류). 라우트 테스트(tabs.test.ts·register.test.ts)는 worker.fetch 통합 스타일 + fetch 스텁 + google-auth 모킹.

3설계

  • 디스패치 재배치: 전 라우트가 /api/*이므로 라우트 디스패치를 인증 블록 안(401/500/health 처리 뒤)으로 이동한다. 비-API 경로의 최종 404는 그대로. 처리 순서(설정 오류 500 → 401 → health → 라우트)는 불변 — 기존 테스트가 이 순서를 고정하고 있다.
  • 통일 시그니처: 5개 핸들러 모두 (request, env, profile). request를 안 쓰는 words/tabs는 tsconfig.node.json의 noUnusedParameters 때문에 _request로 받는다.
  • words 응답: { fetchedAt, words, profile: toPublicProfile(profile) } — words 항목 형태 불변, sheetId·password 미포함은 toPublicProfile이 보장.
  • 격리 테스트 설계: 새 파일 worker/index.sheet-isolation.test.ts(파일=isolate 규약)에 2프로필 구성(sheet-a/sheet-b)을 두고, sheetId별 상태를 가진 fetch 스텁이 모든 호출 URL을 기록한다. 프로필 A 요청 후 기록된 URL 전수가 /spreadsheets/sheet-a만 가리키는지 검증 — PRD-general §6 "모든 Sheets 호출 경로가 인증된 프로필의 sheetId만 쓰는지"의 직접 검증.
  • 비채택 대안: 핸들러가 profile.sheetId만 받는 방안은 words의 profile 블록·후속 이슈(answer 모드 검증, 재시도 큐 태깅)가 전체 프로필을 요구해 기각. 라우트 밖 profile 변수 호이스팅은 non-null 단언이 필요해져 기각(블록 내 이동이 타입 안전).

4작업 단계

  1. 라우트 디스패치를 /api/* 인증 블록 안으로 이동하고 각 핸들러에 profile 전달 — 처리 순서(500→401→health→라우트)와 비-API 404 불변 worker/index.ts
  2. words: 시그니처 (_request, env, profile) + profile.sheetId 전환 + 응답 최상위 profile: toPublicProfile(profile) 추가 worker/routes/words.ts
  3. answer: 시그니처 (request, env, profile) + profile.sheetId 전환 (모드 검증은 후속 이슈 — 스레딩만) worker/routes/answer.ts
  4. review-fail: (env, request) → (request, env, profile) 역순 정리 + profile.sheetId 전환 worker/routes/review-fail.ts
  5. tabs: 시그니처 (_request, env, profile) + profile.sheetId 전환 worker/routes/tabs.ts
  6. register: 시그니처 (request, env, profile) + profile.sheetId 전환 (6곳) worker/routes/register.ts
  7. 신규 테스트: 2프로필 fetch 스텁(URL 전수 기록)으로 격리·프로필별 words/tabs 데이터·words profile 블록 형태(sheetId/password 부재) 검증 worker/index.sheet-isolation.test.ts
  8. 전체 검증: npm test(기존 폴백 경로 회귀 포함) + npm run build(tsc -b) + npm run lint 전체

5리스크

리스크영향완화책
디스패치 재배치 중 처리 순서(500→401→health) 변경설정 오류가 401로 위장되거나 미인증 라우트 접근순서를 고정한 기존 3개 index 테스트 스위트가 회귀를 즉시 잡음 — 블록 구조만 옮기고 조건 로직은 손대지 않음
getProfiles isolate 캐시로 신규 테스트가 타 파일 구성에 오염격리 테스트 헛통과/헛실패새 구성은 새 파일(index.sheet-isolation.test.ts)로 격리, 파일 내 단일 PROFILES 값 유지 (기존 규약 준수)
words 응답에 profile 추가가 클라이언트 파싱을 깨뜨림홈/학습 화면 로드 실패src/lib/wordsApi.ts:15가 data.words만 읽는 것을 확인 완료 — 추가 필드는 무시됨
noUnusedParameters로 미사용 request 컴파일 오류빌드 실패words/tabs는 _request로 수신 (TS 언더스코어 관례)

6테스트 계획

  • 신규·격리: 2프로필 구성에서 프로필 A 비밀번호로 GET /api/words 호출 → 기록된 모든 fetch URL이 /spreadsheets/sheet-a를 가리키고 sheet-b 문자열이 어디에도 없음
  • 신규·프로필별 데이터: 같은 구성에서 words가 A 비밀번호→A 시트 단어, B 비밀번호→B 시트 단어를 반환. GET /api/tabs도 프로필별 탭 목록(+_ 접두 제외) 반환
  • 신규·profile 블록: words 응답 최상위 profile이 { id, name, modes, contentType } 정확히 일치, 응답 전문에 sheetId/password/실제 시트 ID/비밀번호 문자열 부재, fetchedAt·words 형태 불변
  • 회귀: 기존 스위트 전부 무수정 통과 — index.test.ts(폴백 인증·health), index.profiles.test.ts(2프로필 해석), index.config-error.test.ts(설정 오류 500), routes/tabs.test.ts·routes/register.test.ts(폴백 단일 프로필 경로의 실동작)
  • 정적 검증: npm run build(tsc -b 포함)와 npm run lint(oxlint) 통과, worker/routes/·worker/lib/에 env.SHEET_ID 참조 0건 확인(lib/profiles.ts 폴백 합성 제외)

  • 프로필 2개 구성에서 words/tabs가 각자 시트의 데이터를 반환
