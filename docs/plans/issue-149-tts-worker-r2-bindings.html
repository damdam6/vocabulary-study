#149기능 개선

중국어 TTS의 Worker 환경과 R2 바인딩을 연결한다

damdam6/vocabulary-study 브랜치 feat/149-tts-worker-r2-bindings ← feat/ch-sound 라벨 enhancement 2026-09-16

1요약

완성된 TTS Worker 경로에 비밀이 아닌 고정 설정과 실제 비공개 R2 바인딩을 연결하고, Wrangler가 생성하는 Env를 구성의 단일 소스로 맞춘다. 운영 기능은 TTS_ENABLED="false"로 유지하며 배포·활성화·유료 호출은 하지 않는다. 계획 당시 없던 실제 버킷 증거는 구현 중 확보됐다. vocabulary-study-tts-audio를 운영, audio-uploads를 개발/테스트(preview_bucket_name)로 연결했으며, 키 주입·배포된 바인딩 접근·모델 접근·청취는 출시 후속 확인으로 미검증 상태를 유지한다.

3설계

설정의 기준: wrangler.jsonc의 top-level vars에 TTS_ENABLED="false", TTS_PROVIDER="qwen", TTS_MODEL="qwen-audio-3.0-tts-flash", TTS_VOICE="longanfengyue", TTS_RATE="1.0", TTS_REVISION="tts-v1"을 명시한다. API 키는 절대 vars에 넣지 않는다. secrets.required는 배포 시 실제 secret 존재를 강제하는 별도 동작이므로, 주입 상태와 기존 secret 목록을 검증하기 전 임의로 추가하지 않는다.

R2 매핑: 현재처럼 하나의 top-level Worker 설정을 유지한다. 검증된 두 실제 이름을 받은 뒤에만 r2_buckets의 단일 항목을 추가하고 binding="TTS_AUDIO", 운영 버킷은 bucket_name, 검증 버킷은 preview_bucket_name으로 연결한다. Wrangler 스키마상 이름 생략은 자동 프로비저닝으로 이어질 수 있으므로 placeholder나 binding-only 설정은 금지한다. 기존 운영 체계가 별도 named 환경을 실제로 사용한다는 근거가 새로 제시되면 non-inheritable vars/r2_buckets를 환경별로 완전하게 반복하되, 근거 없이 env.validation을 만들지 않는다. 참고: Cloudflare R2 binding 설정.

타입과 호환성: 최종 설정 확정 후 npm run cf-typegen을 한 번 실행해 생성 헤더의 TTS vars와 TTS_AUDIO: R2Bucket을 확인한다. worker-configuration.d.ts를 직접 고치지 않고, TtsEnv의 선택성도 유지해 구 설정·테스트 더블·비활성 경로를 보존한다. 타입 생성은 구성 형태를 증명할 뿐 실제 버킷 존재·권한·시크릿 주입을 증명하지 않는다. 참고: Cloudflare TypeScript 타입 생성.

환경 기록: 신규 docs/plans/chinese-tts-audio-environment.md에는 운영/검증별로 Worker 환경 역할, 실제 버킷 식별자와 TTS_AUDIO 매핑, Standard/비공개/도메인/lifecycle 확인 상태, DASHSCOPE_API_KEY의 발급·주입·접근 상태를 각각 날짜·근거와 함께 적는다. 키 값, R2 객체 내용, 계정 인증 토큰은 기록하지 않는다. 실제 연결·청취·모바일·지연·유료 모델 접근은 별도 출시 확인으로 남기며 #150 자동 회귀와 의존시키지 않는다.

4작업 단계

  1. 비밀이 아닌 P2 입력과 증거를 확정한다. 운영/검증 버킷의 실제 이름·대상 계정/역할 매핑을 받아 읽기 전용 bucket list로 존재를 대조하고, domain/lifecycle 메타데이터로 공개 경로 없음과 자동 만료 없음 상태를 확인한다. 인증이 복구되지 않거나 이름이 없으면 상태를 pending으로 유지하고 placeholder를 설정에 쓰지 않는다. docs/plans/chinese-tts-audio-environment.md 완료 — 사용자 확인에 따라 audio-uploads를 개발/테스트용, vocabulary-study-tts-audio를 운영용으로 확정했다. 두 버킷의 Standard, custom domain 없음, r2.dev 비활성, 완성 객체 자동 만료 없음도 읽기 전용으로 확인했다.
  2. 비밀이 아닌 고정 TTS vars를 추가하고 false kill switch를 명시한다. 실제 버킷 식별자가 검증된 경우에만 단일 TTS_AUDIO R2 항목의 운영 bucket_name·검증 preview_bucket_name을 채운다. 키 값, 자동 프로비저닝용 빈 binding, named 환경 추측, 배포·활성화는 포함하지 않는다. wrangler.jsonc 완료 — 고정 vars와 false kill switch, 단일 TTS_AUDIO의 운영 bucket_name·검증 preview_bucket_name을 추가했다.
  3. 환경별 준비표와 검증 경계를 문서화한다. API 키는 “발급 완료 / 주입 미확인 또는 확인 / 접근 미검증”으로 분리하고, 버킷은 식별자·binding·Standard·private·도메인·lifecycle·객체 접근 상태를 분리한다. 실제 접근/청취/모바일/지연은 수행 근거가 없으면 미검증으로 두고 #150이 독립 실행 가능함을 명시한다. docs/plans/chinese-tts-audio-environment.md, docs/plans/chinese-tts-audio-tasks.md 완료 — 환경별 준비표, 상태 분리, #150 독립성을 기록했다.
  4. 최종 Wrangler 설정에서 타입을 재생성한다. 생성 Env의 TTS vars 및 바인딩 형태를 확인하고 diff가 생성 헤더/구성 반영에 한정되는지 검토한다. 기존 optional TtsEnv, Worker 로직, lockfile은 수정하지 않는다. worker-configuration.d.ts, worker/lib/tts/types.ts, package.json 완료 — Wrangler 4.110.0의 지원되는 --env-file에 공개된 기존 secret 이름과 가짜 값만 둔 로컬 합성 fixture를 사용해 기존 secret 타입, vars 타입, TTS_AUDIO: R2Bucket을 생성하고 동일 입력으로 최신성을 확인했다.
  5. 비활성 안전성과 프로젝트 회귀를 검증한다. TTS false에서 provider/R2가 호출되지 않는 기존 테스트, 전체 test/lint/build, Wrangler type check를 실행하고 추적 파일에 시크릿 값이 추가되지 않았는지 변경 파일 기준으로 확인한다. 실제 버킷 객체 read/write·유료 TTS·배포는 실행하지 않는다. worker/lib/tts/config.test.ts, worker/routes/tts.test.ts, worker/routes/words.test.ts, worker-configuration.d.ts, wrangler.jsonc 완료 — 관련 31개와 전체 681개 테스트, lint, build, 합성 입력을 사용한 Wrangler types --check, git diff --check는 통과했다. 최초 typegen 뒤 기존 secret 타입 누락으로 발생한 build 실패는 합성 입력 재생성으로 해결했다. 실제 접근·유료 호출·배포는 범위 밖이며 실행하지 않았다.
  6. 실제 버킷과 원격 메타데이터 증거를 환경 기록과 설정에 일치시키고 ready PR을 준비한다. 범위 밖인 키 주입·배포·실접근은 출시 후속 확인으로 남기며 #150은 독립적으로 진행하고 #151에는 미검증 상태를 그대로 전달한다. docs/plans/chinese-tts-audio-environment.md, docs/plans/issue-149-tts-worker-r2-bindings.html 완료 — 실제 버킷 설정과 정확한 출시 후속 확인을 구분했으며 이슈 소유 범위의 ready PR 조건을 충족했다.

5리스크

리스크영향완화책
실제 버킷 이름 부재 또는 잘못된 계정 매핑다른 데이터 저장소에 연결하거나 Wrangler 자동 프로비저닝으로 범위를 벗어날 수 있다.두 실제 식별자와 대상 계정을 읽기 전용 메타데이터로 대조하기 전에는 r2_buckets를 완성하지 않고 pending으로 둔다.
검증 환경 형태를 임의로 선택존재하지 않는 Worker 환경을 만들거나 non-inheritable vars/bindings 누락으로 환경별 동작이 갈린다.현재 단일 top-level 설정을 기준으로 bucket_name/preview_bucket_name을 사용하고, named 환경은 실제 운영 근거가 있을 때만 완전한 설정으로 추가한다.
시크릿 발급과 주입·접근 성공 혼동disabled 해제 또는 배포 시 tts_not_configured가 발생하거나 민감 정보가 노출될 수 있다.값은 읽거나 기록하지 않고 secret 이름과 상태만 구분한다. TTS_ENABLED=false를 유지하며 실제 주입·접근은 별도 증거 없이는 미검증으로 남긴다.
생성 Env를 손으로 보정하거나 과도한 typegen diff 발생구성과 타입이 다시 드리프트하고 551KB 생성 파일에 불필요한 변경이 섞인다.프로젝트 Wrangler 4.110.0의 npm run cf-typegen만 사용하고, 생성 헤더·해시·runtime 변경을 별도로 검토한다.
자동 검증을 실환경 검증으로 과장R2 권한·비공개 상태·음질·모바일·지연 문제가 출시 뒤 드러날 수 있다.typegen/build/test는 구성·회귀 증거로만 기록하고 실제 R2 객체 접근, Qwen 호출, 청취, 모바일, 지연, 배포는 미검증으로 명시한다.
false kill switch 또는 독립 그래프 경계 훼손유료 호출이 시작되거나 환경 대기가 #150 자동 회귀를 불필요하게 막는다.추적 설정에서 TTS_ENABLED="false"를 단언하고 #149↔#150 의존성을 추가하지 않으며 graph JSON을 수정하지 않는다.

6테스트 계획

  • npm run cf-typegen 후 프로젝트 로컬 Wrangler의 wrangler types --check를 실행한다. 기대: 수동 수정 없이 생성 타입이 최신이며, 실제 binding을 넣은 경우 TTS_AUDIO: R2Bucket과 고정 TTS vars가 생성 Env에 반영된다.
  • git diff -- wrangler.jsonc worker-configuration.d.ts와 git diff --check로 설정/생성 diff를 검토한다. 기대: TTS_ENABLED는 정확히 "false", provider/model/voice/rate/revision은 승인값, bucket 이름은 검증된 실제 식별자이며 secret 값·placeholder·자동 생성 binding은 없다.
  • 소유 경계 회귀인 worker/lib/tts/config.test.ts, worker/routes/tts.test.ts, worker/routes/words.test.ts를 실행한다. 기대: false/누락 설정은 capability만 끄고 R2/provider 0회이며 기존 words/학습 경로는 정상이다.
  • npm test, npm run lint, npm run build를 실행한다. 기대: 전체 테스트·정적 검사·Cloudflare Vite production build가 통과한다. 빌드 통과는 원격 버킷/시크릿 접근 성공으로 해석하지 않는다.
  • 인증 복구 및 실제 이름 제공 뒤 읽기 전용 wrangler r2 bucket list, bucket domain/lifecycle 조회로 이름·비공개·자동 만료 상태를 문서와 대조한다. 기대: 운영/검증 버킷이 분리되고 공개 도메인과 만료 규칙이 없다. 객체 list/get/put은 이번 검증에 포함하지 않는다.
  • 실제 R2 객체 접근·재생, Qwen 모델 접근/유료 합성, 청취 품질, 모바일 브라우저, 실제 지연, 수동 배포는 실행하지 않았다고 결과에 명시한다. 이 항목들은 자동 테스트 통과로 대체하지 않는다.

7완료 조건

  • 검증된 실제 운영/검증 R2 식별자가 TTS_AUDIO의 운영/preview 매핑과 환경 기록에 정확히 일치하며, 빈 이름·placeholder·자동 생성 리소스가 없다.
  • 두 버킷의 Standard 사용, 비공개(r2.dev/custom domain 없음), 자동 만료 lifecycle 없음이 근거와 확인일을 포함해 기록된다. 미확인 상태는 완료로 표시하지 않는다.
  • wrangler.jsonc에 qwen / qwen-audio-3.0-tts-flash / longanfengyue / 1.0 / tts-v1이 명시되고 운영 TTS_ENABLED="false"가 유지된다.
  • npm run cf-typegen으로 생성한 worker-configuration.d.ts가 최종 설정과 일치하고, #135의 optional TtsEnv는 그대로이며 생성 파일에 수동 보정이 없다.
