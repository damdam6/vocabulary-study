#137기능 개선

Qwen 이벤트 검증과 MP3 조립을 구현한다

damdam6/vocabulary-study 브랜치 feat/137-qwen-audio-protocol ← feat/ch-sound 라벨 enhancement 2026-09-16

1요약

QwenCloud WebSocket과 분리된 순수 프로토콜 계층을 추가해 네 종류의 클라이언트 메시지를 직렬화하고, 서버 JSON 이벤트와 바이너리 조각을 제한 안에서 검증·조립한다. 완료는 올바른 task-finished와 구조가 유효한 비어 있지 않은 MP3가 모두 있을 때만 성립하며, 실패는 기존 공통 TTS 오류 코드로 정규화한다. 실제 Upgrade, 인증 헤더, socket·timer·AbortSignal 수명, R2 및 앱 경로는 후속 이슈의 소유 범위로 남긴다.

2현황 분석

선행 #135가 기준 커밋 be74e1270be127a3252e2143e0b5f1560d21ef9c에 합쳐져 있다. 현재 worker/lib/tts/types.ts:6-16에는 MP3 4MiB, JSON 단건 64KiB·누적 1MiB 상한이 있고, worker/lib/tts/types.ts:18-44에는 모델·음색·형식과 24kHz/128kbps/volume/rate/pitch/seed/language hint/SSML 설정이 고정되어 있다.

  • worker/lib/tts/types.ts:46-77의 기존 오류 계약은 제공자 사용 불가를 tts_unavailable, 형식·프로토콜 오류를 tts_upstream_error로 표현한다. 새 공개 오류 문자열이나 제공자 원문을 만들 필요가 없다.
  • worker/lib/tts/types.ts:100-125의 SynthesisInput은 text만 허용하고 TtsProvider 결과는 MP3 바이트와 선택적 실제 billedCharacters를 받는다. worker/lib/tts/pronunciation.ts:3-13도 병음을 진단·저장 키에만 남기고 합성 입력에서 제거한다.
  • worker/lib/tts/config.ts:52-66은 비밀 없는 검증 설정과 API 키/R2 의존성을 분리한다. 프로토콜 직렬화기는 TtsConfig와 SynthesisInput만 받아야 하며 DASHSCOPE_API_KEY나 환경 객체를 받을 이유가 없다.
  • 계획 시점에는 worker/lib/tts/audio.ts와 worker/lib/tts/providers/qwenProtocol.ts가 존재하지 않는다. Vitest는 vitest.config.ts:1-7처럼 Vite/Cloudflare 플러그인 없이 순수 함수 테스트를 실행하므로 이 모듈도 네트워크 없는 Node 테스트로 완결할 수 있다.

저장소 설계는 docs/architecture/chinese-tts-audio.md:104-123에서 run-task → task-started → continue-task + finish-task → result-generated/binary → task-finished 흐름, 상한, 실패 정규화를 정한다. 공식 Qwen 클라이언트 이벤트는 run-task와 finish-task의 빈 input, 취소의 directive: "cancel"을 요구하고, 서버 이벤트는 task-started, result-generated, task-finished, task-failed 및 누적 usage.characters를 정의한다.

소유 경계: docs/architecture/chinese-tts-audio.md:125-138와 docs/plans/chinese-tts-audio-issues/TTS-04.md:24-36에 따라 이번 이슈는 메시지·상태·바이트만 다룬다. 실제 fetch Upgrade, Authorization, WebSocket 리스너와 close/error, abort, 12초 deadline, 한 번만 settle하는 연결 정리는 #138의 worker/lib/tts/providers/qwen.ts가 담당한다. R2 소비·서비스·HTTP 라우트도 구현하지 않는다.

3설계

클라이언트 메시지

worker/lib/tts/providers/qwenProtocol.ts는 호출자가 생성한 UUID, 검증된 TtsConfig, SynthesisInput을 받아 JSON 문자열을 만드는 순수 API를 노출한다. 공통 header는 같은 task_id와 streaming: "duplex"를 쓰고, 메시지별 payload는 아래처럼 고정한다.

메시지직렬화 계약금지 필드
run-taskaudio / tts / SpeechSynthesizer, 확정 model, PlainText, voice, mp3, sample_rate, bit_rate, volume, rate, pitch, seed, language_hints: ["zh"], enable_ssml: false, 빈 inputAPI 키·endpoint·pinyin·instruction·hot_fix·SSML 본문
continue-taskpayload.input.text에 정규화된 A열 원문 전체를 한 번 넣음pinyin·분할/절단·추가 지시
finish-taskpayload.input은 빈 객체종료 외 데이터
cancelaction은 finish-task, payload.input.directive는 cancel별도 가상 action·대기 정책

수신 상태와 오류

같은 파일의 factory는 awaiting-start → streaming → finished/failed 상태를 캡슐화하고 text 또는 Uint8Array만 받는다. task-started는 정확히 한 번, result-generated와 바이너리는 started 이후이자 terminal 이전, task-finished는 started 이후 정확히 한 번만 허용한다. task-failed는 성공 결과 대신 즉시 terminal 실패가 되며, terminal 뒤 추가 입력·중복 시작/완료·알 수 없는 이벤트·다른/비정상 task ID·스키마 오류는 모두 tts_upstream_error다.

  • 각 text 이벤트는 파싱 전에 TextEncoder 기준 UTF-8 바이트를 재고 단건 64KiB와 실행 누적 1MiB를 검사한다. primitive/null/array JSON, header/event/task_id 누락 및 잘못된 필드 타입은 성공 경로에 들어오지 못한다.
  • 문서화된 인증·권한·할당량·요청 제한 error_code만 명시적 allowlist로 tts_unavailable에 매핑한다. InvalidParameter와 알 수 없는 값은 tts_upstream_error이며, 분류에 error_message를 사용하거나 반환 오류에 복사하지 않는다.
  • usage.characters는 유한한 비음수 safe integer일 때만 최신 누적값으로 보존하고, 유효한 task-finished 값이 있으면 갱신한다. 누락·잘못된 값은 결과에서 생략하며 원문 길이로 추정하지 않는다.
  • 바이너리는 받은 순서의 조각 배열로 보관하고 합계를 먼저 계산한다. 4MiB를 넘는 조각은 복사·추가 전에 거부하며, task-finished에서만 정확한 크기의 버퍼를 한 번 할당해 순서대로 복사한다. 부분 결과나 빈 배열은 절대 결과로 노출하지 않는다.

공용 MP3 검사

worker/lib/tts/audio.ts의 validateMp3(audio, contentType)는 기존 ValidateAudio와 호환되는 동기 boolean 함수로 만든다. MIME을 안전하게 정규화한 뒤 audio/mpeg만 허용하고, 1..4MiB 크기 안에서 optional ID3 메타데이터 길이를 경계 검사한 다음 MPEG Layer III frame header의 version/bitrate/sample-rate/padding으로 frame 길이를 계산해 끝까지 순회한다. 최소 한 개의 완전한 audio frame과 버퍼 경계의 정확한 종료를 요구해 ID3-only, 첫 sync만 맞는 바이트, 잘린 마지막 frame, reserved/free bitrate, trailing garbage를 거부한다.

작은 유효 MPEG frame으로 구성한 테스트 전용 fixture와 손상 변형을 worker/lib/tts/fixtures/mp3.ts에 둔다. 브라우저 계약 fixture인 src/lib/ttsFixtures.ts:3-12의 임의 문자열 Blob을 유효 MP3로 바꾸지 않으며, 후속 R2/provider 테스트가 같은 Worker fixture와 검사기를 재사용할 수 있게 한다.

4작업 단계

  1. 재사용 가능한 MP3 fixture와 공용 검사기를 구현한다. 고정된 작은 Layer III frame fixture를 만들고 MIME·크기·ID3 길이·frame header와 계산된 frame 경계를 검사한다. 빈 바이트, HTML/JSON/WAV, metadata-only, reserved header, 중간/마지막 frame 절단, trailing garbage를 false로 반환하며 예외나 디코더·I/O를 사용하지 않는다. worker/lib/tts/audio.ts, worker/lib/tts/audio.test.ts, worker/lib/tts/fixtures/mp3.ts, worker/lib/tts/types.ts (기존 상수·타입 import만)
  2. Qwen 네 종류의 outbound 메시지 직렬화기를 추가한다. 호출자 UUID와 검증 설정을 한 번 받아 공통 header를 유지하고, 공식 필드명과 빈 input 형태를 정확히 만든다. 중국어 따옴표·개행도 JSON.stringify로 안전하게 보존하고, API 키·socket·endpoint 및 pinyin/SSML/instruction/hot_fix가 결과의 어느 깊이에도 없는지 테스트한다. worker/lib/tts/providers/qwenProtocol.ts, worker/lib/tts/providers/qwenProtocol.test.ts, worker/lib/tts/types.ts, worker/lib/tts/pronunciation.ts (기존 계약 소비)
  3. 서버 이벤트를 검증하는 순수 상태 처리기를 구현한다. UTF-8 JSON 단건·누적 상한을 파싱 전에 검사하고, UUID 일치·이벤트 스키마·started/result/finished 순서를 강제한다. task-failed의 문서화된 code allowlist만 503 계열로 매핑하고 나머지 파싱·형식·순서 오류는 502 계열로 정규화하며 제공자 메시지를 폐기한다. worker/lib/tts/providers/qwenProtocol.ts, worker/lib/tts/providers/qwenProtocol.test.ts, worker/lib/tts/types.ts (기존 상한·TtsErrorCode import)
  4. 바이너리 조립과 완료 게이트를 상태 처리기에 연결한다. started 이후 binary만 순서대로 보관하고 4MiB 초과를 복사 전에 차단한다. task-finished에서 단 한 번 조립해 validateMp3를 통과한 비어 있지 않은 바이트만 반환하며, 사용량은 유효한 누적값만 선택적으로 넣는다. 정상 JSON/binary 교차 흐름, 조각 경계가 frame 내부인 흐름, 빈/손상/부분 MP3와 완료 누락을 순수 fixture로 검증한다. worker/lib/tts/providers/qwenProtocol.ts, worker/lib/tts/providers/qwenProtocol.test.ts, worker/lib/tts/audio.ts, worker/lib/tts/fixtures/mp3.ts
  5. 소유 범위와 회귀를 검증하고 구현 증거를 기록한다. 전용 테스트에서 정상·오류·상한의 경계값을 확인한 뒤 전체 test/lint/build를 실행한다. 성공한 항목만 계획에 체크하고 실제 명령 결과 및 외부 미검증 사항을 남긴다. 구현 세션은 feat/ch-sound base의 ready PR을 만들지만, 이 계획 세션은 앱 코드·테스트 구현·commit/push/PR을 수행하지 않는다. worker/lib/tts/audio.test.ts, worker/lib/tts/providers/qwenProtocol.test.ts, docs/plans/issue-137-qwen-audio-protocol.html, .issue-codex/interactive-state.json

5리스크

리스크영향완화책
MP3를 magic byte만 보고 허용HTML/JSON, ID3-only, 잘린 frame이나 저장소 손상이 정상 음성으로 반환될 수 있다.MIME·전체 크기·ID3 bounds·계산된 Layer III frame 경계를 모두 검사하고 최소 한 frame 및 정확한 종료를 요구한다.
유효 MP3 변형을 지나치게 좁게 해석Qwen이 ID3 또는 가변 bitrate frame을 반환할 때 정상 결과를 거부할 수 있다.고정 128kbps signature가 아니라 version별 bitrate/sample-rate 표와 frame 길이를 사용하고, 명시적으로 지원하는 metadata 변형을 fixture로 고정한다. 실제 제공자 출력 호환은 미검증으로 남긴다.
JSON/오디오 누적 중 메모리 증폭상한을 넘긴 뒤 복사하면 Worker 메모리와 CPU를 불필요하게 소모한다.UTF-8/바이너리 크기를 추가 전에 검사하고, 조각은 참조로 모아 완료 시 한 번만 합친다.
실패 메시지 문자열에 의존한 분류문구 변경으로 502/503이 흔들리거나 원문·민감 데이터가 외부 오류에 섞일 수 있다.error_code exact allowlist만 사용하고 unknown은 502로 닫으며 error_message는 보관·출력하지 않는다.
#138 연결 수명 책임 선행 구현socket close·abort·timeout 상태가 두 모듈에 중복되어 정리/settle 경쟁이 생긴다.processor 입출력을 string/Uint8Array와 상태 update로 제한하고 fetch/WebSocket/timer/R2 import 부재를 코드 리뷰와 정적 검색으로 확인한다.
fixture 통과를 실제 음질·계정 검증으로 오인형식 테스트가 모델 접근·과금·청취 품질·실환경 호환을 보장하지 못한다.실제 키, 유료 합성, R2, 청취, 모바일, 지연은 실행하지 않고 후속 출시 검증으로 명시한다. TTS_ENABLED=false를 유지한다.

6테스트 계획

  • 직렬화: run-task의 모델·설정·필드명과 continue-task의 원문, 정상 finish의 빈 input, cancel directive를 exact object로 비교한다. 중국어/따옴표/개행 round-trip과 네 메시지의 같은 UUID를 확인하고, 결과 전체에서 pinyin/API key/SSML text/instruction/hot_fix가 없음을 검사한다.
  • 정상 수신: task-started → result-generated → 여러 binary 조각 → result-generated → task-finished를 섞어 넣어 fixture MP3가 byte-for-byte 원래 순서로 복원되고 contentType이 audio/mpeg인지 확인한다. 조각 경계를 MPEG frame 중간에 두어 chunk 단위 검사를 하지 않음을 보장한다.
  • 이벤트 순서/형식: started 전 result/binary/finished, 중복 started/finished, terminal 후 추가 입력, 다른 UUID, 비-UUID task_id, unknown event, header/payload 누락, null/array/primitive/깨진 JSON을 각각 tts_upstream_error로 확인한다. task-failed는 started 전·후 모두 성공이 아니며 부분 바이트를 반환하지 않는다.
  • task 오류 분류: 인증·권한·quota·throttling의 allowlist 대표 code는 tts_unavailable, InvalidParameter·빈 값·unknown은 tts_upstream_error인지 확인한다. sentinel error_message가 throw/result/직렬화된 오류 어디에도 포함되지 않는지 검사한다.
  • 사용량: result-generated의 누적값과 task-finished의 최종값을 처리하고, 누락·문자열·음수·소수·NaN 범주의 JSON 값·safe integer 초과는 생략한다. 어느 경우에도 입력 text.length 또는 코드 포인트 수를 fallback으로 넣지 않는다.
  • 크기 상한: UTF-8 text 이벤트 64KiB 정확히/초과, 여러 이벤트 누적 1MiB 정확히/초과를 검사한다. MP3 조각 합계는 4MiB 이하에서 구조 검증까지 진행하고 다음 조각이 상한을 넘으면 그 조각을 보관·복사하지 않은 채 실패한다.
  • MP3 구조: 정확한 audio/mpeg과 안전한 대소문자/parameter 정규화, 최소 유효 frame, 여러 frame, 경계가 맞는 ID3 metadata를 통과시킨다. 잘못된 MIME, 0 byte, 4MiB 초과, HTML/JSON/WAV, ID3-only/과대 ID3, reserved/free header, 잘린 frame, trailing garbage는 모두 false여야 한다.
  • 소유 테스트: npm test -- worker/lib/tts/audio.test.ts worker/lib/tts/providers/qwenProtocol.test.ts를 실행한다. 네트워크·실제 키·R2 없이 결과가 결정되어야 한다.
  • 전체 회귀: npm test, npm run lint, npm run build를 실행한다. 타입 빌드는 protocol export가 기존 TtsConfig/SynthesisInput/ValidateAudio/TtsErrorCode 계약과 맞는지도 검증해야 한다.
  • 정적 범위 확인: 변경 파일과 import를 검토해 fetch, WebSocket, timer, R2, API key/env 접근이 없고 worker/lib/tts/providers/qwen.ts나 앱 경로를 선행 구현하지 않았는지 확인한다. 실제 DashScope 호출·리소스 생성·배포·청취·모바일 검증은 하지 않는다.
  • 이 계획 단계의 검증: HTML placeholder·구조·참조 경로·Git 변경 범위를 검사하고 공유 서버의 plan URL을 HTTP 200으로 확인한다. 앱 테스트는 구현 단계에서 실행하므로 현재 기능 통과를 주장하지 않는다.

7완료 조건

  • 확정 TtsConfig, UUID, A열 SynthesisInput.text로 run/continue/finish/cancel JSON을 만들며 네 메시지의 ID와 공식 payload 형식이 일치한다.
  • 직렬화 결과에 API 키·socket·pinyin·SSML 본문·instruction·hot_fix·대체 모델/endpoint가 없다.
  • task-started/result-generated/task-finished/task-failed의 스키마, UUID 일치, 허용 순서를 검사하고 malformed JSON·unknown/중복/역순 이벤트를 성공으로 처리하지 않는다.
  • JSON 단건 64KiB·누적 1MiB와 binary 누적 4MiB를 추가/복사 전에 강제하며, 실패 시 부분 결과를 노출하지 않는다.
  • JSON과 여러 binary 조각이 섞인 정상 흐름에서 원래 순서의 MP3를 한 번 조립하고, task-finished와 공용 validateMp3 통과가 함께 있을 때만 완료 결과를 반환한다.
  • validateMp3가 ValidateAudio 포트와 호환되고 MIME·크기·metadata/frame 전체 경계를 검사해 빈 오디오, HTML/JSON/WAV, 손상·절단·trailing garbage를 거부한다. 재사용 가능한 최소 유효/손상 fixture가 있다.
  • usage.characters는 유효한 제공자 누적값만 선택적으로 포함하고, 누락·잘못된 값을 원문 길이로 추정하지 않는다.
  • task-failed의 안정적 code allowlist만 tts_unavailable로 분류하고 다른 protocol/format 실패는 tts_upstream_error다. 제공자 원문 오류·입력·비밀은 공개 오류에 포함되지 않는다.
  • 소유 모듈과 테스트는 socket·timer·fetch·R2를 사용하지 않으며 #138 이후 앱/저장/서비스 코드를 선행 구현하지 않는다. 운영 TTS_ENABLED=false와 graph JSON은 그대로다.
  • 전용 테스트(34개), 전체 npm test(509개), npm run lint, npm run build가 통과했다. 실제 키·모델 접근·R2·청취·모바일·지연은 안전 조건에 따라 미검증이다.
  • 구현 PR은 base feat/ch-sound, head feat/137-qwen-audio-protocol을 명시하고 변경 범위·검증·Closes #137를 기록한다.

R1독립 리뷰 수정 기록

공식 서버 이벤트 계약상 sentence-synthesis 이벤트 직후 WebSocket binary 메시지 한 개가 대응하므로, 처리기에 해당 binary 대기 상태를 추가했다. 예고 없는 binary, binary 대기 중 JSON 또는 완료, 한 이벤트에 대한 중복 binary를 tts_upstream_error로 거부한다. sentence-begin/sentence-end 메타데이터와 유효한 누적 usage.characters 처리는 유지했다.

검증: 정상 다중 프레임과 네 종류의 순서 위반 회귀를 포함한 전용 테스트 38개, 전체 테스트 513개, lint와 build가 통과했다. 소켓 수명·실제 제공자 호출·키·R2·배포·청취는 범위 밖으로 유지했다.
