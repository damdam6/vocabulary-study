1요약

#188에서 만든 학습 범위 모델(src/lib/studyScope.ts)을 홈 화면에 연결한다. 스페이서 아래에 세그먼트 전체 | 탭 선택과 다중 선택 탭 칩 목록을 두고, 현황 카드·세션 수·시작 큐를 모두 하나의 거른 단어 배열에서 계산해 #128 불변식(표시 수 = 큐 길이)을 지킨다. 선택은 프로필별로 저장·복원되며 학습·완료 화면, 기록 API, 재시도 큐, TTS는 건드리지 않는다.

2현황 분석

  • 홈은 마운트마다 fetchWords를 호출하고(src/screens/HomeScreen.tsx:44-68), 응답 시점에 computeHomeStats(fetched, getSeoulToday(), modes, sessionLimit)를 한 번 계산해 stats 상태로 굳힌다(HomeScreen.tsx:56). 범위가 바뀌어도 다시 계산할 길이 없다.
  • 시작 버튼은 전체 words로 buildSessionQueue를 호출한다(HomeScreen.tsx:91-95). 카드·세션 수와 큐는 "같은 단어 배열 + 같은 산식"이라는 전제로만 일치한다(HomeScreen.tsx:3, src/lib/homeStats.ts:17-20).
  • 렌더 순서는 헤더 → 현황 카드 → .home-spacer → 미전송 인디케이터 → .session-count → .start-button(HomeScreen.tsx:129-161). PRD §4.1은 선택 UI를 스페이서 아래·인디케이터 위에 두라고 한다.
  • #188이 제공하는 것: deriveTabs(시트 순서 탭 목록), filterWordsByScope(공유 필터), saveStudyScope(0개 선택은 저장 안 함, all 저장 시 마지막 탭 선택 보존), restoreStudyScope(누락 탭 정리·전부 사라지면 전체), getLastTabSelection(src/lib/studyScope.ts:28-152).
  • "문제 수가 가장 많은 탭 1개(동률이면 앞선 탭)" 초기 선택을 고르는 함수는 아직 없다.
  • Dropdown(src/components/Dropdown.tsx)은 단일 선택 리스트박스라 쓰지 않는다. 레포에 radiogroup·aria-pressed 패턴은 아직 없다. 포커스 링 기준은 .dropdown-trigger:focus-visible { outline: 2px solid var(--accent); outline-offset: -1px }(src/index.css:1253-1256)이다.
  • 프로필 전환(clearPassword, src/lib/api.ts:20-23)은 비밀번호와 프로필 캐시만 지우므로 vocab-study:study-scope는 남는다. 재로그인 후 복원이 그대로 된다.
  • 레이아웃: .app-column은 min-height: 100dvh이고 .home-screen은 세로 flex에 스페이서로 시작 버튼을 바닥에 붙인다(src/index.css:72-90, 861-901). 칩 목록 높이를 제한하지 않으면 탭이 많을 때 시작 버튼이 첫 화면 밖으로 밀린다.
  • DOM 테스트는 react-dom/client과 act를 쓰는 자체 헬퍼로 한다(src/test-utils.tsx). HomeScreen.test.tsx는 fetchWords를 목으로 바꿔 쓴다.

3설계

상태와 파생값 (HomeScreen)

  • stats 상태를 없애고 파생값으로 바꾼다. 상태로 두는 것은 words·profile·sessionLimit·today(조회 시점의 getSeoulToday(), 기존 의미 유지)·scope: StudyScope다.
  • tabs = useMemo(deriveTabs(words)). pickerVisible = status === "ready" && tabs.length > 1. 선택 UI를 숨기면 유효 범위는 항상 {kind:"all"}이다(탭 1개 프로필은 전체로 동작). 이때 저장값은 덮어쓰지 않는다. 나중에 탭이 늘면 원래 선택이 돌아와야 하기 때문이다.
  • scopedWords = useMemo(filterWordsByScope(words, effectiveScope)) 하나를 computeHomeStats와 handleStart의 buildSessionQueue가 함께 쓴다. 필터 호출은 한 곳에만 두고, 이것으로 #128 불변식을 지킨다.
  • 칩별 n: 탭마다 computeHomeStats(filterWordsByScope(words, {kind:"tabs", tabs:[tab]}), …).sessionCount로 구한다. 같은 필터와 같은 산식이라 "그 탭만 골랐을 때의 세션 수"와 정의상 같다.

복원·저장·초기 선택

  • 조회에 성공하면 restoreStudyScope(fetchedProfile.id, deriveTabs(fetched))로 범위를 복원한다. 매 홈 진입마다 새 응답으로 다시 검증하며, 누락 탭 정리와 저장값 갱신은 #188 함수가 맡는다.
  • 변경할 때마다(세그먼트 전환, 칩 토글, 모두 선택/해제) 이벤트 핸들러에서 saveStudyScope(profile.id, next)를 호출한다. 0개 선택은 모듈이 저장하지 않는다.
  • 탭 선택으로 바꿀 때는 getLastTabSelection(profile.id, tabs) 값을 쓰고, 비어 있으면 새 순수 함수 pickDefaultTabSelection(tabCounts)(최대 n 탭 1개, 동률이면 시트 순서상 앞)를 쓴다. 이 경로 하나로 "전체→탭 선택 시 이전 칩 복원"과 "첫 전환 시 기본 탭"을 모두 처리한다.
  • 선택 배열은 항상 tabs(시트 순서)로 다시 정렬해 보관한다. 세션 수 줄의 첫 이름을 시트 순서로 정하기 위해서다.

UI 컴포넌트 StudyScopePicker (새 파일, 완전 제어형)

  • props: kind, tabs: {name, count}[], selected: string[], onKindChange, onSelectedChange.
  • 세그먼트: role="radiogroup"(라벨 학습 범위) 안에 role="radio" 버튼 2개를 두고 aria-checked와 roving tabIndex를 쓴다. ←/→/↑/↓ 키로 포커스를 옮기면서 바로 선택하는 WAI-ARIA 라디오 패턴이다.
  • 탭 선택일 때만 칩 영역을 렌더한다. 위에 저강조 텍스트 버튼 모두 선택/선택 해제(하나라도 꺼져 있으면 모두 선택)를 두고, 아래에 role="group" aria-label="학습할 탭" 안의 <button aria-pressed> 칩을 둔다. 네이티브 버튼이라 Tab 이동과 Space/Enter 토글이 기본으로 된다.
  • 칩 내용: 체크 표시(선택 시, aria-hidden) + 말줄임되는 이름 + · n. 선택된 칩은 accent 테두리, 옅은 accent 배경, --text, 체크 표시로, 꺼진 칩은 bg-panel과 text-muted로 표시한다. n=0이면 is-empty로 흐리게 하되 누를 수 있다.

표시 규칙

  • 세션 수 줄: 전체이면 현행 문구, 탭 1개이면 HSK6 · 오늘 세션 · n문제, 2개 이상이면 HSK6 외 k개 탭 · 오늘 세션 · n문제로 표시한다. 탭 이름 부분만 말줄임한다(320px에서 긴 이름이 줄을 넘치지 않도록).
  • 0개 선택이면 세션 수 줄을 숨기고, 시작 버튼을 비활성화하고 라벨을 탭을 선택하세요로 바꾼다. 카드는 거른 결과대로 0이 된다.
  • 범위 안에 할 것이 없으면 기존 오늘 할 것 없음을 쓴다.

레이아웃·스타일 — 칩 목록은 flex-wrap에 3줄 높이 max-height와 overflow-y: auto를 준다. 칩은 max-width: 100%이고 이름 span은 말줄임한다. 포커스 링은 .dropdown-trigger와 같게 둔다(offset −1px라 스크롤 컨테이너에 잘리지 않는다). 토큰은 design-prd §1만 쓰고, 옅은 accent 배경만 --accent 기반 rgba 파생값으로 쓴다(--accent-hover 선례).

기각한 안

  • stats를 상태로 두고 범위를 바꿀 때마다 setStats: 필터를 여러 곳에서 호출하게 돼 #128 불변식이 흐려진다.
  • 범위 저장을 useEffect([scope])로 처리: 복원 직후에도 한 번 더 저장해 불필요하게 쓰고, 탭 1개 프로필에서 숨겨진 범위를 덮어쓸 위험이 있다. 그래서 이벤트 핸들러에서만 저장한다.
  • 칩 대신 체크박스 목록이나 Dropdown 확장: PRD §4.1이 칩과 새 컴포넌트를 지정했다.

5리스크

리스크영향완화책
카드·세션 수와 큐가 서로 다른 단어 집합을 씀#128 회귀. 표시 n과 실제 큐 길이가 어긋나거나 빈 큐로 시작scopedWords 한 값을 두 경로가 공유한다. 테스트에서 세션 수 표시와 큐 길이를 같은지 비교한다.
첫 진입 회귀기존 사용자 수치가 달라짐저장값이 없으면 전체이고 필터 결과가 전체 복사본이다. 전체 범위의 수치와 큐 길이를 기존 산식과 비교하는 테스트를 둔다.
탭 1개 프로필에서 숨겨진 저장 범위가 적용됨UI 없이 결과가 좁아질 수 있음선택 UI를 숨기면 유효 범위를 강제로 전체로 둔다(탭 1개면 결과도 같다).
탭이 많거나 이름이 길 때 모바일 레이아웃이 깨짐가로 스크롤이 생기거나 시작 버튼이 화면 밖으로 나감칩 max-height 스크롤, 이름 말줄임, 세션 수 줄 말줄임을 적용하고 320·375px에서 직접 확인한다.
선택된 칩의 accent 테두리와 포커스 링이 겹침키보드 포커스가 잘 안 보임링 두께 2px가 테두리 1px보다 두껍다. 선택 칩 배경도 옅은 accent라 대비는 확보된다. 사양대로 .dropdown-trigger와 같게 둔다.

6테스트 계획

  • studyScope.test.ts: pickDefaultTabSelection의 최대값, 동률 시 시트 순서, 전부 0, 빈 입력.
  • HomeScreen.test.tsx 회귀: 저장값이 없으면 전체가 체크되고, 세션 수 문구가 현행 오늘 세션 · n문제이며, 큐 길이가 전체 단어 기준 산식과 같다. 기존 테스트 5+1개는 수정 없이 통과한다.
  • 탭 선택 첫 전환이면 최대 n 탭 1개가 선택된다(동률이면 앞선 탭). 탭 1개와 n개일 때 시작 큐의 모든 문제의 word.tab이 선택 탭에 속하고, 세션 수 표시 n이 큐 길이와 같다. 칩 n의 합(예: 4+4=8)과 합집합 상한(5)이 다른 데이터로 검증한다.
  • 미선택 탭에 복습 대기가 있어도 복습 대기 카드·세션 수·큐에 없다.
  • 칩을 모두 끄면 버튼이 비활성화되고 라벨이 탭을 선택하세요가 되며, 세션 수 줄이 없고 카드가 0이다. 모두 선택과 선택 해제의 라벨 전환과 동작도 본다.
  • 전체로 갔다가 다시 탭 선택으로 오면 이전 칩 선택이 돌아온다. 재마운트(새로고침)하면 같은 범위와 칩이 복원된다. 프로필 A/B 목 응답을 번갈아 쓰면 각자의 범위가 복원되고 섞이지 않는다.
