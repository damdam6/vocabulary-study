# 시트별 세션 문제 수 + 홈 상단 유틸 바 플랜

> 소유자 요청(2026-07-28): ① 1회(세션) 문제 수를 시트마다 다르게 설정 — 스프레드시트의 **'정보' 탭**에 `문제수 | 30` 형태(키 셀 옆칸에 값)로 두고 서비스가 따른다. ② 홈 하단 저강조 링크 대신 **상단 유틸 아이콘**(참고: BERNICE 앱의 우상단 자물쇠 버튼 위치) — 수정 아이콘(노트+연필)은 "단어 등록 / 1회 문제 수 수정" 두 옵션 메뉴, 사람 아이콘(상반신 실루엣)은 프로필 접근.
>
> 기준 문서: `docs/PRD.md` §6.1(세션 60문제 상한)·§4(시트 구조), `docs/design-prd.md` §3(홈). 이 문서는 그 위의 **변경분만** 정의한다.
>
> 작성일: 2026-07-28 · 상태: **확정** — 같은 날 소유자 확인으로 §7 Q1~Q7 전부 해소 (Q1은 '_정보'로, Q7은 등록 화면 통합으로 기본값 변경). **코드 착수 가능.** 작업 분해·그래프는 §5.

## 1. 배경·목표

- 세션 문제 수 60은 상수다: `src/lib/sessionQueue.ts`의 `SESSION_CAP = 60`과 `src/lib/homeStats.ts`의 동명 로컬 상수(중복). 프로필(시트)마다 학습량이 다르므로 — 예: 영어 표현 시트는 30문제 — **시트가 자기 설정을 갖게** 한다. 설정 저장소는 Worker 시크릿(`PROFILES`)이 아니라 **시트 안('_정보' 탭)**: 소유자가 시트에서 직접 고칠 수 있고, 프로필 시크릿 갱신 없이 반영되며, 시트 = 원천 데이터라는 서비스 정체성과 맞는다.
- 앱에서도 고칠 수 있어야 한다("1회 문제 수 수정") — 시트 쓰기는 Worker 일원화 원칙(PRD §4)이므로 쓰기 API가 필요하다.
- 홈 진입 액션이 하단 저강조 링크 2개(단어 등록 › · 프로필 전환)에 숨어 있다 — 참고 이미지(BERNICE)처럼 **상단 우측 라운드 아이콘 버튼**으로 승격하고, 수정 계열 액션(등록·설정)을 메뉴 하나로 묶는다.
- 목표: 세션 상한의 파라미터화(기본 60, '정보' 탭 값으로 대체)와 홈 유틸 바 도입. 학습 규칙의 다른 상수(정답 3회 졸업, 간격 사다리 등)는 **불변**.
- 비목표: '_정보' 탭의 다른 설정 키 도입(구조만 전방 호환으로), 프로필 시크릿 스키마 변경, 학습·복습 알고리즘 변경, 학습 중 화면의 UI 변경.

## 3. 설계

### 3.1 '_정보' 탭 계약

- **탭 이름 '_정보'** (소유자 확정 Q1): 기존 "`_` 접두 = 학습 제외" 규약(PRD §4.1)을 그대로 재사용한다 — words(출제)·tabs(드롭다운)·등록(대상 지정·createTab, `_` 시작 차단)에서 **이미 자동 제외/차단되므로 제외용 코드 변경이 없다**. Worker 설정 로직만 '_정보' 탭을 직접 읽고 쓴다. 주의: 비접두 '정보'로 만들면 단어 탭으로 스캔·출제된다 — 이미 '정보'로 만든 시트가 있다면 '_정보'로 이름을 바꾼다.
- **구조**: 헤더 행 없음. A열 = 설정 키, B열 = 값. 행 위치 자유 — A열에서 키를 정확 일치(트림)로 탐색해 그 행의 B열을 읽는다. **모르는 키는 무시**(전방 호환 — 이후 설정 추가 여지). 이번에 인식하는 키는 `문제수` 하나.
- **`문제수` 값**: 세션당 최대 문제 수. 정수 1~500. **읽기는 관대** — 탭 없음/키 없음/비정수/범위 밖 → 기본 60으로 폴백하고 words 호출을 실패시키지 않는다. **쓰기는 엄격** — §3.3.
- 이 탭은 단어 탭 컬럼 계약(A~G)의 적용 대상이 아니다 — PRD §4.1 개정에 명시.

### 3.2 읽기 경로 — words 응답에 settings 동봉

- `GET /api/words` 응답 최상위에 `"settings": { "sessionLimit": 30 }` 블록을 추가한다(프로필 블록과 같은 패턴 — 홈 진입마다 재조회되므로 시트에서 값을 고쳐도 다음 홈 진입에 자연 반영). `/api/health`에는 넣지 않는다(로그인 시점에 불필요).
- Worker: words 라우트가 '_정보' 탭 `A:B`를 1회 읽어 합성(탭 부재·읽기 실패 → 기본 60). 시트 읽기 1회 추가 비용은 허용.
- 클라: `fetchWords` 반환을 `{ profile, words, settings }`로 확장(응답에 없으면 `{ sessionLimit: 60 }` — 구서버 호환). `buildSessionQueue(words, today, modes, rng, limit)`·`computeHomeStats(words, today, modes, limit)`로 상한을 스레딩 — 복습 대기 "오래된 순 컷"과 총 상한, 홈 `sessionCount`가 전부 같은 limit을 쓴다. homeStats의 중복 상수는 제거하고 sessionQueue의 `SESSION_CAP`을 기본값 상수로 일원화.
- 진행 중인 세션에는 영향 없다 — 큐는 세션 시작 시 확정(변경은 다음 세션부터).

### 3.3 쓰기 API — `POST /api/settings`

- 요청 `{ "sessionLimit": n }` — 정수 1~500 아니면 400(문구에 허용 범위 명시). 인증·프로필 해석은 기존 Bearer 그대로(인증된 프로필의 시트에 쓴다).
- 동작: '_정보' 탭 없으면 생성(빈 탭 — 단어 탭 헤더 복사 없음), `문제수` 행 없으면 A열 첫 빈 행에 `[문제수, n]` 추가, 있으면 **그 행의 B열만** 갱신(다른 행·열 불가침). `valueInputOption=RAW`. 응답 `{ "sessionLimit": n }`(반영값).
- 실패 시 재시도 큐 대상이 아니다 — 설정 변경은 유실되면 재입력이 맞고(학습 기록과 다름), 오류는 문제수 필드 옆에 즉시 표시한다(§3.5).

### 3.4 홈 상단 유틸 바

- 위치: 홈 헤더 상단 **우측**(참고 이미지의 자물쇠 버튼 위치) — 라운드 사각 아이콘 버튼 2개 나란히. 구성(위→아래) 개정: 날짜/타이틀 행 우측에 유틸 바 → 이하 동일. 구체 스타일(크기·여백·순서)은 design-prd 개정에서.
- **수정 버튼**(노트+연필 아이콘): 탭 시 옵션 메뉴 — ① **단어 등록**(기존 register 화면 이동, 전 프로필 #101 유지) ② **1회 문제 수 수정**(같은 register 화면으로 이동해 상단 '문제수' 필드에 포커스 — §3.5). 메뉴는 경량 팝오버로, 바깥 탭 닫힘은 기존 커스텀 드롭다운의 pointerdown 패턴(#66) 재사용.
- **사람 버튼**(상반신 실루엣 아이콘): 프로필 전환 — 현행 하단 링크와 동일 동작(저장된 비밀번호·프로필 캐시 삭제 → 로그인 화면, 확인 단계 없음).
- 하단 "단어 등록 ›"·"프로필 전환" 링크는 **제거**(유틸 바가 대체). 등록 링크의 "오늘 학습 상태와 무관하게 항상 노출" 성질은 유틸 바가 승계한다.
- 아이콘: 인라인 SVG 자체 제작(외부 아이콘 라이브러리 도입 없음), `aria-label`·버튼 시맨틱 준수.

### 3.5 "1회 문제 수" 편집 — 등록 화면 상단 필드 (소유자 확정 Q7)

- 별도 모달·화면이 아니라 **단어 등록 화면 상단에 '문제수' 필드 섹션을 추가**한다 — 등록 화면이 "시트 편집 창구"를 겸한다. 타이틀과 이하 등록 플로우(붙여넣기 → 확인 → 탭 선택 → 제출)는 불변.
- 구성: 현재값 표시(등록 화면이 이미 부르는 words 응답의 `settings.sessionLimit`) + 숫자 입력(1~500 클라 선검증 — 최종 강제는 Worker) + **전용 저장 버튼**. 등록 제출과 완전 독립 — 문제수 저장이 아래 등록 배치에 영향 없고, 역도 같다.
- 저장 → `POST /api/settings` → 성공 시 반영값·성공 표시(홈 복귀 시 sessionCount는 words 재조회로 자연 갱신). 실패 → 필드 옆 오류 문구, 입력값 유지.
- 홈 수정 메뉴의 "1회 문제 수 수정" 옵션은 이 화면으로 이동해 문제수 필드에 포커스/스크롤한다(§3.4).

## 6. 테스트 전략

- **기준선**: 기존 스위트가 limit 기본값 60 경로로 무수정 통과(인자 추가만 허용) — 동작 보존 증명.
- **settings 파서(Worker)**: 정상(`문제수|30`), 행 위치 자유, 탭 없음/키 없음/비정수/0/501/음수 → 60 폴백, 모르는 키 무시.
- **'_정보' 자연 제외**: 기존 `_` 규칙으로 words 출제·tabs 목록·등록 대상에서 빠지는지 회귀 확인(신규 제외 로직 없음).
- **쓰기 API**: 400 경계(0·501·비정수·누락), 탭 생성/행 추가/B열 갱신 각각의 range 검증(mock URL — 다른 셀 불가침), 프로필 sheetId 격리.
- **클라**: limit 30/60/1 경계에서 큐 컷·sessionCount 일치, settings 부재 폴백, 문제수 필드 검증·성공 반영·실패 문구·등록 제출과의 독립성(필드 저장이 등록 배치에 영향 없음).
- **홈 UI**: 유틸 바 렌더·메뉴 열림/바깥 닫힘(pointerdown)·프로필 전환 동작, 하단 링크 부재.
