# 중국어 발음 읽어주기(TTS) — 결정 내역

> 소유자 요청(2026-09-14): ① 콘텐츠 타입이 `zh`일 때 표제어를 **음성으로 읽어주는 기능**을 넣는다. ② 브라우저 내장 음성이 아니라 **유료 모델**을 붙인다 — "중국 모델이 발음 정확할 것 같음". ③ 추후 단어가 아니라 **문장**도 `zh`(타입 1번)로 등록할 예정이며, 그때도 읽어줘야 한다 — 제공자 선택 기준에 **문장 읽기 자연스러움**을 포함한다.
>
> 기준 문서: `docs/PRD.md` §4(시트 구조)·§11(비목표), `docs/PRD-general.md` §5.2(A/B/C열 계약)·§7(콘텐츠 타입), `docs/design-prd.md` §4.2·§4.3·§4.6. 이 문서는 그 위의 **변경분과 결정 내역만** 담는다.
>
> 작성일: 2026-09-14 · 상태: **부분 확정** — 노출·재생 정책은 확정(§2 D1~D5, §3), **TTS 제공자는 미정**(§4 후보군 · §7 Q1). 제공자가 정해지기 전까지 코드 착수 없음.

---

## 1. 배경·목표

- 현재 앱은 한자를 **눈으로만** 학습한다. `zh` 프로필에서 병음(B열)이 있어도 실제 소리를 확인할 방법이 없어, 성조·연음 감각이 붙지 않는다.
- `docs/PRD.md` §11(비목표)에 "예문, 발음 오디오(TTS)"가 명시돼 있다 — 이 문서는 그중 **발음 오디오를 v1.x 범위로 승격**한다(§6에서 PRD 개정 필요 항목으로 추적).
- **자산**: 시트 B열에 이미 병음이 들어 있다(`PRD-general` §5.2). 다음자(多音字) 오독을 막는 발음 힌트로 그대로 재사용할 수 있다 — 제공자가 SSML 음소 지정을 지원하면 "行"을 `xíng`/`háng` 중 어느 쪽으로 읽을지 우리가 지정할 수 있다(§4 비교표의 '병음 지정' 열).
- **목표**: 정답이 공개된 순간 표제어를 자연스러운 중국어 음성으로 들려준다. 단어 1개든 문장이든 **같은 경로**로 동작한다.
- **비목표**: 사용자 발음 녹음·평가, 속도/음색 사용자 설정 UI, 오디오 파일의 시트 저장, `generic` 프로필의 음성(영어 등 — 다국어 확장은 별건), 예문 자동 생성.

## 3. 노출·재생 정책 상세 (D3·D4)

- **모드1**(`design-prd` §4.2): 3D 플립(0.55s)이 **끝난 뒤** 자동 1회 재생. 뒷면의 병음 줄 옆에 스피커 버튼 — 병음이 빈칸이어도(B열 공백) 버튼은 뜬다(읽는 대상은 A열).
- **모드2 오답**(§4.3): 결과 화면 진입 시 자동 1회. 정답 표제어 옆 스피커 버튼.
- **모드2 정답**: 재생 **없음**. 정답은 결과 화면 없이 즉시 다음 문제로 넘어가므로(§4.5) 소리를 낼 지점이 없다 — 억지로 넣으면 다음 문제 위로 이전 문제 발음이 겹친다.
- **겹침 방지**: 새 재생 시작 전 이전 오디오를 반드시 정지한다. 연속 판정으로 카드가 빠르게 넘어가도 소리는 항상 1개만.
- **자동재생 차단 대비**: 모바일 브라우저는 사용자 제스처 없는 오디오를 막을 수 있다. 세션은 "학습 시작" 탭에서 출발하므로 대개 통과하지만, **실패해도 조용히 넘긴다** — 에러 토스트 없음, 스피커 버튼은 그대로 남아 수동 재생이 가능하다.
- **실패 정책**: 네트워크·API 실패는 **학습 진행을 막지 않는다**(기능 PRD §6.2의 기록 전송과 동일 태도). 재시도 큐(#18) 대상 **아님** — 발음은 유실돼도 재전송할 가치가 없다.
- **접근성**: 스피커 버튼은 `aria-label="발음 듣기"`, 아이콘은 인라인 SVG 자체 제작(아이콘 라이브러리 도입 없음 — `session-limit-and-home-utils.md` §8 관행).

**읽는 법 / 트레이드오프 요약**

- **중국어 자연스러움만 보면** MiniMax·Alibaba·BytePlus(중국 본토 계열)가 Azure보다 앞선다는 평가가 일반적이다 — 특히 **문장**에서 차이가 난다. 다만 셋 중 BytePlus는 **기업 인증 벽**이 있어 개인 계정으로는 진입이 어렵다.
- **Azure의 결정적 강점은 병음 지정**이다. 우리 시트는 B열에 병음을 이미 갖고 있으므로, 단어 1개를 읽힐 때 다음자 오독(行 xíng/háng, 长 cháng/zhǎng, 重 zhòng/chóng)을 **원천 차단**할 수 있다. 단어 학습 앱에서 이 값은 크다. 반면 문장 자연스러움은 중국 모델 대비 한 수 아래.
- 따라서 **단어 중심이면 Azure, 문장 비중이 커질수록 MiniMax/Alibaba**가 유리하다. D5(문장 전제)를 감안하면 이 선택이 이 문서의 핵심 갈림길이다.
- 비용은 **어느 쪽이든 실사용에선 무시할 만하다**: 단어는 2~4자, 하루 60문제라도 월 1만자 미만이라 Azure 무료 한도(50만자/월) 안에 들어간다. **문장을 도입하면 자릿수가 바뀌므로** 그때 캐시(§5.2)가 비용 방어선이 된다.
- 표의 가격·기능 중 "확인 필요" 표시는 이 세션에서 **1차 출처로 확정하지 못한 값**이다(중국 업체 문서 도메인 일부가 네트워크에서 차단됨). 제공자 확정 전에 실제 콘솔에서 재확인할 것.

**청취 비교를 권함**: 표의 "자연스러움"은 공개 자료·평판 기반이다. 최종 결정 전 같은 문장 3개(단어 1개 / 짧은 문장 / 다음자 포함 문장)를 후보 3곳의 데모에 넣어 직접 듣고 고르는 편이 확실하다.

## 5. 설계 스케치 (제공자 무관 공통 골격)

제공자가 바뀌어도 아래 골격은 유지된다 — **제공자별 차이는 Worker 안 어댑터 한 겹**에 가둔다.

### 5.1 `POST /api/tts` (신설)

- 요청 `{ "text": "经济", "pinyin": "jīngjì" }` — `pinyin`은 **선택**(있으면 SSML 음소 힌트로 사용, 제공자가 지원할 때만). 문장이면 `text`에 문장이 그대로 온다(**D5**).
- 응답 `audio/mpeg` 바이트. 인증·프로필 해석은 **기존 Bearer 미들웨어 그대로**(`worker/lib/auth.ts`).
- **길이 상한**: 문장 대비 `text` 최대 200자(초과 400). 과금·남용 방어선.
- API 키는 **Worker 시크릿**에 둔다 — 클라이언트에 절대 노출하지 않는다(`PROFILES`와 동일 취급, `wrangler secret put`).
- 브라우저에서 제공자를 직접 호출하지 않는 이유: 키 노출 + CORS + 과금 통제 불가. 시트 쓰기를 Worker로 일원화한 것과 같은 원칙(PRD §4).

### 5.2 캐시

- 같은 단어를 여러 세션에서 반복해 듣는 구조라 **캐시가 곧 비용·지연 절감**이다.
- 1차: Worker **Cache API** (키 = `제공자:음색:해시(text+pinyin)`), 응답에 `Cache-Control: public, max-age=...`.
- 문장 도입 후 적중률이 낮아지면 그때 KV/R2 승격을 검토한다 — **지금은 도입하지 않는다**(현 스택에 없는 바인딩을 미리 늘리지 않음).

### 5.3 클라이언트

- `src/lib/speak.ts` — `speak(text, pinyin?)` 1개 함수 + 진행 중 오디오 정지. `contentType === 'zh'` 분기는 **`contentLabels.ts`와 같은 자리**에 둔다(렌더링 분기 일원화, `design-prd` §4.6).
- `Mode1Card`(뒷면 진입 시)·`Mode2Card`(오답 결과 화면 진입 시)에서 각각 1회 자동 호출 + 스피커 버튼.
- 테스트: 순수 함수(분기·캐시 키)는 vitest(node), 버튼 렌더·자동재생 호출은 `src/test-utils.tsx`의 jsdom 렌더로 `Audio`를 스텁해 확인.

## 7. 열린 질문

- **Q1 (차단)** 제공자를 어디로 할 것인가? §4 기준 — **단어 정확도 우선이면 Azure**(병음 지정), **문장 자연스러움 우선이면 MiniMax 또는 Alibaba**. BytePlus는 기업 인증 벽으로 사실상 제외 권고.
- **Q2** 계정·키는 소유자가 직접 발급하는가? (Azure/MiniMax 모두 카드 등록 필요 — 키 발급 후 `wrangler secret put`으로 주입)
- **Q3** 음색을 무엇으로 고정할 것인가? (예: Azure `zh-CN-XiaoxiaoNeural` 여성 / `zh-CN-YunxiNeural` 남성) — 사용자 설정 UI는 비목표이므로 **하나를 골라 고정**한다.
- **Q4** 읽기 속도를 학습용으로 느리게 할 것인가? (예: 0.9배) 단어는 기본 속도, 문장은 느리게 — 로 나눌지.
- **Q5** 문장 도입 시점에 A열(표제어)이 곧 문장이 된다. 모드2(뜻→표제어 **입력**) 채점을 문장에도 그대로 적용할지는 **이 문서 범위 밖** — 별도 결정 필요.
