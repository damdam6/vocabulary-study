프로필 구성 파서 — worker/lib/profiles.ts 신규 (PROFILES 파싱·검증·폴백 합성)

damdam6/vocabulary-study 브랜치 feat/70-profile-config-parser ← main 라벨 enhancement 2026-07-26

1요약

범용화 PRD(docs/PRD-general.md §3)의 프로필 개념을 Worker에 들여오는 첫 조각으로, PROFILES 시크릿(JSON 배열)을 파싱·검증하고 isolate 수명 동안 캐시하는 순수 로직 모듈 worker/lib/profiles.ts를 신설한다. PROFILES 미설정 시에는 기존 APP_PASSWORD+SHEET_ID로 단일 폴백 프로필을 합성해 배포 순서 제약을 없앤다. 인증(resolveProfile)·라우트 배선은 후속 이슈(플랜 작업 1 후반부·작업 2) 소관이라, 이 이슈 단독 머지 시 관측 가능한 동작 변화는 없다.

2현황 분석

  • 프로필 개념이 아직 없다. 인증은 단일 APP_PASSWORD 전제(worker/lib/auth.ts:8)이고, 시트 접근은 전부 env.SHEET_ID 직접 참조다(worker/lib/sheets.ts). worker/index.ts:14가 isAuthorized 불리언으로 401만 가른다.
  • 따라갈 캐시 선례: worker/lib/auth.ts:6의 cachedPasswordDigest — 모듈 스코프 변수로 isolate 수명 캐시. 이 이슈의 파싱 결과 캐시도 같은 패턴을 쓴다.
  • 따라갈 검증 모듈 선례: worker/lib/register.ts — Sheets 호출 없는 순수 함수 + 같은 디렉토리의 register.test.ts(vitest, 한국어 테스트명). vitest.config.ts는 vite 플러그인과 분리된 빈 설정이라 워커 lib 단위 테스트가 그대로 돈다.
  • 타입 환경: worker-configuration.d.ts는 wrangler types 생성 파일이고 현재 Env에 PROFILES가 없다(시크릿 미설정 상태라 생성 안 됨). 생성 파일은 수정 대상이 아니다.
  • CI: PR에는 AI 리뷰 워크플로우(.github/workflows/ai-review.yml)만 붙는다. 테스트·린트(npm test=vitest run, npm run lint=oxlint)와 타입 체크(tsc -b, 빌드에 포함)는 로컬에서 보장해야 한다.

3설계

  • 모듈 외형 — worker/lib/profiles.ts 신규:
    • QuizMode("m1"|"m2") · ContentType("zh"|"generic") · Profile 타입 export.
    • ProfileConfigError extends Error — 설정 오류를 instanceof로 구분 가능하게 하는 전용 오류. 500 변환·console.error는 후속 인증 이슈에서 worker/index.ts가 담당.
    • parseProfiles(env) — 캐시 없는 순수 파싱·검증·폴백 합성 (테스트 표면).
    • getProfiles(env) — 모듈 스코프 캐시 래퍼 (후속 이슈에서 auth가 부를 진입점). 성공 결과만 캐시하고 오류는 매 호출 재검증(fail closed 유지).
  • env 타입 — 생성 파일에 PROFILES가 없으므로, 모듈 안에 필요한 조각만 담은 ProfilesEnv(PROFILES?/APP_PASSWORD?/SHEET_ID? 전부 optional string) 인터페이스를 선언한다. 실제 Env는 구조적으로 대입 가능하고, 시크릿 설정 후 wrangler types 재생성과도 충돌하지 않는다. 기각한 대안: worker-configuration.d.ts 수동 편집(생성 파일 오염) · as any 캐스트(격리 검증 원칙 훼손).
  • 검증 규칙 (PRD-general §3.1 표 그대로): 배열이 아니거나 빈 배열 거부 · id/name/password/sheetId 비어 있지 않은 문자열 · id·password 전 프로필 유일 · modes는 "m1"/"m2"의 비어 있지 않은 부분집합(중복 거부) · contentType 생략 시 "zh", 그 외 값 거부. 알 수 없는 여분 필드는 무시하고 알려진 필드만으로 새 객체를 구성한다(전방 호환).
  • 비밀번호 로그 금지 — 오류 메시지에 비밀번호 값·원문 JSON을 절대 싣지 않는다. 특히 V8의 JSON.parse SyntaxError 메시지는 소스 일부를 인용하므로(비밀번호 유출 경로) 원인 메시지를 버리고 고정 문구로 던진다. 중복 password 오류는 값 대신 해당 프로필의 id(비밀 아님, PRD §3.1)로 지목한다.
  • 폴백 합성 (PRD §3.2): env.PROFILES가 falsy면 APP_PASSWORD·SHEET_ID 둘 다 있을 때 { id: "default", name: "단어 암기", modes: ["m1","m2"], contentType: "zh" } + 두 값으로 단일 프로필 합성. 둘 중 하나라도 없으면 ProfileConfigError(어느 변수가 없는지 이름만 명시).

4작업 단계

  1. 모듈 신설 — 타입·ProfileConfigError·parseProfiles(파싱·검증·폴백 합성)·getProfiles(isolate 캐시). 모듈 헤더 주석은 PRD-general §3 참조, 기존 lib 스타일(한국어 주석) 준수. worker/lib/profiles.ts (신규)
  2. 단위 테스트 — 정상 2프로필(+contentType 기본값) · 오류 6종(JSON 깨짐·필드 누락/형식 위반·password 중복·id 중복·modes 빈 배열/중복/오값·contentType 오값) · 파싱 오류 메시지에 원문 비밀번호 미포함 · 폴백 합성 · 폴백 불가(둘 다 미설정, SHEET_ID만 누락) · 캐시(다른 env로 재호출해도 첫 결과 반환). worker/lib/profiles.test.ts (신규)
  3. 전체 검증 — npm test · npm run lint · npm run build(tsc -b 포함) 통과 확인. (테스트 192건·18파일 전부 통과, oxlint 0건, 빌드 성공 — 2026-07-26) (명령 실행)
  4. 플랜 체크오프 반영 후 저장소 스타일 커밋 → push → PR 생성 (Closes #70). docs/plans/issue-70-profile-config-parser.html

5리스크

리스크영향완화책
V8 JSON.parse 오류 메시지가 소스 스니펫을 인용후속 이슈의 console.error 경유로 비밀번호가 로그에 유출원인 메시지를 전파하지 않고 고정 문구로 throw + "메시지에 비밀번호 미포함" 테스트로 고정
모듈 스코프 캐시가 테스트 간 상태를 공유검증 케이스가 캐시에 가려져 헛통과검증 전 케이스는 순수 parseProfiles로 테스트, getProfiles는 전용 블록 1곳에서만 호출(vitest 파일별 모듈 격리)
생성 파일(worker-configuration.d.ts)에 PROFILES 부재타입 오류 또는 생성 파일 오염모듈 내 ProfilesEnv 조각 인터페이스로 해결, 생성 파일 불변
인증·라우트까지 손대는 범위 팽창후속 이슈와 충돌, 리뷰 비대이 이슈는 worker/lib/profiles.ts(+테스트)만 추가 — 기존 파일 수정 0, 관측 가능 동작 변화 0 유지

6테스트 계획

  • 정상 2프로필 구성 파싱 — 필드 보존, contentType 생략 프로필이 "zh"로 채워지는지.
  • 오류 각각 ProfileConfigError throw: JSON 깨짐 · 배열 아님/빈 배열 · 필드 누락(id/name/password/sheetId/modes) · 빈 문자열 필드 · password 중복 · id 중복 · modes 빈 배열/중복/범위 밖 값 · contentType 오값.
  • JSON 깨짐 오류 메시지에 원문(비밀번호 문자열)이 포함되지 않는지 명시 검증.
  • 폴백: PROFILES 미설정 + APP_PASSWORD/SHEET_ID 존재 → 명세 값 그대로의 단일 프로필. PROFILES·APP_PASSWORD 모두 미설정 → 오류. SHEET_ID만 누락 → 오류.
  • 캐시: getProfiles 첫 호출 후 다른 env로 재호출해도 첫 결과를 그대로 반환(재파싱 없음 증명).
  • 회귀: npm test 전체(기존 index/register/interval 등 포함) · npm run lint · npm run build.

7완료 조건

  • PROFILES 미설정 + APP_PASSWORD/SHEET_ID 존재 → 폴백 프로필 합성
