1요약

학습 범위를 전체 또는 고른 탭 n개로 제한하기 위한 순수 로직 모듈 src/lib/studyScope.ts를 추가한다. #187 PRD §3·§4.3 계약대로 StudyScope 타입, 탭 목록 도출, 다중 탭 필터, 프로필별 저장·복원·누락 탭 정리 함수를 구현하고 단위 테스트로 검증한다. UI(#189)는 이 이슈 범위 밖이며, computeHomeStats·buildSessionQueue의 시그니처와 산식은 그대로 둔다.

2현황 분석

  • src/screens/HomeScreen.tsx:48 홈 진입마다 fetchWords로 전체 단어를 조회하고, computeHomeStats(HomeScreen.tsx:56)와 handleStart의 buildSessionQueue(HomeScreen.tsx:94) 모두 그 전체 words 배열을 필터 없이 그대로 소비한다.
  • src/lib/api.ts:140 WordEntry가 tab 필드를 이미 담고 있고, /api/words는 시트 탭 순서대로 이어 붙여 반환한다(PRD-tab-scoped-study.md §3) — GET /api/tabs 없이도 words[].tab 등장 순서만으로 탭 목록을 만들 수 있다.
  • src/lib/sessionQueue.ts:86 buildSessionQueue<T extends WordProgress>는 제네릭이라 tab을 포함한 WordEntry를 그대로 받을 수 있다. src/lib/homeStats.ts:25 computeHomeStats는 WordProgress[]를 받는데 WordEntry가 구조적으로 이를 만족하므로, 필터링을 호출 이전 단계에서 끝내면 두 함수 모두 손댈 필요가 없다.
  • localStorage 키 규약은 vocab-study:* 접두(api.ts:9,25)를 따른다. 프로필별 분리 전례로 src/lib/retryQueue.ts:14가 있지만, 거긴 평면 배열에 profileId를 태그하는 로그 구조다 — 이 이슈는 프로필당 "가장 최근 선택" 하나만 필요해 다른 저장 형태가 맞다(§3 설계 참고).
  • 범위 개념 자체가 아직 코드에 없다 — 이 플랜이 처음 도입하는 순수 로직이며 회귀 기준선은 "기존 sessionQueue·homeStats 테스트가 무변경 통과"다.

3설계

  • StudyScope 타입은 이슈 본문·PRD §3 그대로: { kind: "all" } | { kind: "tabs"; tabs: string[] }.
  • deriveTabs(words): Set으로 word.tab 처음 등장 순서를 유지하며 중복 제거. 서버가 이미 시트 탭 순서로 이어 붙여 보내므로 별도 정렬이 필요 없다.
  • filterWordsByScope<T extends { tab: string }>(words, scope): kind === "all"이면 복사본을 그대로 반환, "tabs"면 Set 멤버십으로 필터(트림·대소문자 무시 없이 정확히 일치). tabs가 빈 배열이면 결과도 빈 배열이다. computeHomeStats·buildSessionQueue는 이 필터의 출력을 그대로 받으므로 시그니처를 바꾸지 않고도 #128 "같은 산식" 불변식을 지킨다 — 필터 함수 하나를 홈·큐 양쪽이 호출 전 단계에서 공유하는 방식.
  • 저장 형식: PRD §4.3 "세그먼트를 전체로 바꿔도 탭 선택은 따로 보존한다"를 만족하려면 kind만 저장해서는 안 된다. vocab-study:study-scope 키에 { [profileId]: { kind, tabs } } 맵으로 저장하되, tabs 필드는 kind와 무관하게 "마지막 탭 선택"을 항상 담는다 — kind === "all"로 저장해도 이전 tabs 값은 지우지 않고 보존한다. saveStudyScope는 kind === "tabs"이고 tabs.length === 0이면 저장을 건너뛴다(§4.3 "선택 0개 상태는 저장하지 않는다").
  • 복원: restoreStudyScope(profileId, availableTabs)가 저장값을 읽어 availableTabs에 없는 탭을 조용히 걸러내고, 걸러낸 뒤 tabs가 비면 kind를 "all"로 되돌린다(§4.3 "남은 탭이 없으면 전체로 되돌린다"). 정리 결과가 원래 저장값과 다르면(탭이 실제로 빠졌거나 kind가 바뀌었으면) 저장값도 갱신해 쓴다 — 변화가 없으면 불필요한 쓰기를 생략한다. 최상위 JSON이 손상됐거나 특정 프로필 엔트리의 타입이 어긋나면(예: kind가 열거값이 아니거나 tabs가 배열이 아님) 그 프로필만 { kind: "all" }로 취급하고 다른 프로필의 엔트리는 건드리지 않는다(프로필 간 격리).
  • 기각한 대안 — 평면 배열 + profileId 태그(retryQueue.ts 전례): 이 이슈는 프로필당 append 로그가 아니라 최신 값 하나만 필요해 로그 구조가 불필요한 복잡성을 더한다. 프로필을 키로 하는 맵이 더 단순하고 조회·갱신이 O(1)이다.
  • 기각한 대안 — kind별로 tabs 저장 위치를 분리(예: "all"일 때 키 자체를 지움): PRD가 저장 형식은 "구현에서 정하되 동작은 지켜야" 한다고 명시한다. kind와 무관하게 항상 tabs를 갖는 단일 레코드가 분기 없이 더 간단하고, "전체로 바꿨다 돌아왔을 때 탭 선택 보존" 요구를 자연스럽게 만족한다.

4작업 단계

  1. ✅ StudyScope 타입, 탭 목록 도출(deriveTabs), 다중 탭 필터(filterWordsByScope), 프로필별 저장(saveStudyScope)·복원 및 누락 탭 정리(restoreStudyScope), 저장 키 상수(STUDY_SCOPE_STORAGE_KEY)를 새 모듈로 작성한다. §3 설계를 그대로 구현한다. — 완료, 설계대로 구현. src/lib/studyScope.ts
  2. ✅ 단위 테스트를 작성한다: 탭 도출(순서·중복 제거·빈 입력), 필터(0개/1개/n개/전체, "전체"와 "모든 탭 선택"의 결과 차이), 저장·복원(손상된 JSON·타입이 어긋난 엔트리, 프로필 간 격리, 전체↔탭 선택 전환 시 탭 선택 보존, 선택 0개는 저장 안 함, 일부/전부 누락 탭 정리 후 재저장 확인). retryQueue.test.ts의 localStorage 스텁 패턴을 재사용한다. — 완료, 20개 테스트 모두 통과. src/lib/studyScope.test.ts, 참고: src/lib/retryQueue.test.ts
  3. ✅ npm test·npm run build·npm run lint를 실행하고, 기존 sessionQueue.test.ts·homeStats.test.ts가 무변경으로 통과하는지 확인한다. — 완료: 전체 1103개 테스트 통과(기존 스위트 무변경), 빌드·린트 통과. package.json
