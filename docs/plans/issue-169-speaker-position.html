Speaker Position 디자인을 학습 화면에 반영

damdam6/vocabulary-study 브랜치 feat/169-speaker-position ← feat/ch-sound 라벨 enhancement 2026-09-24

1요약

Claude Design의 Speaker Position.dc.html은 학습 화면 두 장면(모드1 뒷면, 모드2 오답 결과)에서 발음 버튼을 병음 바로 오른쪽에 붙이고, 병음은 카드 가운데에 그대로 두도록 바꾼다. 현재 앱은 모드1에서 버튼이 병음 옆 흐름 안에 44px 원 + 아래 안내 문구로 놓이고, 모드2 오답에서는 한자 옆에 붙는다. 버튼 위치·크기·스타일과 두 카드의 글자 크기만 디자인에 맞추고, 자동/수동 재생·채점·다음 문제 이동 로직은 건드리지 않는다.

2현황 분석

디자인 원본 (DesignSync로 가져와 확인함)

  • Speaker Position.dc.html: 420×800 화면 두 장. 01 한자→뜻: 카드 안 한자 52px/700 → 병음 24px(#7ea0f0) → 뜻 24px(margin-top:22px), 아래 X/O 80px 원. 02 뜻→한자 오답: "오답" 19px/700 → 한자 52px → 병음 20px → 뜻 20px, 아래 "다음" 버튼.
  • 두 장면 모두 발음 버튼은 position:relative; display:inline-flex인 병음 래퍼 안에 position:absolute; left:100%; top:50%; translateY(-50%); margin-left:10px로 놓인다. 30px 원, 테두리 #2f3542, 아이콘 색 #9aa1ad, 마우스를 올리면 배경 #222733·아이콘 #e8eaee. 버튼이 레이아웃 흐름 밖에 있으므로 병음은 정확히 가운데에 온다.
  • support.js: dc-runtime을 빌드한 파일(템플릿 파싱·컴파일·helmet·style-hover→:hover 클래스 변환 등)이다. 앱 동작 로직은 없으며, 여기서 가져올 건 style-hover가 hover 스타일이라는 점 하나뿐이다.
  • uploads/*.png 3장: 현재 앱 스크린샷. 모드1은 버튼이 병음 옆에 흐름대로 붙어 병음이 왼쪽으로 밀리고, 모드2 오답은 버튼이 한자 옆에 있다. 디자인이 고치려는 부분이 바로 이것이다.

3설계

  • 공용 병음+버튼 행: 모드1·모드2가 같은 마크업을 쓴다. .pinyin-speaker(position:relative; display:inline-flex) 안에 병음 span과 버튼 래퍼 .pinyin-speaker__button(position:absolute; left:100%; top:50%; transform:translateY(-50%); margin-left:10px)을 둔다. 병음이 없으면 버튼만 가운데에 흐름대로 놓는다(기존 "병음 없어도 버튼 유지" 동작 보존).
  • PronunciationButton 크기 옵션: size?: 'default' | 'compact' prop을 추가한다. compact는 보이는 원은 30px(테두리 #2f3542, 아이콘 색 #9aa1ad, hover 배경 #222733·아이콘 #e8eaee)이다. 아이콘은 디자인의 🔊︎ 글리프가 아니라 기존 SpeakerIcon SVG와 로딩 스피너를 그대로 쓰고, 30px 원에 맞게 크기만 18px로 줄인다이지만, ::before로 누를 수 있는 영역을 44px까지 넓혀 모바일 터치 목표를 지킨다. 재생 중·불러오는 중 색 표현은 그대로 유지한다.
  • 안내 문구 처리: compact에서는 __message가 레이아웃 높이를 차지하지 않는다. 불러오는 중·재생 중 문구는 화면에서 숨기고 스크린리더에만 읽힌다(aria-describedby 연결 유지). 오류 문구(snapshot.message, 입력 사유)는 버튼 아래에 absolute로 작게 띄워 사용자가 볼 수 있게 한다. 기본(default) 사용처는 동작이 바뀌지 않는다.
  • 모드2 오답 순서: 오답 → 한자 → [병음 + 버튼] → 뜻 → 내 답. 한자 행에서 버튼을 뺀다.
  • 글자 크기 맞춤: 디자인 수치로 조정한다. 모드1 뒷면 .mode-card-hanzi는 52px/700, 병음 24px, 뜻 24px + margin-top:22px(뒷면 범위로만). 모드2 결과 카드는 한자 52px/700, 병음 20px, 뜻 20px. 앞면·출제 화면·헤더·판정 버튼은 이미 디자인과 같으므로 바꾸지 않는다.
  • 좁은 화면 대비: 병음이 길면 absolute 버튼이 카드 밖으로 나갈 수 있다. 행 최대 너비를 calc(100% - 2 × (30px + 10px))로 좌우 대칭 제한해 병음은 줄바꿈되고 버튼은 카드 안에 남게 한다.
  • 포커스 이동(모드1 공개 후 .pronunciation-button__control, 모드2 오답 후 버튼 → 다음)은 클래스명을 유지하므로 코드 변경이 없다.

5리스크

리스크영향완화책
보이는 버튼 30px는 44px 터치 기준보다 작다중::before로 누를 수 있는 영역을 44px로 넓혀, 보이는 모습은 디자인대로 두고 터치 목표는 지킨다.
absolute 버튼이 긴 병음이나 좁은 폭에서 카드 밖으로 넘친다중행 max-width를 좌우 대칭으로 제한하고, 390px에서 긴 병음 샘플로 확인한다.
오류·상태 문구가 보이지 않아 사용자가 실패를 모름중오류 문구는 버튼 아래에 계속 표시하고, 진행 상태만 스크린리더 전용으로 둔다. 재생 중 색 표현은 유지한다.
글자 크기를 키워 긴 뜻이나 한자가 모드2 결과 스크롤에서 넘침하기존 .mode2-result-scroll과 overflow-wrap:anywhere는 유지한다. 모드1 앞면 적응 크기(hanziFontSize)는 건드리지 않는다.
포커스 대상 선택자가 바뀌어 접근성 흐름이 깨짐하.pronunciation-button__control과 pronunciationRef 대상 유지. 기존 포커스 테스트로 회귀를 확인한다.
