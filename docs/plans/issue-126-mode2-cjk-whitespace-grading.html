#126버그 수정

모드2 느슨 채점이 중국어 띄어쓰기를 오답 처리 — 공백을 '제거'가 아니라 '1개로 축약'해서

damdam6/vocabulary-study 브랜치 fix/126-mode2-cjk-whitespace-grading ← main 라벨 bug 2026-07-30

1요약

#123이 도입한 모드2 느슨 채점의 정규화가 공백을 제거하지 않고 연속 공백을 1개로 축약한다. 띄어쓰기가 없는 중국어·한국어 표제어에서는 입력에 공백이 하나라도 끼면 시트 표제어와 영원히 불일치해서 오답이 된다. src/lib/studySession.ts:31의 .replace(/\s+/g, " ")를 .replace(/\s+/g, "")로 바꿔 공백을 전부 제거한다 — 전각 공백(U+3000)까지 \s에 포함되므로 중문 IME 공백도 함께 해결되고, 앞뒤 공백도 같이 사라져 .trim()은 불필요해진다. 콘텐츠 타입 분기 없이 전 프로필 공통(PRD-general §4.2)을 유지하며, 대가로 영어 icecream이 ice cream의 정답이 되는 것은 수용한다.

2현황 분석

모드2 채점은 순수 모듈 한 곳에 모여 있고 화면은 그 결과만 쓴다 — 고칠 지점이 정확히 한 줄이다.

  • 정규화 헬퍼 src/lib/studySession.ts:30-32: value.normalize("NFC").toLowerCase().trim().replace(/\s+/g, " "). NFC 통일 → 소문자화 → 앞뒤 트림 → 내부 연속 공백을 1개로 축약. 마지막 단계가 이번 버그의 원인이다.
  • 채점 함수 src/lib/studySession.ts:41-47의 gradeMode2(input, hanzi): 입력과 A열 표제어 양쪽에 같은 정규화를 적용해 비교하고, answer로는 정규화 이전의 input.trim()을 돌려준다. 빈 입력 가드는 answer !== ""라 정규화 방식과 독립이다.
  • 유일한 호출부 src/screens/Mode2Card.tsx:29: const { correct, answer } = gradeMode2(value, word.hanzi). 오답이면 answer를 wrongAnswer 상태에 넣고 결과 화면의 "내 답"(src/screens/Mode2Card.tsx:47-50)에 그대로 표시한다 — 즉 표시 경로는 정규화와 분리돼 있어 이번 변경의 영향을 받지 않는다.
  • 기존 테스트 src/lib/studySession.test.ts:44-91: 정확 일치·앞뒤 공백 트림·빈 입력·병음·부분 일치·이체자·대소문자·연속 공백·NFC/NFD·"내 답" 표시까지 10개 케이스. 이 중 ice cream ↔ ice cream 케이스는 공백 전면 제거 후에도 그대로 통과한다(양쪽 다 icecream).
  • 문서 서술: docs/PRD.md:133(§5.2 채점 절차), docs/PRD-general.md:104(§4.2 콘텐츠 타입 무관 원칙), docs/PRD-general.md:202(Q6 결정 기록), docs/design-prd.md:109(§4.3 모드2 카드) 네 곳이 #123에서 "공백 정규화"·"내부 연속 공백 1개화"로 적혀 있다.

3원인 분석

근본 원인: src/lib/studySession.ts:31의 .replace(/\s+/g, " ")는 공백을 보존하는 정규화다. 이 규칙은 "양쪽 문자열이 같은 위치에 공백을 가진다"는 전제 위에서만 느슨하게 동작한다.

  • 중국어·한국어 표제어는 시트에 공백 없이(你好) 들어간다. 사용자가 你 好로 입력하면 정규화 후에도 你 好 ≠ 你好 — 공백 하나가 그대로 살아남아 불일치한다.
  • 앞뒤 공백만 .trim()이 처리하므로 你好 는 정답이 됐다. 그래서 #123이 "zh 동작 불변"이라 판단했지만, 실제로는 글자 사이 공백이 전혀 구제되지 않는 상태였다 — 개선이 없었을 뿐 문제가 없던 게 아니다.
  • 전각 공백 U+3000(중문 IME 기본 스페이스)도 \s에 매칭돼 반각 " "로 치환될 뿐 제거되지 않아 같은 이유로 오답이었다.

채택 설계: .replace(/\s+/g, "") — 모든 공백류(반각·전각·탭·개행)를 전면 제거. 앞뒤 공백까지 함께 사라지므로 선행 .trim()은 중복이 되어 제거한다(answer용 트림은 gradeMode2에 별도로 남아 있으므로 "내 답" 표시에는 영향 없음). 콘텐츠 타입 분기를 두지 않아 PRD-general §4.2의 "모드2 채점은 콘텐츠 타입 무관 공통" 원칙을 유지한다.

기각한 대안 (이슈 본문에 기록됨):

  • CJK 인접 공백만 제거 — \p{Script=Han}·\p{Script=Hangul} 룩어라운드로 좁히면 영어 ice cream vs icecream 구분은 지킨다. 그러나 정규식이 복잡하고 혼합 스크립트(中国 people) 엣지 케이스가 새로 생긴다. 영어 공백 엄격성이 실제로 필요해지면 그때 좁힌다.
  • 콘텐츠 타입별 분기(zh만 공백 제거) — §4.2의 콘텐츠 타입 무관 원칙을 깨고, 같은 generic 시트에 한국어 표제어가 들어오는 경우를 못 구제한다.

4작업 단계

  1. normalizeForGrading의 공백 처리를 전면 제거로 교체 — .trim().replace(/\s+/g, " ") → .replace(/\s+/g, ""). 중복이 된 .trim()을 걷어내고, 헬퍼 JSDoc(29행)과 gradeMode2 JSDoc(34-40행)의 "공백 정규화"·"zh 판정 불변" 서술을 "공백 제거"·"#126"으로 정정한다. src/lib/studySession.ts
  2. 회귀 테스트 추가 — 중국어 글자 사이 공백(你 好, 不 好 意 思), 전각 공백(你　好, U+3000), 한국어 띄어쓰기(사과 나무), 그리고 표제어 쪽에 공백이 있는 역방향 케이스. 기존 케이스(대소문자·연속 공백·NFC/NFD·빈 입력·병음·부분 일치·이체자·"내 답")는 그대로 두고 ice cream 케이스의 설명만 새 규칙에 맞게 조정한다. src/lib/studySession.test.ts 결과: 4개 it 블록 신규 추가(한자 사이 공백 / 전각 공백 / 한국어 띄어쓰기 / 양쪽 대칭), 연속 공백 케이스 제목을 "공백 제거 후 판정(#123·#126)"으로 조정. studySession.test.ts 27개 통과.
  3. PRD 채점 서술 정정 — #123에서 "공백 정규화 / 내부 연속 공백 1개화"로 적힌 네 지점을 "공백 제거"로 바꾸고, zh가 실제로 혜택을 받게 된 점과 영어 트레이드오프를 개정 주석(#126)으로 남긴다. docs/PRD.md, docs/PRD-general.md, docs/design-prd.md 결과: PRD.md §5.2 · PRD-general.md §4.2·Q6 · design-prd.md §4.3 네 지점 개정 완료.
  4. 전체 검증 — npm test(vitest run) · npm run lint(oxlint) · npm run build(tsc -b + vite build) 그린 확인. package.json 결과: 테스트 32파일 426개 통과(exit 0) · 린트 무경고 · 빌드 성공. 계획에 없던 선행 조치 — jsdom이 package.json에 선언돼 있는데 로컬 node_modules에 설치돼 있지 않아 .tsx 테스트 3개가 워커 기동에 실패했다(#126과 무관한 환경 설치 누락). 레포 루트에서 npm install로 복구했고, 부수적으로 재작성된 package-lock.json은 원상복구해 커밋에 포함하지 않았다.

5리스크

리스크영향완화책
영어 표제어의 공백 구분이 사라진다 (icecream → ice cream 정답) 낮음 — 모드2는 단어를 아는지를 검증하지 띄어쓰기 표기를 검증하지 않는다. 이슈 본문에서 수용 가능한 트레이드오프로 명시 결정됨. 필요해지면 기각안(CJK 인접 공백만 제거)으로 좁힌다 — 원인 분석에 근거를 남겨둔다.
여러 단어 표제어가 한 덩어리로 붙어 다른 표제어와 충돌 매우 낮음 — 정규화는 비교 시점에만 쓰이고 저장·조회 키에는 관여하지 않는다. 같은 문제의 정답 하나와만 비교하므로 표제어 간 충돌 경로가 없다. gradeMode2가 단일 hanzi와만 비교한다는 점을 테스트로 이미 고정.
공백만 입력(" ")이 빈 문자열로 정규화돼 표제어와 오매칭 없음 — gradeMode2의 answer !== "" 가드가 정규화보다 먼저 걸러낸다. 기존 "빈 입력·공백만 입력은 오답" 테스트를 그대로 유지해 회귀를 막는다.
