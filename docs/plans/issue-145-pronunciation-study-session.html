3설계

1. 홈 응답을 세션 시작 값으로 고정

WordsResponse.tts: TtsCapability를 필수 정규화 결과로 추가하고 raw의 tts?: unknown을 검증한다. enabled가 정확한 true이며 revision이 서버 계약의 ^[A-Za-z0-9_-]{1,64}$, maxTextLength가 공통 TTS_MAX_TEXT_LENGTH(200)일 때만 켠다. 누락·null·배열·원시값·잘못된 enabled/revision/상한은 {enabled:false}로 만든다. 응답 나머지 필드는 기존대로 처리한다.

Home의 onStart(queue, context)에서 context는 {profile: PublicProfile, tts: TtsCapability}다. 성공 응답의 profile·tts를 함께 보관하고 ready이며 profile이 있는 경우에만 시작한다. context 타입은 HomeScreen에서 export해 App이 재사용할 수 있다. App은 큐와 context를 하나의 세션 state로 저장하고 Study에 queue, profile, tts를 전달한다. Study의 contentType은 profile.contentType에서 얻는다. 별도 TTS localStorage·재조회·캐시 변경은 추가하지 않는다. 기존 등록 화면의 저장 프로필 사용은 이번 경계 밖이다.

2. hook이 Study의 React 수명에 controller를 연결

신규 src/hooks/usePronunciation.ts은 {profileId, contentType, capability, questionId, input}을 받고 {pronunciation: PronunciationBinding | undefined, stop}을 반환한다. Study는 mount마다 고유 세션 ID를 만들고 질문 ID를 세션 ID + ':' + session.pos로 구성한다. 순수 ID는 useState initializer에 보관할 수 있지만 controller·Audio·cache를 render/useMemo/useState initializer에서 만들지 않는다. word 참조·뜻·기록 응답 갱신으로 질문이나 controller를 교체하지 않는다.

가벼운 layout effect setup에서 createPronunciationController에 fetchTtsAudio, createTtsAudioOutput(), createTtsBlobCache()를 조합한다. 한 controller가 이 자원을 소유하며 cleanup에서 구독 해제·stop('exit')·dispose·ref 초기화를 수행한다. layout cleanup은 로그인 전환 등 언마운트에서 정지를 늦추지 않기 위한 선택이다. 생성·구독 effect의 의존성은 세션의 profile ID·지원 여부·capability 원시값으로 한정하여 snapshot·feedback·pos 변화로 재생성하지 않는다.

별도의 질문 활성화 effect는 같은 controller와 questionId를 사용하고 A열 word.hanzi, B열 word.pinyin을 전달한다. activate 자체는 요청하지 않는다. 구독을 먼저 연결하고 activate/getSnapshot 결과를 반영한다. 현재 인스턴스의 snapshot.questionId가 현재 질문과 일치할 때만 binding을 제공하여, 새 카드 effect가 활성화 전 이전 질문에 reveal을 보내는 유실을 막는다. 생성 초기·전환 중의 빈 binding은 정상이다.

binding callback은 생성 당시 controller와 질문 ID에 묶고 현재 인스턴스/질문인지 검사한다. 오래된 callback이 새 controller ref를 따라가거나 질문을 다시 activate해서는 안 된다. prepare/reveal/replay는 controller의 동기 명령을 그대로 잇고 replay 앞에 await·timer를 두지 않는다. snapshot 변경이 prepare/reveal/replay 함수 identity를 불필요하게 바꾸지 않게 한다. 초기/실행 중 hidden이면 요청 명령을 막고 controller에 hidden 정지를 적용한다.

supportsPronunciation(contentType)은 zh만 true다. capability와 함께 검사하여 generic/off는 controller 생성·요청과 binding이 없다. controller가 503 disabled/not_configured 뒤 snapshot.enabled=false를 알리면 binding을 제거하며, 같은 세션에서 새 controller를 만들어 다시 켜지 않는다. 텍스트 오류로 inputReason이 설정된 경우에는 binding을 유지해 후속 카드가 비활성 안내를 표시할 수 있게 한다.

StrictMode의 첫 setup은 cleanup으로 폐기되고 두 번째 setup은 새 controller·구독을 만든다. disposed 객체가 남은 ref를 생성 가드로 삼지 않는다. React의 추가 setup/cleanup은 공식 StrictMode 문서, commit 수명 및 정리 시점은 useLayoutEffect 문서를 참고했다. 카드 공개의 취소 가능한 예약은 #148 소유이며 이 hook에서 자동 공개를 생성하지 않는다.

4. 카드 인계 계약과 소유 범위

두 카드 props에 pronunciation?: PronunciationBinding import·선언만 추가하고 Study에서 전달한다. 카드의 함수 인자에 미사용 binding을 억지로 구조 분해하지 않는다. 버튼 import/렌더, prepare/reveal 호출, 모드2 오답 공개 예약, focus·플립·CSS는 #147/#148에 맡긴다. 따라서 #145 단독 완료에서는 실제 카드 음성 요청이 아직 발생하지 않는 것이 정상이다.

state machine·입력 검증·자동재생 기회·Blob/revision·요청 취소의 내부 정책은 기존 controller를 재사용한다. 새 의존성, Worker·설정·생성 타입·studySession/sessionQueue/기록 알고리즘 수정은 필요하지 않다. 관련 테스트용 controller 더블은 subscribe 통지·dispose 후 거부·현재 질문/stop semantics를 재현하는 전용 fixture로 한정한다.
