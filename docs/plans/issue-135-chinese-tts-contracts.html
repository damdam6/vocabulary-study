3설계

1. 런타임 경계와 공통 계약

Worker의 types.ts를 서버 계약의 소유점으로, src/lib/ttsTypes.ts를 브라우저 공개 계약·포트의 소유점으로 둔다. 외부로 전달되는 요청·오류 코드·헤더·capability·공통 제한만 미러하며, 교차 호환 검사는 Worker 쪽 전용 테스트에서 수행한다. 브라우저 런타임 import가 Worker로 이어지거나 tsconfig 범위를 넓히지 않는다.

계약구체적인 형태와 책임
요청·정규화 결과TtsRequest = { text: string; pinyin?: string }. 내부 검증 결과는 { text: string; pinyin: string | null }로 고정해 빈 B열을 null로 통일한다. 원본 객체를 그대로 넘기지 않고 허용 필드만 새로 구성한다.
합성·발음SynthesisInput = { text: string }; PronunciationDecision은 absent 또는 ignored/provider_hint_unsupported이며 effectiveHint는 항상 null. TtsProvider.pronunciationMode는 none, synthesize(input, signal)은 Promise<{ audio: Uint8Array; contentType: "audio/mpeg"; billedCharacters?: number }>를 반환한다. 과금 문자 수는 선택적 실제 값이고 추정 기본값을 만들지 않는다.
MP3 검사 주입ValidateAudio = (audio: Uint8Array, contentType: string) => boolean 형태의 순수 동기 포트를 export한다. true는 MIME·비어 있지 않은 완성 MP3·4MiB 제한 통과를 뜻한다. 실제 검사는 #137, R2에서 사용은 #136, 서비스 주입은 #139다. 더블을 실제 검증기로 취급하지 않는다.
설정 / 환경TtsEnv는 TTS_ENABLED/PROVIDER/MODEL/VOICE/RATE/REVISION과 DASHSCOPE_API_KEY를 optional string, TTS_AUDIO를 optional R2Bucket으로 둔다. TtsWorkerEnv = Env & TtsEnv 별칭만 소유 types.ts에 정의한다. 생성 Env·index.ts는 이번 이슈에서 수정하지 않는다.
공개 capabilityTtsCapability = { enabled: false } | { enabled: true; revision: string; maxTextLength: 200 }. 비활성 사유·시크릿·버킷·설정 전체는 공개 capability에 넣지 않는다. 누락/잘못된 구 서버 필드의 false 처리는 #145에서 구현한다.
응답 진단{ source: "STORED"; storage: "PRESENT" } | { source: "GENERATED"; storage: "SAVED" | "UNCONFIRMED" }와 pronunciation/revision을 조합한다. 불가능한 STORED/SAVED 등의 조합을 타입으로 막는다. 내부 ignored reason과 effectiveHint를 HTTP 헤더 값에 섞지 않는다.
제한 상수text 200 코드 포인트, pinyin 1,000 코드 포인트, 요청 16×1024 bytes, MP3 4×1024² bytes, provider JSON 64×1024/전체 1024² bytes. R2 조회/저장 2,000ms, 합성 12,000ms, 클라이언트 준비 20,000ms, Blob LRU 20개/8×1024² bytes. 각 런타임에서 필요한 상수만 노출하며 교차 값은 계약 테스트로 일치시킨다. 타이머 구현은 포함하지 않는다.

2. 입력을 제한하며 읽고 검증

input.ts는 readTtsRequest(request)와 normalizeTtsInput(raw: unknown)의 두 경계로 나눈다. 전자는 본문 스트림의 실제 바이트를 합산하고 상한 통과 후 JSON을 해석한다. 후자는 순수 입력 검증을 소유한다. Content-Type·메서드·인증·HTTP 응답 생성은 #140이 담당하고 이 helper는 Response를 만들지 않는다.

  1. Content-Length는 조기 거부의 보조 자료일 뿐이다. 누락·작게 위조한 헤더에서도 읽은 바이트가 16KiB를 넘으면 tts_request_too_large다. 초과 chunk를 누적 복사하기 전에 확인하고 reader를 취소·해제한다. 정상·오류 경로 모두 lock을 해제하며 UTF-8 다중바이트가 chunk 경계에 나뉘어도 원문을 보존한다. 무제한 request.json()/text() 선호출은 하지 않는다.
  2. JSON 객체만 허용한다. null·배열·primitive·깨진 JSON·text 누락/비문자열·pinyin의 null/숫자/배열/객체와 text/pinyin 이외 키를 거부한다. JSON.parse 오류의 원문 메시지는 폐기하고 고정된 오류를 반환한다.
  3. A열은 CRLF/CR→LF, NFC, trim을 적용한다. 금지 C0는 trim으로 사라지기 전에 검사하여 VT/FF 등이 끝에 있어도 조용히 허용되지 않게 한다. 탭·LF와 정규화 전 CR만 허용하고 NUL 및 나머지 C0를 거부한다. 정규화 후 Array.from(text).length가 1~200이고 \p{Script=Han}이 하나 이상이어야 한다. 문장부호·숫자·라틴문자·내부 공백을 유지하며 자르거나 나누지 않는다.
  4. B열은 NFC·trim 후 최대 1,000 코드 포인트다. 생략/빈칸은 null, 나머지 문자열은 그대로 보존한다. 의미·음절·성조·A열과의 대응을 검사하지 않는다. A열의 Han/길이 규칙을 B열에 적용하지 않는다. B열 줄바꿈은 명세 §5.1의 NFC·trim 계약을 유지한다.
  5. pronunciation.ts는 정규화된 B열만으로 absent/ignored를 결정한다. 합성 입력은 명시적으로 { text: normalized.text }를 구성하는 계약으로 분리한다. normalized.pinyin은 후속 저장 키 입력에 남기며 이번에는 키 계산을 구현하지 않는다.

3. 설정 검증과 기능 격리

resolveTtsConfig(env: TtsEnv)는 예외 대신 판별 가능한 결과를 반환한다: 비활성(tts_disabled), 잘못된/누락 설정(tts_not_configured), 준비됨(검증된 config와 서버 전용 의존성). TTS_ENABLED 생략 또는 문자열 false는 비활성이고 true만 활성 요청으로 해석한다. 그 밖의 flag 값은 미설정 오류다. PROFILES·Google 설정을 읽거나 기존 파서 캐시를 변경하지 않는다.

  • 기본값은 문서 §9의 qwen / qwen-audio-3.0-tts-flash / longanfengyue / rate 1.0 / revision tts-v1이다. 해당 선택 var가 생략되면 기본값을 쓰고, 명시된 빈 문자열·잘못된 값은 기본값으로 숨기지 않는다. 키와 R2는 기본값이 없으며 활성 요청에서 둘 다 필요하다.
  • provider·model·voice는 현재 확정값 allowlist만 허용한다. rate는 빈 문자열·부분 숫자·NaN·Infinity를 거부하고 완전한 십진수로 파싱한 유한 [0.5, 2.0]만 허용한다. revision은 ^[A-Za-z0-9_-]{1,64}$로 제한한다.
  • region=intl, outputFormat=mp3, adapterVersion=qwen-ws-v1, 발음 정책 pinyin-none-v1과 고정 endpoint를 코드 상수로 둔다. audioSettings는 [24000, 128, 50, 1.0, 0, ["zh"], false, null]의 readonly 튜플로 정의한다(sampleRate/bitRate/volume/pitch/seed/languageHints/enableSsml/instruction). 설정·튜플·기본값을 요청 간 변이시키지 않는다.
  • 국제 주소 wss://dashscope-intl.aliyuncs.com/api-ws/v1/inference와 후속 Worker Upgrade용 같은 주소의 https 형태만 계약에 둔다. 다른 모델·음색·지역·SSML·hot_fix·자동 재시도는 추가하지 않는다.
  • API 키는 비어 있지 않은 값인지, R2는 필요한 get/put binding 형태가 있는지만 검사한다. 네트워크 접근 가능성을 확인하지 않는다. 키·R2는 해시용 TtsConfig와 분리한 서버 전용 결과로 돌려주고 capability·오류·로그·fixture에는 실제 값을 넣지 않는다. 운영 TTS_ENABLED=false와 실제 바인딩은 그대로 유지한다.

4. HTTP와 클라이언트 포트

공개 오류 body는 { error: TtsErrorCode; message: string }이며 안정적인 한국어 문구를 사용한다. 오류/상태 매핑과 헤더 이름을 중앙 정의하되 라우트 응답·오류 처리기는 후속 소유자가 연결한다.

상태계약
400 / 403 / 405 / 413 / 415invalid_tts_request / tts_not_allowed / method_not_allowed / tts_request_too_large / unsupported_media_type. 405는 후속 라우트에서 Allow: POST.
503tts_disabled, tts_not_configured, tts_unavailable, tts_storage_unavailable. 앞의 둘은 세션 기능 비활성, R2 조회 오류는 합성 시작 금지라는 의미를 문서화한다.
502 / 504tts_upstream_error / tts_timeout. 제공자 401/403은 앱 401로 노출하지 않고 tts_unavailable로 정규화한다.
기존 401 / 500앱 401 빈 body와 기존 프로필 구성 오류 500 계약은 유지한다. 일반 내부 500은 공개 정보만 반환하는 후속 라우트 책임이며 제공자 원문을 노출하지 않는다.
성공 헤더Content-Type: audio/mpeg, Cache-Control: private, no-store, X-Content-Type-Options: nosniff, X-TTS-Source, X-TTS-Storage, X-TTS-Pronunciation(absent/ignored), X-TTS-Revision. 실패도 private, no-store.

아래 이름은 구현 시 export할 계약 이름이다. 필요한 필드는 타입과 주석으로 확정하며 네트워크·DOM·React·LRU 알고리즘을 이 파일에 넣지 않는다.

src/lib/ttsTypes.ts 계약포트 형태 / 의미

후속 연결만 규정: R2 첫 요청 생성·비공개 지속 보관, 조회 오류 때 재합성 금지, 저장만 실패하면 GENERATED/UNCONFIRMED로 생성 음성 반환을 유지한다. 원격 리소스·저장 키·MP3 파서·WebSocket·service·플레이어는 이 계획의 구현 대상이 아니다.

5리스크

리스크영향완화책
공개 계약의 양쪽 타입 드리프트후속 이슈가 다른 오류·capability를 해석Worker 전용 계약 테스트에서 중립 src 계약과 호환 검사. src→worker import와 생성 Env 편집 금지.
Unicode·바이트 길이 혼동확장 한자를 2자로 세거나 다중바이트 본문이 한도를 우회NFC 후 코드 포인트 길이와 UTF-8 실제 바이트를 별개 검사. chunk 분할·위조 Content-Length 테스트.
trim이 금지 C0를 제거끝의 VT/FF가 조용히 허용text 제어문자를 trim 이전에 검사하고 CR만 LF로 정규화. 양 끝·중간 금지 문자 테스트.
설정 오류가 기존 인증을 막음로그인·words·학습 전체 장애ProfilesEnv/PROFILES 파서와 독립된 결과 union 사용. 기존 프로필 오류 500 회귀 확인.
키·제공자 오류 원문의 유출응답·로그·저장 메타데이터로 민감 정보 전파실제 시크릿 파일 미접근. 고정 오류 메시지, 비밀 없는 TtsConfig와 서버 전용 의존성 분리. 테스트용 sentinel 누출 검사.
후속 실행 코드의 선행 구현소유 파일 충돌·다른 이슈 완료를 잘못 주장포트·상수·입력/설정/병음만 구현. #136~#151의 런타임·인프라·UI 파일 수정 금지.
설정 유효성을 실제 가용성으로 오인키 발급·R2 더블 통과를 운영 성공으로 기록capability는 설정상 준비만 뜻함. 실제 버킷 정보는 #149, 모델 접근·청취·모바일은 출시 검증에 남김. TTS_ENABLED=false 유지.

6테스트 계획

  • 입력 경계: 빈 문자열·공백·0/1/200/201 코드 포인트, Han 없음, 확장 한자 U+20000 포함, 문장부호/숫자/라틴문자 혼합. 200자 허용·201자 거부와 NFC 조합형/분해형의 동일 결과를 검사한다.

  • JSON/바디: 잘못된 JSON·null·배열·primitive·필드 누락·pinyin 비문자열·알 수 없는 provider/profileId/SSML 키 거부. 16KiB 정확히 허용(유효 JSON의 공백 padding), 16KiB+1 거부. Content-Length 누락/작은 거짓값/과대값, 여러 chunk와 단일 과대 chunk, UTF-8 문자 중간 분할, reader 오류·초과 시 cancel/lock 해제를 검사한다.
