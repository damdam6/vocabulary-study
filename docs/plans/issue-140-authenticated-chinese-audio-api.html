3설계

1. 요청 경계와 우선순위

/api/tts 경로 전체를 기존 인증 블록 안에서 dispatch한다. 순서는 PROFILES 확인·앱 인증 → POST 여부 → 인증 프로필의 zh 여부 → resolveTtsConfig → Content-Type → readTtsRequest → 서비스 호출이다. 다른 메서드를 404로 흘리지 않고 인증 뒤 405와 Allow: POST를 반환한다. Content-Type은 매개변수를 제거하고 대소문자를 정규화해 application/json만 허용하며 charset=utf-8은 허용한다.

서비스·provider 생성은 모든 사전 검증 뒤에 둔다. 요청의 profileId/contentType/sheetId/provider/URL 등은 기존 입력 allowlist가 거부한다. 서비스에는 인증에서 얻은 { id, sheetId }만 넘기며 비밀번호는 전달하지 않는다. 정상 요청도 Sheets 조회·등록 상태 확인을 추가하지 않는다.

2. 조합과 수명

새 worker/routes/tts.ts의 handler가 TtsWorkerEnv와 인증 Profile, ExecutionContext를 받는다. ready 설정으로 createQwenTtsProvider와 createR2TtsAudioService를 요청별 생성하고 request.signal을 그대로 넘긴다. 최소 TtsAudioBinding과 storage의 구체 버킷 타입 연결은 이 조합 지점 한 곳에서만 좁힌다. 생성 Env·공통 타입의 소유 경계를 확장하지 않는다.

registerBackgroundTask: (promise) => ctx.waitUntil(promise)로 연결해 this 바인딩을 보존한다. 원래 put이 늦게 끝나도 서비스가 등록한 observation Promise를 회수하며, 라우트는 HTTP 반환 전에 그 Promise를 추가 await하지 않는다. 취소는 request.signal.aborted를 우선 확인해 signal.reason을 재전파한다. 종료된 요청의 abort를 일반 500이나 provider 장애로 기록하지 않는다. 서비스의 합성 deadline은 그대로 504로 직렬화한다.

3. HTTP 응답

결과응답
성공200 + 정확한 audio 바이트 구간 + audio/mpeg + nosniff. Uint8Array의 byteOffset/byteLength를 보존해 backing buffer의 다른 바이트가 섞이지 않게 한다.
세 진단 조합STORED/PRESENT · GENERATED/SAVED · GENERATED/UNCONFIRMED. X-TTS-Pronunciation은 absent/ignored, X-TTS-Revision은 서비스 결과. 저장 객체 metadata/URL/key를 헤더로 복사하지 않는다.
사전 검증 오류400 invalid_tts_request · 403 tts_not_allowed · 405 method_not_allowed · 413 tts_request_too_large · 415 unsupported_media_type · 503 tts_disabled/tts_not_configured.
서비스 오류TtsServiceError.code를 공통 TTS_ERROR_RESPONSES로 직렬화: 503 tts_unavailable/tts_storage_unavailable · 502 tts_upstream_error · 504 tts_timeout. provider 인증/할당량/429는 앱 401로 전달하지 않는다.
앱 인증·구성 오류기존 빈 401 본문과 WWW-Authenticate/X-Worker-Version, PROFILES의 기존 500 JSON을 유지한다. index의 해당 응답에는 pathname이 /api/tts일 때만 no-store를 추가한다.
예상 못 한 내부 오류HTTP 500, 공개 본문은 기존 tts_unavailable 코드·고정 한국어 문구를 재사용한다. 이 상태 예외를 라우트 테스트와 아키텍처 §3.2에 명시하며 새 오류 코드를 발명하지 않는다. 임의 error.code/status/message를 그대로 반환하지 않는다.

모든 /api/tts HTTP 응답에 Cache-Control: private, no-store를 적용한다. 성공 전용 X-TTS 헤더는 실패 응답에 붙이지 않는다. 응답은 필드를 명시해 만들고 config/dependencies/profile/서비스 결과 전체를 JSON으로 펼치지 않는다.

4. capability와 로그

words 응답 최상위에 tts: { enabled: false }를 기본값으로 둔다. 인증 프로필이 zh이고 resolveTtsConfig가 ready일 때만 { enabled: true, revision, maxTextLength: 200 }을 만든다. 설정 resolver만 재사용하고 R2/provider 네트워크나 service를 호출하지 않는다. words의 fetchedAt/profile/words/settings와 기존 조회 횟수, health/PROFILES 스키마를 보존한다.

라우트가 생성한 requestId를 서비스의 createRequestId에 주입해 foreground 결과와 늦은 저장 로그를 연결한다. 로그는 명시한 allowlist 객체로 작성한다: requestId, profileId, provider/model/revision, 정규화 문자 수, 실제 billedCharacters(존재할 때), hint 상태/사유, source/storage, 응답 byteLength, 정규화 오류 코드. 서비스가 제공하는 저장 outcome/elapsedMs만 사용하며 노출되지 않은 단계별 시간을 추정하지 않는다. 원문 예외·본문·병음·시트 ID·키·객체 키·제공자 원문은 기록하지 않는다.

5. 소유 경계와 인계

변경은 routes/tts·index·routes/words·test-utils 및 해당 테스트, 이 계획과 HTTP 계약 보충 문서에 한정한다. service/storage/provider 정책, 프론트, Wrangler/생성 Env, graph는 변경하지 않는다. 계획 완료 뒤 root가 Terra high 구현 surface를 시작한다. 이 탭의 모델은 Astra high 계획 담당이며 구현·커밋·push를 수행하지 않는다. 이후 독립 리뷰와 GitHub squash merge 대상은 feat/ch-sound다.

6테스트 계획

  • HTTP 차단 행렬. 인증 없음/잘못된 토큰 → 빈 401; 인증된 GET/PUT/OPTIONS → 405+Allow; generic POST → 403; disabled/미설정 → 각각 503; media 누락/text/plain → 415; application/json;charset=utf-8 허용. 우선순위가 겹치는 요청도 인증→메서드→zh→설정 순서를 확인한다. spy로 서비스 생성·R2·provider·Sheets 0회를 확인한다.
  • 본문 경계. 배열/null/잘못된 JSON/알 수 없는 필드/위조 profileId·URL·설정 → 400; 0/1/200/201 Unicode 코드 포인트, 확장 한자·문장·NFC·CRLF, 빈/과대 병음; Content-Length 없음/거짓 값에도 실제 스트림 16KiB 경계와 초과 → 413. 상세 정규화는 기존 input.test를 재사용한다.
  • 응답과 오류. 세 성공 조합 × absent/ignored, exact MP3 바이트·MIME·nosniff·revision·no-store, Uint8Array subarray 사례. 공통 오류 코드 11개 모두 status/message와 일치하며 앱 401/PROFILES 500/내부 500도 확인한다. 내부 500은 명시한 tts_unavailable 본문을 사용한다. provider 인증 오류는 503으로 앱 토큰을 만료시키지 않는다. TTS 실패는 성공 헤더/객체 URL/key를 포함하지 않는다.
  • 실제 서비스 연결. 실제 service/storage/MP3 검사 + R2 더블에서 hit는 같은 바이트·provider 0회, miss→생성/저장은 SAVED, put 실패 또는 2초 초과는 200 UNCONFIRMED. 늦게 resolve/reject한 put의 등록 Promise를 drain해 미처리 rejection 없음과 같은 requestId를 확인한다. R2 get 오류/손상은 503·provider 0회. 모든 TTS 요청에서 Sheets 0회.
  • 취소와 deadline. 이미 취소한 요청은 부작용 없음. 진행 중 request.signal 취소가 실제 service를 통해 adapter handshake signal/socket 종료에 전달되고 원래 reason이 보존된다. 저장 시작 후 취소해도 등록한 put observation은 회수된다. 서비스의 12초 timeout→HTTP 504 대표 사례를 fake timer로 확인하고 r1의 동기 검사 deadline/abort 회귀 테스트를 함께 실행한다.
  • 격리와 로그. 고정된 두 zh 프로필의 같은 입력은 서로 다른 R2 key를 사용하고 각각의 바이트만 반환한다. generic 차단, body로 프로필 변경 불가. 응답·로그에서 password/apiKey/text/pinyin/sheetId/provider 원문 sentinel·객체 키가 나오지 않는다. 관측 필드는 allowlist로 제한한다.
  • capability·회귀. zh ready→true/revision/200, missing/false/잘못된 flag·키 없음·R2 없음·잘못된 모델/음색/속도/revision→false, generic+ready도 false. 기존 fetchedAt/profile/settings/words와 Sheets 호출 수·대상 유지. health·PROFILES 오류·answer/review-fail/register/settings 기존 테스트를 모두 통과한다. src/lib/api.test.ts·ttsApi.test.ts·wordsApi.test.ts로 소비자 계약 회귀를 확인한다.
