1요약

#128이 학습 중 정렬을 D+E 오름차순으로 뒤집었지만, 동률 구간의 타이브레이커가 여전히 시트 상 순서다. 실데이터(zh 프로필)는 학습 중 145개 중 126개가 0점 동률이라 실제 선정은 전적으로 타이브레이커가 결정하고, 시트가 append-only라 최근 등록분은 항상 꼬리에 있어 큐 진입이 0/10이다. 수정은 한 줄이다 — 학습 중 후보 배열에 이미 있는 Fisher–Yates shuffle을 먼저 걸고 그 다음 stable 오름차순 정렬을 하면, 점수 축 우선순위는 그대로 두고 동률 구간만 정확히 무작위가 된다. 비교 함수에서 난수를 반환하는 방식은 균등 분포가 아니므로 쓰지 않고, rng 주입 경로를 유지해 테스트에서 시드를 고정한다.

3원인 분석

근본 원인

Array.prototype.toSorted는 명세상 stable이다. 따라서 sessionQueue.ts:105의 비교 함수가 0을 돌려주는 구간(= D+E가 같은 단어들)은 입력 배열 순서가 그대로 보존된다. 입력 순서 = 시트 행 순서 = 등록 순서(시트는 append-only)이므로, 같은 점수 안에서는 오래된 단어가 항상 이긴다.

#128은 "점수 있는 단어 vs 0점 단어" 축만 해소했다. 그런데 실데이터에서 신규 단어의 진짜 경쟁 상대는 같은 0점인 오래된 미학습 단어 125개였다. 0점 풀(126)이 학습 슬롯(35)보다 크기 때문에 점수 정렬은 아무것도 가르지 못하고 선정이 100% 타이브레이커로 결정된다 — 그래서 오름차순 반전 후에도 시트 마지막 10행의 큐 진입이 0/10이었다.

이 방향성은 테스트에도 그대로 박제돼 있다 — sessionQueue.test.ts:104-116 ("총 정답 수가 동률이면 시트 상 순서를 따른다")와 sessionQueue.test.ts:265-268 ("신0·신34는 포함, 신35는 제외")가 현재 동작을 의도된 계약으로 못박고 있다. 두 테스트는 이번 개정에서 반드시 다시 써야 한다.

채택 설계 — 먼저 섞고, 그 다음 stable 정렬

// 현재 (sessionQueue.ts:104-107)
const learningQuestions = learning
  .toSorted((a, b) => a.m1 + a.m2 - (b.m1 + b.m2))
  .slice(0, slots.learning)
  .map(...);

// 개정
shuffle(learning, rng);              // ← 동률 구간의 타이브레이커를 무작위로 (#131)
const learningQuestions = learning
  .toSorted((a, b) => a.m1 + a.m2 - (b.m1 + b.m2))   // stable → 동점끼리는 셔플 순서 유지
  .slice(0, slots.learning)
  .map(...);
  • 점수 축은 완전 불변 — 비교 함수를 건드리지 않으므로 낮은 점수가 높은 점수를 이기는 우선순위는 그대로다. 셔플은 오직 비교 함수가 0을 돌려주는 구간에만 영향을 준다.
  • 제자리 셔플이 안전한 이유 — learning은 :84에서 함수 안에 새로 만든 지역 배열이다. 입력 words는 readonly T[]이고 원소 참조만 담기므로 호출자 배열이 재배열되지 않는다.
  • 넣는 위치 — 복습 문제 생성(:98-101) 다음, 학습 정렬 바로 앞. 학습 슬롯 계산(:95)은 개수만 쓰므로 순서와 무관하다.

배제한 대안

  • 비교 함수에 난수 (toSorted((a,b) => rng() - 0.5)) — 균등 분포가 아니고, 비교의 일관성 (transitivity)을 깨서 엔진의 정렬 구현에 따라 결과가 달라진다. 이슈에서 명시적으로 금지.
  • slice 이후 셔플 — 이미 선정이 끝난 뒤라 출제 순서만 바뀐다. :110의 기존 전체 셔플이 정확히 그것이고, 이 버그를 못 고친다. 무작위성은 반드시 컷 이전에 들어가야 한다.
  • 등록 타임스탬프 역순 정렬 — 최근 등록을 앞으로 당기지만 오래된 미학습 단어가 대신 영구히 굶는다. (소유자 결정: 어느 쪽도 편들지 않는 무작위.)
  • 신규 단어 전용 쿼터 — "신규"의 경계를 새로 정의해야 하고 PRD에 개념이 하나 늘어난다. 126개 동률 풀에서는 무작위만으로 충분하다(35/126 ≈ 27.8%/세션, 기대 재등장 ~3.6세션).

부수 효과 하나 — rng 스트림

새 셔플이 learningMode·최종 shuffle보다 먼저 rng를 소비하므로, 시드를 고정한 기존 테스트의 하류 난수 값이 밀린다. 다만 실제로 영향받는 건 특정 시드 결과에 의존하는 단언뿐이다 — () => 0 같은 상수 rng 테스트와 후보가 1개 이하인 테스트는 무영향이다(길이 ≤ 1 배열에서는 Fisher–Yates 루프가 한 번도 안 돌아 난수를 뽑지 않는다). 깨질 것으로 예상되는 건 위에서 지목한 2개다.

5리스크

리스크영향완화책
새 셔플이 rng를 먼저 소비해 시드 고정 테스트의 하류 난수가 밀린다 기존 테스트가 예기치 않게 깨질 수 있다 상수 rng(() => 0)·단일 후보 테스트는 구조적으로 무영향(길이 ≤ 1이면 난수를 안 뽑는다). 깨질 것으로 지목한 2개는 단계 4·5에서 의도적으로 개정한다. 전체 npm test로 나머지를 확인.
세션마다 0점 조합이 바뀌어 같은 단어를 연속으로 못 볼 수 있다 단어별 학습 연속성이 낮아진다 소유자 명시 결정(2026-07-30). 35/126 ≈ 27.8%/세션이라 기대 재등장 간격 ~3.6세션이고, 정답을 맞힌 단어는 점수가 올라 자연히 뒤 그룹으로 빠진다. 코드 대응 없음.
복습 대기 동률(같은 복습일)은 여전히 시트 순서다 같은 날짜 복습이 복습 몫을 넘으면 시트 뒤쪽 단어가 밀린다 — 같은 종류의 편향 이슈가 compareNextReview를 손대지 말라고 명시했으므로 이번 범위 밖. 실사용에서 문제가 확인되면 후속 이슈로 분리한다.

8실데이터 검증 결과

zh 프로필 시트를 서비스 계정으로 직접 읽어(탭 HSK6급·HSK유의어·새탭테스트, 단어 150 / 0점 126 / 상한 35), 같은 데이터에 시드 200회를 돌려 시트 마지막 10행의 큐 진입을 측정했다. 수정 전/후는 shuffle(learning, rng) 한 줄의 유무만 다르다.

세션당 평균 진입진입률200회 중 한 번이라도 진입
수정 전0.00 / 100.0%0 / 10
수정 후2.26 / 1022.6%8 / 10

진입하지 않은 2개는 버그가 아니라 설계대로다 — 꼬리 10행을 개별 확인한 결과:

  • 容易 (m1=3, m2=1) — 학습 중이지만 D+E=4라 0점 126개에 밀린다. 0점 풀이 학습 슬롯보다 큰 동안 점수 있는 단어는 안 들어오는 게 #128의 계약이다.
  • 简单 (m1=3, m2=3, 복습일 2026-07-31) — 복습 예약(복습일 미도래)이라 큐에서 제외(§5.1).

즉 출제 자격이 있는 꼬리 단어 8개는 8개 전부 진입한다. 자격 있는 8개 기준 세션당 진입률은 2.26 ÷ 8 ≈ 28.3%로, 이론값 35/126 ≈ 27.8%와 일치한다 — 신규 단어가 오래된 미학습 단어와 정확히 같은 확률로 경쟁하고 있다는 뜻이다.
