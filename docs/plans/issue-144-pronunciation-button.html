1요약

PronunciationButton을 새 표시 전용 컴포넌트와 전용 CSS로 추가한다. #135가 확정한 PronunciationSnapshot과 replay()만 입력으로 받아 준비·재생·로딩·자동 실패/차단·수동 오류·입력 불가를 일관되게 표시한다. 상태 전이, API·Audio 호출, 세션 전달과 카드 배치는 후속 이슈가 계속 소유하며, 이번 변경은 실제 TTS 호출·설정 변경·배포를 하지 않는다.

2현황 분석

  • src/lib/ttsTypes.ts:67-77는 UI가 소비할 여섯 상태(idle/loading/ready/playing/blocked/error), 사용 가능 여부, 입력 불가 사유와 수동 안내 문구를 이미 정의한다. message는 수동 오류·수동 차단에만 노출 가능한 값이고, src/lib/ttsTypes.ts:103-106은 버튼 props를 snapshot과 replay()로 고정한다.
  • docs/PRD-chinese-tts-audio.md:89-104는 로딩의 aria-busy, 자동 실패·자동 차단의 무음 복귀, 수동 실패·수동 차단의 서로 다른 안내 문구, 200자 초과/읽을 수 없는 입력의 비활성 사유를 구분한다. 자동 여부를 추측하는 별도 플래그는 없으므로 이 컴포넌트는 message === null인 실패 상태를 조용히 표시한다.
  • docs/architecture/chinese-tts-audio.md:315-326는 controller와 Audio·cache의 상태 머신을 TTS-07~09에, capability·카드 연결을 TTS-11에 배정한다. 같은 문서는 PronunciationButton.tsx/.css를 전달된 상태와 callback만 쓰는 TTS-10의 경계로 명시한다.
  • src/components/HomeUtilBar.tsx:12-69는 인라인 SVG에 aria-hidden="true"와 focusable="false"를 적용하는 현재 관례다. src/components/HomeUtilBar.test.tsx:1-61와 src/test-utils.tsx:18-49는 jsdom에서 React 19 act 기반으로 DOM·클릭을 검증하는 재사용 가능한 방식이다.

3설계

상태 표시와 상호작용의 단일 경계

새 컴포넌트는 props 계약을 재정의하지 않는다. idle·ready·blocked/error + message:null은 일반 스피커를, playing은 강조 변형을, loading은 같은 고정 영역의 로딩 표시와 aria-busy="true"를 렌더한다. 로딩 중 클릭도 한 번의 전달된 replay() 호출로만 위임하여 요청 합치기는 controller의 책임으로 남긴다.

inputReason가 있거나 소비 불가능한 snapshot은 native disabled와 버튼 밖의 연결된 설명으로 나타낸다. text_too_long과 invalid_text는 PRD의 한국어 사유를 사용한다. capability가 꺼져 카드에서 버튼 자체를 생략할지 여부는 TTS-11의 선택적 binding 책임이므로, 이 공용 컴포넌트는 전달받은 비활성 snapshot을 안전하게 렌더할 수만 있게 한다.

message가 있는 경우에만 버튼 근처의 고정 메시지 영역을 aria-live="polite"로 사용한다. 따라서 자동 재생 차단·자동 요청 실패에는 토스트·live announcement·새 오류 문구를 만들지 않는다. SVG는 장식으로 숨기고, 활성 버튼의 기본 이름은 발음 듣기로 유지한다.

제외한 선택지

  • 컴포넌트 내부 fetch, Audio, 상태 관리: snapshot/controller와 중복 상태 머신이 되어 TTS-07~09 경계를 침범하므로 제외한다.
  • src/index.css 또는 Mode1/Mode2 카드 직접 수정: 병렬 이슈의 소유 파일과 충돌하고 현재 Mode1의 중첩 button 문제를 해결할 수 없으므로 TTS-11~14로 남긴다.
  • 자동 실패에도 공통 오류 문구를 생성: 수동 오류만 알린다는 PRD UX와 맞지 않으므로 controller가 제공한 message만 표시한다.

5리스크

리스크영향완화책
자동 실패와 수동 실패를 UI가 혼동자동 재생에 불필요한 토스트·스크린리더 알림이 생김상태명만으로 원인을 추론하지 않고 message가 있는 수동 사례만 live message로 렌더하는 계약 테스트를 둔다.
버튼을 로딩 중 disabled 처리controller의 요청 병합·수동 의도 처리를 막거나 UX가 계약과 달라짐loading은 busy 시각 상태로만 표현하고 replay 전달·중복 억제는 controller 소유로 유지한다.
현재 Mode1의 큰 button 안에 즉시 삽입중첩 interactive element로 키보드·접근성 오류 발생이슈 #144는 독립 컴포넌트만 추가하고 구조 분리는 TTS-12, 연결은 TTS-11·13에서 한다.
상태 메시지의 출현/소멸로 카드가 흔들림모바일·확대 화면에서 판정/다음 버튼 공간이 밀림전용 CSS에 메시지 영역의 최소 높이를 두고 390px·200% 확대는 후속 실제 화면 통합 검증에도 남긴다.

6테스트 계획

  • npm test -- src/components/PronunciationButton.test.tsx: jsdom에서 6개 상태와 enabled/inputReason/message 조합을 렌더하고, 20px SVG가 접근성 트리에서 제외되며 활성 제어의 이름이 발음 듣기인지 확인한다.
  • 같은 테스트에서 loading은 aria-busy="true"이고, 자동 blocked/error의 message:null에는 live region이 없으며, 수동 message만 aria-live="polite"로 노출되는지 검증한다.
  • host form 안에서 click 및 button의 기본 키보드 활성화 경로를 검증해 replay가 정확히 한 번 호출되고 form submit 또는 카드 판정 callback을 호출하지 않음을 확인한다. inputReason/enabled 비활성 상태에서는 replay가 호출되지 않고 설명이 aria-describedby로 연결되는지도 확인한다.
  • npm test, npm run lint, npm run build: 공용 타입 소비와 CSS import가 전체 TypeScript/Vite 경로에서 회귀하지 않는지 확인한다.
  • 실제 서비스·player 없이 실행하는 단위 테스트 범위를 명시한다. 실제 브라우저 자동재생 차단, 모바일 터치/청취, R2와 유료 제공자 호출은 이 이슈의 검증으로 주장하지 않고 TTS-16 및 출시 검증에 남긴다.
