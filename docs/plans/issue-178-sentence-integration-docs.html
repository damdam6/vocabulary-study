1요약

#174와 #177이 병합된 현재 HEAD에는 중국어 문장 등록 형식·등록 경고·문장 채점·긴 화면·TTS 원문 전달이 각각 구현·검증되어 있다. 그러나 추출 킷 JSON이 등록 화면을 거쳐 Worker가 mock Sheets에 저장한 동일한 A열 원문이 GET /api/words, 모드1/2 세션, 정답·복습 기록까지 이어지는 대표 종단 증거는 흩어져 있다. 이번 작업은 기존 계약을 재구현하거나 시트 열을 추가하지 않고, 공유 fixture를 이용한 mock 통합 회귀와 제품 문서 정합성을 완성한다. 생산 코드보다 통합 테스트·문서·시리즈 추적 산출물이 중심이며, 실제 Sheets·유료 Qwen·모바일 실기기는 미검증으로 분리한다.

2현황 분석

  • 공유 fixture는 tests/fixtures/chinese-sentence-registration.json:1에서 단어·문장부호 문장·문장부호 없는 장문·숫자/영문 혼합·다음자/변조 병음·200/201자·병음 1000/1001·불허 문자·중복·기존 장문·generic을 한 파일에 정의한다. Python 킷은 docs/registration-kit/schema_check.py:46에서 같은 계약을 미러링하고, 클라이언트는 src/lib/registerValidation.ts:91의 JSON 파싱과 :128의 행 분류, Worker는 worker/lib/register.ts:18의 재검증을 각각 수행한다.
  • 등록 화면은 형식 오류·중복·병음 검토 경고를 구분한다(src/lib/registerValidation.ts:146). 전송 경계는 src/lib/registerApi.ts:75의 POST /api/words/register이며 blocked만 제외하고 warning/duplicate는 Worker에 전달한다. Worker는 worker/routes/register.ts:42에서 프로필별 재검증, :73에서 A열 중복 재탐색, :80에서 A:C append-only 저장을 한다.
  • 저장된 값은 worker/routes/words.ts:28에서 탭별 A2:F를 읽고 worker/lib/words.ts:29가 원문·병음·뜻·진도 객체로 보존한다. 등록 제한을 기존 시트 조회에 재적용하지 않는 회귀는 worker/routes/words.test.ts:189에 이미 있다.
  • 학습 화면은 src/screens/StudyScreen.tsx:66의 현재 질문과 :73의 원문 question.word.hanzi를 TTS에 사용하며, :79의 answer effect와 :93의 review-fail effect가 원래 tab + hanzi를 전송한다. 모드2는 src/screens/Mode2Card.tsx:69에서 gradeMode2(value, word.hanzi, contentType)를 호출하고, 정답 원문은 :114 결과에 보존한다.
  • Worker 기록은 worker/routes/answer.ts:64에서 매번 탭+A열 원문으로 행을 재탐색하고, :74에서 카운트·F열·G열 타임스탬프를 묶어 쓴다. 복습 오답은 worker/routes/review-fail.ts:44에서 같은 키로 찾아 F열만 갱신한다. 따라서 채점 정규화 결과가 기록 키로 흘러가면 다른 행 갱신 또는 0건이 될 수 있다.
  • #177의 기존 TTS 통합은 원문 transport와 200/201 경계, 자동/수동 재생, 실패/off/자동재생 차단을 확인한다(src/screens/StudyScreen.tts.integration.test.tsx:153). 독립 리뷰가 확인한 것처럼 취소·늦은 응답 테스트는 짧은 표제어 fixture 기반 기존 controller 테스트(src/lib/speak.test.ts:238)다. 문장 fixture까지 확장했다고 서술하지 않고, 텍스트 내용과 무관한 기존 경계 회귀를 그대로 재사용한다.

3설계

  • 대표 원문: 我今天很忙。와 我有2本书。를 등록→조회→학습에 사용한다. mode2 입력은 문장부호를 생략해 정답 처리하되, UI 요청·Worker 행 탐색·answer/review-fail payload·TTS text에는 저장된 A열 원문을 그대로 사용한다.
  • 검증 경계: 통합 테스트는 실제 Google Sheets를 호출하지 않고 기존 route 테스트의 메모리 상태 double과 fetch 가로채기를 재사용한다. 등록 PUT 결과로 A:C 원문을 저장하고, 별도 GET 응답을 학습 큐로 공급한 뒤, answer/review-fail mock write에서 정확한 행과 기록 열을 검증한다.
  • 경고 정책: semantic mismatch·다음자·변조 병음은 format PASS/비차단 warning으로 남기고 제출 가능함을 검증한다. 불허 문자·길이 초과·빈 값·배치/탭 중복은 차단 또는 skip으로 구분한다. 서버와 Python 킷은 발음 정확성을 보장한다고 표현하지 않는다.
  • generic 경계: generic 등록/채점은 문장 문장부호 완화나 zh 병음 정책을 받지 않는다. 최소 한 개의 generic fixture를 client/Worker/학습 회귀에 남겨 contentType 분기가 거꾸로 새지 않는지 확인한다.
  • 문서 원본: 새 중국어 문장 PRD와 SENT-01~06 시리즈 문서는 현재 main에만 있는 미추적 파일이므로 이 worktree에 복사해 최종 PR에 포함한다. 상세 계약은 docs/PRD-chinese-sentence-study.md에 두고, 기존 PRD·디자인·등록·채점·TTS 문서는 중복 규칙을 새 문서로 연결하거나 구 규칙을 개정한다.

5리스크

리스크영향완화책
정규화된 답안을 저장·TTS·기록 키로 재사용문장부호 원문이 사라지거나 다른 A열 행을 갱신한다.등록 A:C, GET words, TTS text, answer/review-fail hanzi를 각각 원문 문자열로 단언하고 grade 비교 결과와 분리한다.
mock이 등록→조회→학습의 서로 다른 fixture를 사용각 테스트는 통과하지만 실제 원문 연결이 끊긴다.한 registration JSON row를 memory Sheets state에 저장하고 같은 응답을 WordEntry로 변환해 StudyScreen에 주입한다.
warning·duplicate·blocked 집계가 실제 전송 대상과 어긋남경고를 불필요하게 차단하거나 차단 행을 서버로 보낸다.RegisterScreen payload와 Worker write 호출을 함께 단언하고 직접 수정 후 재분류를 포함한다.
기존 문서가 새 PRD와 충돌하거나 과거 계획이 잘못된 테스트를 주장후속 구현·리뷰가 잘못된 완료 근거를 읽는다.문서별 stale 문구를 grep하고 canonical PRD 링크로 단일화한다. #177 취소 검증은 기존 짧은 테스트 재사용으로 정확히 기술하며 #176의 공개 버튼 문구와 일치시킨다.
실제 환경 성공으로 mock 결과를 과대 해석운영 Sheets/TTS/모바일 품질이 검증된 것으로 오인한다.mock 성공, headless viewport/IME 에뮬레이션, 실제 Sheets·유료 Qwen·R2·물리 모바일 청취를 결과에서 별도 분류한다.
