1요약

기존 Qwen 프로토콜 처리기를 Workers Upgrade fetch와 연결하는 TtsProvider를 구현했다. 한 합성에 연결·UUID task를 하나씩 만들고, 유효한 task-finished와 완성 MP3가 확인될 때만 성공한다. 호출자의 AbortSignal을 연결 대기부터 완료까지 관측하고 늦은 Upgrade·오류·취소에서도 한 번만 종료하며 자원을 해제한다. 구현은 gpt-5.6-terra / high 탭에서 완료했고, 독립 리뷰·머지는 별도 탭이 맡는다.

3설계

1. provider 생성과 최소 주입 경계

qwen.ts에 createQwenTtsProvider(config, apiKey, options?)를 export하고 TtsProvider를 반환한다. options는 테스트 가능한 Upgrade fetch와 UUID 생성 함수만 선택적으로 받는다. 기본 fetch는 함수 호출 시 global fetch를 감싸며 import 시 네트워크 작업을 하지 않는다. UUID 기본값은 crypto.randomUUID()다. socket·task·processor는 synthesize 호출마다 생성하며 전역 상태나 연결 풀을 두지 않는다. API 키는 closure에만 보유하고 pronunciationMode: "none"을 제공한다. 최소 UpgradeResponse / socket 포트는 실제 Workers Response/WebSocket과 구조적으로 호환되게 같은 파일에서 정의한다. 생성 Env와 공통 타입은 수정하지 않는다.

2. handshake와 전송·수신

signal.aborted를 먼저 검사한 뒤 abort handler를 등록하고 다시 검사한다. 고정 TTS_UPGRADE_ENDPOINT에 GET, Upgrade: websocket, Authorization: Bearer …, redirect: "manual", 전달받은 signal로 fetch를 정확히 한 번 호출한다. 모든 3xx를 거부해 Bearer가 다른 호스트로 전달되지 않게 한다. status 101과 webSocket 모두 필요하다. 비정상 응답 본문은 읽지 않고, body가 있으면 cancel의 실패까지 관측하며 기다리지 않는다.

socket 소유권을 기록하고 binaryType = "arraybuffer" 설정 → message/close/error listener 등록 → accept → run-task 순서로 진행한다. 각 외부 호출 뒤 terminal 여부를 확인해 동기 예외나 재진입 취소 이후 추가 전송을 막는다. run-task의 시작 상태는 send 이전에 설정한다. string은 그대로, ArrayBuffer는 복사 없는 Uint8Array view로 processor.push에 전달한다. arraybuffer 설정 아래 다른 payload 타입은 안전한 upstream 오류로 종료한다. async Blob 변환을 추가하지 않는다.

processor의 첫 정상 pending에서 입력 전송 여부를 먼저 표시한 뒤 continueTask와 finishTask를 순서대로 각 한 번 보낸다. 이 연결은 qwenProtocol.ts:75-106의 시작 전 검사에 의존한다. adapter에서 JSON.parse·task ID 확인·MP3 검사·과금 추정을 다시 구현하지 않는다. 이후 pending은 대기, failed는 정규화 오류, completed는 status를 제외한 audio/contentType/billedCharacters만 반환한다. task-finished 전 정상 code 1000 close도 end()를 통해 실패한다.

3. 한 번만 종료하는 자원 소유

단일 terminal gate를 모든 성공·실패·abort 경로가 공유한다. gate를 먼저 닫은 뒤 abort handler와 등록된 socket listeners를 해제한다. 실패/취소 시 processor.end()로 부분 chunk를 폐기하고 processor·직렬화 메시지·socket 참조를 해제한다. 성공 바이트는 결과에만 남긴다. socket.close는 고정된 비밀 없는 code/reason 또는 기본값으로 수행하며 close 오류가 원래 결과를 바꾸지 않게 한다. listener 등록·binaryType 설정·accept·각 send·fetch의 동기 throw와 비동기 reject도 이 경로로 수렴한다.

abort는 pending handshake가 끝날 때까지 기다리지 않고 즉시 signal.reason 자체로 reject한다. 이미 완료된 결과를 뒤집지 않는다. 열린 task가 있으면 serializer의 cancelTask를 best effort로 한 번 시도하되 실패나 응답을 기다리지 않는다. 12초 timer와 504 변환은 #139 서비스가 소유하므로 여기서는 새 timeout, AbortSignal.timeout, 자동 재연결을 만들지 않는다. 호출자는 원래 reason 객체를 통해 timeout과 일반 취소를 구분할 수 있다.

늦은 Upgrade: 외부 Promise를 race에서 버리지 않는다. fetch의 양쪽 후속 처리를 계속 관측하여 terminal 이후 response에 socket이 생기면 정상 task를 시작하지 않고 닫는다. 아직 accept하지 않은 Upgrade socket은 정리용 accept가 필요한 런타임 상태를 고려해 accept 후 close한다. 정리용 accept 중에도 task listener·runTask·continueTask는 생성하지 않는다. 이미 닫힌 소켓과 accept/close 실패는 방어적으로 처리한다. 늦은 fetch rejection도 처리해 unhandled rejection을 남기지 않는다.

4. 오류 계약과 후속 소비자

qwen.ts에 QwenTtsError를 export하고 code: "tts_unavailable" | "tts_upstream_error"만 안정적으로 제공한다. 메시지는 code 또는 공통 안전 문구, status는 기존 TTS_ERROR_RESPONSES에서 유도한다. handshake 401/403/429는 503 계열, 5xx·3xx·101 socket 누락·그 밖의 비정상 handshake·socket/프로토콜/전송 실패는 502 계열이다. task-failed는 processor의 code를 그대로 사용한다. 원본 provider/fetch/socket 예외를 cause·message·로그·close reason에 복사하지 않는다. 신뢰된 호출부의 AbortSignal reason 보존은 별도 내부 계약이고, #139/140이 HTTP 공개 오류를 정규화한다.

소유 범위: qwen.ts와 그 테스트·전용 fixture만 구현한다. 기존 qwenProtocol.ts/audio.ts/types.ts/config.ts는 소비한다. R2·라우트·서비스·프론트·Wrangler·환경 활성화는 후속 이슈 소유다. 프로토콜 API를 변경하는 대안은 현재 첫 pending 불변식으로 요구를 충족하므로 선택하지 않는다.

5리스크

리스크영향완화책
취소 뒤 Upgradesettle만 끝내고 fetch를 버리면 연결이 남는다.늦은 socket의 accept/close와 늦은 rejection 관측을 별도로 테스트한다.
Blob 기본 수신비동기 변환이 완료 이벤트보다 늦어질 수 있다.accept 전 arraybuffer 고정과 호출 순서를 더블에서 검증한다.
첫 pending 계약처리기 확장으로 의미가 달라지면 입력이 일찍 전송될 수 있다.시작 전 모든 대표 불법 입력에서 continue 0회, 유효 시작에서 1회인 연결 테스트를 고정한다.
정리 재진입·예외close/error/abort가 추가 전송이나 중복 정리를 유발할 수 있다.terminal을 먼저 표시하고 각 send 이후 상태를 재확인한다. cleanup 예외는 원래 결과를 보존한다.
부분 오디오·오류 유출잘못된 바이트 저장 또는 제공자 원문 공개로 이어질 수 있다.processor completed만 반환하며 safe code만 예외에 담는다. error/close/body sentinel 검증.
더블과 실환경 차이실제 모델 접근·합성 취소·음질·과금을 증명하지 못한다.실제 키·청취·모바일·R2·지연은 미검증으로 명시하고 출시 확인 전 TTS_ENABLED=false 유지.

6테스트 계획

  • 정상 경로: 한 fetch·UUID·run, listener와 arraybuffer가 accept 이전에 설정됨, start 이전 continue/finish 0회, start 이후 각각 1회. sentence-synthesis/binary 교차·frame 중간 분할 후 task-finished에서 동일 MP3와 선택적 usage를 반환한다. 완료 직후 close/error/abort는 결과를 바꾸지 않는다.
  • handshake 표: 401/403/429 → tts_unavailable/503; 500/502/503, 301/302/307/308, 200, 101+socket 없음 → tts_upstream_error/502. redirect manual·고정 URL·Bearer/Upgrade·동일 signal, 재요청 0회. 비정상 response가 socket도 가진 더블은 socket 정리까지 확인한다.
  • 프로토콜 연결: 잘못된 JSON·task ID·중복 started·시작 전 result/binary·지원하지 않는 데이터 타입·과대 JSON/오디오·손상 MP3·빈 완료·task-failed 분류·정상 1000 조기 close·완료 누락을 검증한다. parser 상세 조합은 기존 qwenProtocol/audio 테스트를 재사용하며 adapter의 송신·종료·자원 해제를 함께 assert한다.
  • 취소 지점: 사전 취소는 fetch/UUID/task 0회. 연결 중 취소는 fetch가 무시해도 즉시 reason 그대로 reject. 이후 늦은 101 socket은 task 전송 0회·정리 완료, 늦은 reject는 미처리 예외 0개. accept 직전/직후, run 중, started 대기, continue/finish 중, binary 수신 중, task-finished 직전 취소를 제어한다. task-finished→abort는 성공 유지, abort→task-finished는 취소 유지.
  • deadline 경계: 테스트 호출자가 controller를 abort(new DOMException(..., "TimeoutError"))하여 동일 reason 객체 보존과 즉시 정리를 확인한다. idle handshake/start/finish 대기를 모두 종료한다. provider가 자체 12초 timer를 만들지 않는 것은 정적 검토로 확인하며 서비스 예산 자체는 #139의 테스트다.
  • 예외·누수: fetch 동기 throw/reject, binaryType 설정·listener 등록·accept·run/continue/finish send 실패, cancel send·close throw, cleanup의 동기 close/error 재진입을 검증한다. terminal 후 listener와 abort handler가 0이고 추가 송신/재합성이 없으며, 성공/실패/취소 outcome 관측은 1회다. provider를 재사용하는 동시 호출 2개는 task ID와 socket이 분리되고 한쪽 abort가 다른 쪽에 영향이 없다.
  • 민감정보: 가짜 apiKey·원문·추가 병음 sentinel·provider error_message·fetch/close 원문을 사용한다. 반환 오류의 own fields/message/cause 및 console 호출에 포함되지 않는다. 헤더의 가짜 키와 continueTask의 원문은 허용된 전송 위치이며 pinyin은 전송되지 않는다. 실키·환경 파일을 읽지 않는다.
  • 구현 후 명령: npm test -- worker/lib/tts/providers/qwen.test.ts worker/lib/tts/providers/qwenProtocol.test.ts worker/lib/tts/audio.test.ts → npm test → npm run lint → npm run build. 실패는 수정 후 재검증하며 성공으로 기록하지 않는다.
  • 계획 단계 검증: 이슈/댓글·선행 MERGED·base 조상·적용 지침·파일 및 타입 계약·공식 런타임 문서 확인. HTML placeholder/섹션/링크·로컬 HTTP 내용·cmux 렌더를 확인하고 SHA-256을 상태 파일에 기록한다. 계획 단계 앱 테스트는 미실행이며 기능 검증 통과를 주장하지 않는다.

7완료 조건

  • 한 합성당 연결/task 하나. task-finished와 유효 MP3 전 close는 부분 성공이 아니다.
  • 연결 중·수신 중·완료 직후 취소 및 늦은 Upgrade에서 listener·socket 누수와 중복 settle이 없다.
  • 주입된 signal이 모든 대기를 끝내고 timeout reason을 호출부에 보존한다. provider 내부 deadline·재연결·재합성·벤더 전환은 없다.
  • 키·원문·병음·제공자 원문 오류가 공개 결과·로그·close reason에 나오지 않는다.
  • qwen.ts와 전용 테스트·필요 fixture 및 계획 기록만 변경하며 정상·실패·취소 검증을 완료한다.
  • npm test, npm run lint, npm run build의 실제 결과를 기록한다. 실키·모델 접근·청취·모바일·R2·지연은 별도 미검증으로 남긴다.
