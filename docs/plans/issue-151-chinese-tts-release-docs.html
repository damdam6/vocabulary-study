1요약

#149의 환경 기록과 #150의 자동 통합 검증이 feat/ch-sound에 병합된 상태를 제품·설계 문서에 반영한다. 새 운영 문서는 비공개 R2 재사용, Qwen task 완료, UNCONFIRMED, usage.characters 기반 계량, revision 롤백과 명시적 이전 파일 정리를 하나의 실행 순서로 묶는다. 이 이슈는 문서만 변경하며 API 키 주입, Worker 배포·활성화, 실제 R2 객체 접근, 유료 합성·청취, 모바일·지연 측정은 수행하거나 완료로 기록하지 않는다.

2현황 분석

  • 추적 설정은 이미 wrangler.jsonc:26-40에 TTS_ENABLED=false, Qwen 모델·음색·속도·revision 및 운영 vocabulary-study-tts-audio/개발·테스트 audio-uploads R2 binding을 둔다. 환경 문서는 두 버킷의 Standard·비공개·r2.dev 비활성·완성 객체 자동 만료 없음은 관찰했지만 객체 접근은 미검증이라고 구분한다.
  • worker/routes/words.ts:39-50은 인증된 zh 프로필에서만 준비된 설정을 { enabled, revision, maxTextLength: 200 } capability로 공개한다. worker/routes/tts.ts:24-84는 POST /api/tts의 profile/설정/입력 검증을 R2·Qwen보다 앞에 두고 MP3와 X-TTS-Source, X-TTS-Storage, X-TTS-Pronunciation, X-TTS-Revision만 반환한다.
  • 저장 서비스는 R2 hit를 STORED/PRESENT로, 새 MP3의 조건부 저장 성공을 GENERATED/SAVED로 반환한다. 2초 쓰기 대기 초과·실패·경합 재조회 실패는 이미 검증한 생성 MP3를 GENERATED/UNCONFIRMED로 반환하고 원래 put 관측은 background task에 남긴다(worker/lib/tts/service.ts:150-188). 그러므로 UNCONFIRMED는 저장 성공·실패의 확정 표기가 아니다.
  • Qwen adapter는 task가 task-finished가 되고 유효한 MP3가 조립될 때만 완료한다. 제공자가 보낸 정수 payload.usage.characters만 billed characters로 보존한다(worker/lib/tts/providers/qwenProtocol.ts:97-120, :148-152). 원문 코드 포인트 수나 무료 할당량으로 실제 비용을 추정·확정할 수 없다.
  • 제품 PRD는 아직 “구현용 초안/기능 미구현”이라고 서술하고, 기본 PRD는 TTS를 비범위·v2 후보로 남긴다(docs/PRD-chinese-tts-audio.md:1-14, docs/PRD.md:44-54, :326-335). 반면 실제 UI는 모드1 공개 뒤와 모드2 오답 결과의 선택적 버튼·상태를 연결한다(src/screens/Mode1Card.tsx:85-102, :157-169, src/screens/Mode2Card.tsx:36-43, :68-94).
  • #150의 자동 증거는 docs/plans/chinese-tts-audio-verification.md에 AC-01~24별 테스트와 55 files/696 tests·lint·build 결과로 기록되어 있다. 실제 키/endpoint, 객체 격리·재사용, 청취, iOS/Android, p95는 그 문서와 환경 기록 모두에서 출시 전 미검증으로 남아 있다.
이슈 완료 조건계획의 근거·반영 위치
기존 3개 PRD와 저장·길이·재생·병음·API 상태 일치작업 1~3. 코드의 200자 capability, zh 한정, A열 합성/B열 진단, 공개 시점·버튼 상태, POST /api/tts 응답 진단을 공통 표현으로 맞춘다.

키 없이 환경별 주입·무료량 미확인 상태 안내작업 5. 키 발급·staged upload·배포된 secret·국제 endpoint/model 접근을 각각 별도 체크로 기록하고, 계량은 usage.characters와 제공자/R2 청구 자료로만 대조한다.
그래프 완료와 출시 검증 완료 구분작업 4·6. 자동 회귀 완료는 명시하되 실제 오디오·보안 격리·모바일·p95·활성화 체크리스트는 미완료 상태를 유지한다.

3설계

문서를 세 층으로 정리한다. 제품 PRD는 사용자·API 계약을, 아키텍처는 코드와 R2/Qwen의 수명·진단 계약을, 새 운영 문서는 승인된 사람이 실제 환경에서 따라야 할 비파괴적 출시 순서를 소유한다. 자동 테스트의 더블 증거와 실제 환경의 관찰은 같은 표에서 합격으로 합치지 않는다.

  • 선택: 기존 docs/plans/chinese-tts-audio-environment.md와 ...-verification.md를 사실 기록으로 유지하고, 절차만 새 ...-operations.md에 둔다. 이미 검증한 #149/#150 내용을 복제하면 날짜·상태가 다시 어긋날 수 있기 때문이다.
  • 선택: cost는 Qwen의 완료 이벤트에서 나온 usage.characters와 실제 provider/R2 청구 정보를 대조하는 절차로만 기술한다. 현재의 고정 가격·무료 사용량 또는 원문 길이로 비용을 단정하는 예시는 제거하거나 비규범적 기록으로 격리한다.
  • 선택: secret 운영은 Cloudflare 공식 문서의 현행 의미를 따른다. wrangler secret put은 새 version을 만들고 즉시 배포하지만, wrangler versions secret put은 version만 만들며 별도의 wrangler versions deploy가 필요하다. 조사 시 확인한 프로젝트 Wrangler는 4.110.0이며 두 상태를 혼동하지 않는다.
  • 배제: 문서 이슈에서 TTS_ENABLED=true로 바꾸거나, 새 named 환경·bucket lifecycle·자동 cleanup·batch/pre-generation·SSML/hot_fix/provider fallback을 도입하지 않는다. 이들은 계약상 별도 승인·기능 범위다.

4작업 단계

  1. 기본 기능 PRD에서 TTS를 더 이상 비범위/v2 후보로 두지 않고, 기존 학습 계약을 침범하지 않는 zh 전용 음성 기능으로 연결한다. 범위·시스템 구조·환경/시크릿 설명·GET /api/words capability·POST /api/tts·학습 화면·비기능 요구사항을 실제 코드의 200자 제한, private/no-store, 비차단·retryQueue 제외와 일치시키고 오래된 등록 흐름은 다시 쓰지 않는다.docs/PRD.md · 근거: worker/routes/words.ts, worker/routes/tts.ts, worker/lib/tts/types.ts
  2. 범용화 PRD에 A열만 합성하고 B열은 표시·정규화된 객체 키의 식별 입력이지만 첫 버전 provider hint에는 적용하지 않는 정책을 추가한다. profile.contentType === "zh"만 capability/버튼/route를 쓸 수 있고 generic 및 기능 off는 기존 학습을 유지한다는 점, TTS 요청은 profile-tagged 학습 retryQueue에 들어가지 않는 점을 API·화면·큐 절에 정확히 반영한다.docs/PRD-general.md · 근거: worker/routes/words.ts:39-50, worker/routes/tts.ts:24-29, worker/lib/tts/types.ts:94-114
  3. 디자인 PRD의 모드1 공개와 모드2 오답 결과에 공통 발음 버튼의 위치·focus·loading/playing/수동 오류/200자 비활성 상태를 추가한다. B열이 비어도 버튼은 유지하고, generic·모드2 정답에는 노출/요청이 없으며, 자동 시도는 모드1 transform 완료 또는 모드2 결과 DOM 반영 뒤 1회이고 판정·다음·기록을 기다리지 않는다고 명시한다.docs/design-prd.md · 근거: src/screens/Mode1Card.tsx:85-102, :157-169, src/screens/Mode2Card.tsx:36-43, :68-94, src/components/PronunciationButton.tsx:45-72
  4. 중국어 TTS PRD와 아키텍처의 상태를 실제 병합된 구현/자동 증거 기준으로 갱신한다. API의 오류·진단 header, R2 key/revision 보관·조건부 저장, Qwen task-finished과 billed characters, UNCONFIRMED의 의미, capability 및 비목표를 코드와 맞춘다. 5리스크

리스크영향완화책
자동 더블 검증을 실제 출시 성공으로 서술키/R2/청취/모바일/지연의 미확인 위험이 숨겨짐각 표에 “자동 증거”와 “라이브 출시 확인” 열을 분리하고 #149/#150 문서의 한계를 그대로 링크한다.
secret 명령의 deploy 의미 혼동의도하지 않은 version 배포 또는 “주입됨” 오기록staged versions secret put, 별도 deployment, deployed secret-name 확인, endpoint/model 호출 성공을 순서가 다른 네 상태로 기록한다.
UNCONFIRMED를 저장 실패/성공으로 단정불필요한 재합성·비용·운영 오판응답은 생성 MP3의 foreground 성공임을, R2 상태는 새 요청과 background write 관찰로만 확인함을 runbook에 적는다.
현재 가격·Free Tier를 고정값으로 문서화계정·시점별 과금 조건을 잘못 안내문자 수는 provider가 반환한 usage.characters로, 비용/무료량은 운영 시점의 공식 provider·R2 청구 화면으로 확인하도록 한다.
이전 R2 object cleanup을 자동화하거나 넓은 prefix로 실행롤백에 필요한 파일을 비가역 삭제자동 lifecycle/삭제는 비범위로 유지하고, 현재 profile partition·revision을 읽기 전용으로 확인한 뒤 승인된 좁은 대상만 수동 정리하도록 한다.
상호 링크·anchor 또는 설정 이름 드리프트운영자가 잘못된 절차/계약을 따름TTS_ENABLED, DASHSCOPE_API_KEY, bucket binding, source/storage 진단, AC-01~24를 코드·문서 간 검색하고 모든 변경 링크를 해석한다.
