1요약

#172 PRD §3에 따라 중국어 단어·문장에 공통으로 적용할 형식 계약을 만들고 서버 등록에 연결한다. 신규 값은 NFC·trim 후 저장하고, 선택 탭 중복 비교에만 정규화를 적용하여 기존 원문 행과 학습 기록 키를 보존한다. 이번 작업은 #173에 한정하며, UI·병음 경고·Python 킷(#174), 채점(#175), 화면(#176), TTS(#177), 최종 통합(#178)은 후속 이슈다. 요청 실행 설정은 codex / gpt-6-astra / high이며 현재 상태는 구현·검증 완료이며 issue-work 절차에 따라 PR로 게시한다.

2현황 분석

  • 명세: #172의 PRD 전문·의존성 그래프와 메인 체크아웃 docs/PRD-chinese-sentence-study.md를 모두 확인했다. #173은 선행 없음, 직접 후속은 #174·#175다. 메인의 미커밋 PRD는 읽기 참고 자료로 사용하며 이 브랜치에 복사하거나 커밋하지 않는다.
  • worker/lib/register.ts:54는 배열·100건·문자열 타입을 확인한 뒤 모든 필드를 trim한다. zh는 기본 한자 전용 정규식(:23)과 병음 형식(:30)을 적용한다. NFC·길이 제한은 없고, 영문 혼합 및 문장부호를 거부한다. 병음은 v를 포함한 ASCII 전체가 허용되지 않으며 의미 검증은 하지 않는다.
  • worker/lib/register.ts:79는 trim한 신규 원문의 정확 일치로 배치 중복을 차단한다. :119의 선택 탭 중복은 기존 A열 문자열을 정규화하지 않는다.
  • worker/routes/register.ts:42는 인증 프로필의 contentType으로 검사한다. :73에서 선택 탭 A열을 읽고 :82에서 신규 항목만 마지막 행 아래 A~C에 쓴다. 오류 문구(:50)는 한자 전용 정책을 설명하고 있어 변경해야 한다.
  • src/lib/registerValidation.ts:122가 붙여넣기 JSON의 version 1을 검사한다. 실제 POST 요청(src/lib/registerApi.ts:62)은 tab·words이며 version이 없다. 이 요청 계약은 유지한다.
  • worker/lib/words.ts:29는 시트 원문을 보존하고 :67·:94는 정확한 원문 키로 행을 찾는다. 등록 정규화를 이 경로에 전파하지 않는다.
  • worker/lib/register.test.ts:65·:77의 기존 거부 기대와 :150의 클라이언트 정규식 소스 비교는 새 서버 계약에 맞게 대체해야 한다. 서버/클라이언트 설정은 분리되어 있고 공용 shared 디렉터리는 아직 없다(tsconfig.worker.json, tsconfig.app.json).

3설계

공통 모듈: shared/registration.ts에 런타임·프로필 구현 의존성이 없는 순수 함수를 둔다. 한자/병음 정규화, 코드 포인트 개수, 고정 허용 문자, 필드별 형식 오류, 등록 중복 키를 내보내 #174가 직접 재사용할 수 있게 한다. 한자-병음 의미 검사는 넣지 않는다.

  • A열: NFC 후 양끝 공백을 제거하고 1~200 코드 포인트, U+4E00~U+9FFF 한자 최소 1자. ASCII·전각 영문/숫자, U+0020·U+3000과 PRD의 고정 문장부호만 허용한다. 내부 공백, 대소문자, 문장부호, 전각 형태는 보존한다.
  • 고정 문장부호: ，。！？；：、,.!?;:（）()【】[]《》〈〉“”‘’「」『』"'…—-·／/％%＋+＝=．. Unicode 문장부호 전체 허용이나 NFKC 변환은 쓰지 않는다.
  • B열: NFC·trim 후 1~1,000 코드 포인트. ASCII A~Z/a~z 전체(v 포함), ü 및 기존 성조 모음의 대소문자, U+0020·U+3000, 동일 문장부호를 허용한다. 기존 성조 부호 최소 하나를 요구한다. ASCII/전각 숫자와 숫자 성조는 금지한다. 뜻은 기존 문자열·trim 후 비어 있지 않음만 검사한다.
  • 검사 순서: 원본 A/B의 제어문자(C0/C1, 탭·CR·LF 포함)를 먼저 차단한다. 양끝에서는 U+0020·U+3000만 제거하고 나머지 목록 밖 공백도 오류로 처리해 trim으로 불허 문자가 사라지지 않게 한다. NFC 후 길이를 세며 자동 절단하지 않는다. 이 해석을 fixture로 고정해 #174 Python 동기화 시 동일하게 따른다.
  • 오류는 빈 값·불허 문자/제어문자·한자 없음·길이 초과·성조 없음 등 필드별로 구분할 수 있게 한다. 서버는 기존 parseRegisterWords의 배열/null 계약과 HTTP 400 형식을 유지하면서 오류 안내에 200/1,000 코드 포인트 제한을 명시한다.
  • 신규 zh A/B는 정규화된 값을 저장한다. 배치 중복은 정규화된 A열 키로 차단한다. partitionByExisting에 contentType을 전달하여 zh에서만 기존 A열에 NFC·trim 비교 키를 적용한다. 기존 행은 검증·수정하지 않으며 toAdd/skipped에는 신규 등록 원문을 유지한다. 你好와 你好。는 다른 항목이다.
  • generic은 기존 trim, 필수 필드, 빈 병음 허용, 선택 탭 정확 일치, 배치 중복 정책을 유지한다. 신규 zh 제한은 읽기·기록·재시도·TTS로 전파하지 않는다.
  • tests/fixtures/chinese-sentence-registration.json은 JS/Python이 함께 읽을 순수 JSON으로 제공한다(58개 등록 사례·3개 중복 분할 사례·기존 장문 사례). id·contentType·입력 words·기대 허용/차단·정규화 결과를 기록하고, 중복/기존 시트 사례는 별도 묶음으로 구분한다. 의미 불일치·변조·혼합은 서버 형식 검증 통과 사례이며 후속 UI 경고 여부와 혼동하지 않는다. 원문 201자 기존 행은 신규 등록 거부·읽기 보존의 서로 다른 기대를 명시한다.

6테스트 계획

  • 공통 계약: 허용 문장부호 각각, U+4E00/U+9FFF 경계, 확장 A/이모지/서로게이트/불허 문자 거부, ASCII·전각 혼합, 한자 없는 원문 거부.
  • NFC: 분해 성조를 합성하여 저장하고 정규화 후 길이를 센다. 200/201 원문 및 1,000/1,001 병음 경계, 내부/양끝 탭·개행·C0/C1, 비허용 공백을 검증한다. UTF-16 length에 의존하지 않는다.
  • 병음: 대문자 성조·ü·ASCII 전체와 부호 허용, 숫자/전각 숫자·무성조·빈 병음 차단. 단어·문장·다음자·변조·의미 불일치는 형식만 검사한다.
  • 배치: 100건 통과/101건 거부, 누락·비문자열·빈 값·빈 배열 거부, 정규화 중복 차단, 문장부호·내부 공백·대소문자 차이는 다른 키.
  • 라우트: 선택 탭 정규화 중복 스킵과 새 문장 A~C 저장, 기존 A~G 불변, 내부 빈 행 이후 append 위치, invalid 배치에서 Sheets 쓰기 0회, 인증 프로필/탭 격리.
  • generic: 빈 병음·자유 텍스트·기존 trim·대소문자·NFD/NFC 구분과 선택 탭 정확 일치 유지. 기존 장문 GET에서 원문 유지. version 1 및 기존 등록 API 계약은 기존 프런트 테스트로 회귀 확인.
  • 실행: npx vitest run shared/registration.test.ts worker/lib/register.test.ts worker/routes/register.test.ts worker/routes/register.generic.test.ts worker/routes/words.test.ts, 이어 npm test, npm run build, npm run lint. npm ci로 의존성 설치 완료.
  • 검증 결과(2026-09-24): npm test — 56개 파일, 943개 테스트 통과. npm run lint 및 npm run build 통과. 빌드의 Wrangler 로그 저장 권한 오류는 WRANGLER_LOG_PATH=/private/tmp/issue-173-wrangler.log로 경로를 지정하여 재실행했고 오류 없이 완료했다. 외부 Sheets/TTS는 mock으로 검증한다. 실제 시트 쓰기·유료 합성·배포는 수행하지 않는다. Python 구현 동기화/검증은 #174, 전체 E2E는 #178에서 수행한다.

  • 한자 포함 숫자/영문과 문장부호를 허용하고 제어문자·숫자 성조·빈 값·길이 초과를 차단한다.
  • zh 배치·선택 탭은 NFC·trim 키로 중복 비교하고 기존 원문 행·학습 기록 키를 수정하지 않는다.
  • 100건, version 1, 와이어 필드, generic, append-only 저장, 기존 긴 항목 조회를 유지한다.
  • 경계·혼합·단어·문장·generic 공통 JSON fixture와 서버 테스트가 제공되며 npm test/build/lint가 통과한다.
  • #174~#178 구현을 포함하지 않고 실제 환경 미검증 및 테스트 결과를 기록한다.
