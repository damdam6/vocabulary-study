1요약

#172 PRD의 SENT-05 범위에 맞춰 문장 원문이 기존 TTS 경로를 통과하는지, 200 코드 포인트 경계에서 기존 장문 학습을 보존하는지, 모드1·모드2의 자동/수동 재생과 문제 전환 수명을 회귀 검증한다. 현재 코드에는 이 계약을 수행하는 controller·Worker·Audio/R2 경로와 단어 중심 테스트가 이미 있으므로, 우선 문장부호·숫자·긴 문장 fixture를 기존 경계에 연결하고 실패·자동재생 차단·늦은 응답이 채점/기록을 막지 않는다는 증거를 추가한다. 제공자 호출·R2 저장·실제 유료 합성·모바일 청취는 mock 통합 검사와 별도 미검증 기록으로 구분한다.

3설계

새 문장 타입·시트 열·provider 계약을 만들지 않는다. 기존 word.hanzi → usePronunciation → controller → fetchTtsAudio → /api/tts → R2/provider 경계를 그대로 두고, 각 경계가 원문과 수명을 보존하는지를 테스트로 증명한다.

  • 원문 fixture는 今天下午三点，我们一起去图书馆学习。价格是3.5元。, ASCII/전각 문장부호, 숫자·영문 혼합을 사용한다. 채점 정규화 결과(src/lib/studySession.ts의 비교용 값)는 TTS input·AnswerRecord·행 키에 절대 사용하지 않는다는 payload assertion을 둔다.
  • 길이 기준은 JavaScript UTF-16 길이가 아니라 현재 계약의 Unicode code point 기준이다. 200자는 요청/재생, 201자는 요청 0회·비활성 안내·학습/판정 진행으로 분리하고, 앞뒤 trim 및 내부 문장부호/숫자 보존을 함께 검사한다.
  • provider mock은 createSynthesisInput와 Qwen message의 text-only 계약을 확인하고, pinyin이 있거나 바뀌어도 provider 입력은 동일 원문이며 진단은 ignored임을 확인한다. R2 key는 기존 pinyin·revision·설정 분리 계약을 유지한다.
  • 자동 재생은 모드1 공개 후와 모드2 오답 후 각각 1회, 수동 반복은 추가 합성 없이 cache 재사용으로 고정한다. fetch/provider 실패, NotAllowedError, TTS 비활성은 학습 판정·answer/review-fail 기록과 독립임을 화면 통합으로 검증한다.
  • 동일 controller unit과 StudyScreen 통합에서 다음 문제·종료·unmount 전에 AbortSignal/Audio/Object URL을 정리하고, 이후 도착한 응답/이벤트가 새 문제를 재생하지 않는지 확인한다. 실제 모바일 자동재생·음질·과금은 자동 테스트의 합격으로 간주하지 않는다.

7완료 조건

  • #176 이후 문장 원문이 문장부호·숫자를 포함한 채 기존 TTS transport에 전달되고, 채점용 정규화 텍스트가 전달되지 않는다.
  • 기존 시트의 200자 초과 항목은 화면·학습·판정을 유지하며 TTS 요청은 0회이고 “발음은 200자까지 지원해요.” 안내를 제공한다. 200자 경계는 Unicode code point 기준이다.
  • 모드1 공개 후와 모드2 오답 후 자동 재생은 문제당 1회이며, 수동 반복과 cache hit는 추가 합성 없이 동작한다. B열은 provider 발음 힌트로 사용되지 않고 기존 R2 key 계약만 유지한다.
  • 다음 문제·종료·완료·숨김·unmount 시 요청과 재생이 취소/정리되고 늦은 응답·이벤트가 새 문제를 재생하지 않는다.
  • TTS 실패·비활성·자동재생 차단은 채점·answer/review-fail 기록·retry queue·세션 통계를 막지 않으며, 자동 실패는 음성 retry queue를 만들지 않는다.
  • 관련 mock 통합 검사와 전체 test/build/lint 결과가 기록되고, 실제 유료 합성·운영 R2·모바일 청취 여부가 자동 검사 성공과 분리되어 명시된다.
  • 구현과 ready PR 생성은 Sol medium 단계에서 수행하고, 병합은 Grok 독립 리뷰와 오케스트레이터 검증 뒤에만 수행한다.
