API 클라이언트 프로필 수신·저장 — verifyPassword·fetchWords 확장 + 프로필 캐시

damdam6/vocabulary-study 브랜치 feat/77-api-client-profile-cache ← main 라벨 enhancement 2026-07-27

1요약

서버 쪽 프로필 해석(#71)과 응답 배선(#73)은 이미 완료돼, GET /api/health·GET /api/words 모두 공개 프로필 블록({ id, name, modes, contentType })을 반환한다. 이 이슈는 그 서버 계약을 클라이언트 API 계층(src/lib/api.ts·src/lib/wordsApi.ts)이 실제로 수신하고, localStorage에 저장/조회/삭제할 수 있는 헬퍼를 갖추는 "전반부"다. verifyPassword는 성공 시 profile을 함께 반환하고, fetchWords는 { profile, words }를 반환하도록 확장하며, clearPassword(401 처리 경로 포함)는 프로필 캐시도 함께 지운다. 화면이 이 값을 실제로 저장·표시·연결하는 배선(로그인 저장, 홈 프로필명/전환 링크, modes 연결)은 후속 이슈 #78의 범위이므로, 이번 작업은 기존 소비처가 새 반환 형태로 컴파일·테스트를 통과하는 선까지만 다룬다.

2현황 분석

  • src/lib/api.ts:61 VerifyResult = "ok" | "invalid" | "error" — 상태 문자열만 반환, verifyPassword(api.ts:68-77)는 /api/health 응답 바디를 전혀 읽지 않는다.
  • src/lib/wordsApi.ts:11-16 fetchWords는 응답을 { words: WordEntry[] }로 캐스팅해 words 배열만 반환하고 profile·fetchedAt은 버린다.
  • localStorage에는 app-password(api.ts:9)와 재시도 큐 키뿐 — 프로필 캐시 저장소가 없다.
  • 서버 계약은 이미 확정·구현됨: worker/index.ts:35-38의 /api/health가 { ok, time, version, profile: toPublicProfile(profile) }를, worker/routes/words.ts:26-32의 /api/words가 { fetchedAt, words, profile }를 반환한다. worker/lib/profiles.ts:28의 PublicProfile = Pick<Profile, "id"|"name"|"modes"|"contentType">가 sheetId· password 제외를 서버 쪽에서 이미 강제한다.
  • tsconfig.app.json이 src만 포함해 클라이언트가 worker 타입을 import할 수 없다 (api.ts:83-86의 WordEntry 미러 주석과 같은 이유) — PublicProfile도 클라이언트 쪽에 별도 미러 타입이 필요하다.
  • 소비처 3곳: src/screens/LoginScreen.tsx:20-27(verifyPassword 결과를 문자열 비교로 분기), src/screens/HomeScreen.tsx:34-40·src/screens/RegisterScreen.tsx:65-70 (fetchWords를 배열로 직접 소비).
  • HomeScreen.tsx:38,76에 이미 "#78(화면 프로필 배선) 전까지 고정 주입" 주석이 있어, profile.modes를 실제 화면 로직에 연결하는 일은 이 이슈 범위가 아님이 코드에도 명시돼 있다.
  • 의존 이슈 #71·#73 모두 closed — 서버 계약이 확정된 상태에서 진행 가능.

3설계

  • VerifyResult를 판별 유니온 { status: "ok", profile: PublicProfile } | { status: "invalid" } | { status: "error" }로 확장한다 — 기존 3분기 흐름은 그대로 두면서 성공 케이스에만 profile을 싣는다. 대안으로 { result, profile? } 형태(optional 필드)도 고려했으나, 판별 유니온 쪽이 result.status === "ok" 좁히기로 profile 존재를 타입 레벨에서 보장해 더 안전하다.
  • 프로필 캐시 헬퍼는 비밀번호 헬퍼와 이름 대구를 맞춘다: getStoredProfile/saveProfile/ clearProfile, 키는 vocab-study:profile(PRD §7 확정값). getStoredProfile은 손상된 JSON을 만나면 예외 대신 null로 폴백한다.
  • clearPassword 내부에서 clearProfile을 호출한다 — 401 처리 경로(apiFetch)가 clearPassword 하나만 호출하므로, 이 한 곳만 고치면 "비밀번호 삭제 시 프로필도 함께 삭제" 불변식이 모든 호출 경로(직접 호출 + 401 경로)에 자동 적용된다.
  • fetchWords 반환 타입을 { profile: PublicProfile; words: WordEntry[] }로 확장한다. fetchedAt은 클라이언트가 쓰는 곳이 없어(grep 확인) 이번 범위에 포함하지 않는다 — PRD가 요구하는 불변식은 "words 항목 형태"뿐이다.
  • 화면 쪽은 새 반환 형태로 컴파일·테스트를 통과시키는 최소 수정만 한다: LoginScreen은 result.status 분기로 전환만 하고, HomeScreen·RegisterScreen은 fetched.words 구조분해만 한다. saveProfile을 실제로 호출해 로그인 저장·홈 캐시 갱신을 배선하는 일은 하지 않는다 — 그 화면 배선은 #78의 산출물이다.

4작업 단계

  1. 클라이언트 미러 타입 PublicProfile·ContentType과 프로필 캐시 헬퍼 (getStoredProfile/saveProfile/clearProfile, 키 vocab-study:profile) 신설 src/lib/api.ts
  2. clearPassword가 clearProfile도 호출하도록 수정 — 401 경로에 자동 적용 src/lib/api.ts
  3. VerifyResult를 판별 유니온으로 변경하고, verifyPassword가 200 응답 바디의 profile을 파싱해 { status: "ok", profile }로 반환하도록 수정 src/lib/api.ts
  4. fetchWords 반환 타입을 { profile, words }로 확장 src/lib/wordsApi.ts 실행 중 보강: 응답 전체를 그대로 캐스팅하지 않고 { profile, words }만 골라 반환하도록 했다 — 안 그러면 서버가 함께 보내는 fetchedAt이 반환값에 섞여 타입이 약속하는 형태와 실제 런타임 값이 어긋난다.
  5. 소비처 컴파일 갱신: LoginScreen은 result.status 분기, HomeScreen· RegisterScreen은 fetched.words 구조분해로 전환 src/screens/LoginScreen.tsx, src/screens/HomeScreen.tsx, src/screens/RegisterScreen.tsx
  6. 테스트 갱신·추가: verifyPassword 3분기(ok/invalid/error) + profile 페이로드, 프로필 캐시 헬퍼 왕복, clearPassword 연쇄 삭제(직접 호출 + 401 경로), fetchWords 신 반환 형태 src/lib/api.test.ts, src/lib/wordsApi.test.ts
  7. npm test·npm run lint·tsc -b 전체 통과 확인 (229 tests passed, lint clean, 빌드 통과) (전체)

6테스트 계획

  • 프로필 캐시 헬퍼: 저장 → 조회 → 삭제 왕복이 성립한다.
  • clearPassword 직접 호출 시, 그리고 apiFetch의 401 경로를 통했을 때 모두 비밀번호와 프로필 캐시가 함께 삭제된다.
  • verifyPassword가 반환하는 profile에 sheetId·password 키가 없음을 확인한다(타입 정의 + 목 응답 검증).
  • fetchWords가 { profile, words } 형태를 그대로 반환한다(AbortSignal 전달, 비정상 응답 throw 등 기존 케이스는 유지).
