1요약

#175에서 확정한 중국어 문장 채점과 원문 키 보존을 전제로, 학습 카드가 200자 원문·1,000자 병음·긴 뜻·긴 오답을 손실 없이 표시하도록 만든다. 짧은 단어의 기존 강조 크기는 유지하고 긴 콘텐츠는 코드 포인트 길이에 따른 표시 크기, 줄바꿈, 콘텐츠 전용 스크롤로 처리한다. 모드2 중국어 입력은 여러 줄 textarea로 바꾸되 Enter 제출, Shift+Enter 개행, IME 조합 중 제출 방지를 명확히 한다. 데이터 필드·기록 API·채점·TTS lifecycle은 변경하지 않고, #169 Speaker Position의 병음 중심·발음 버튼 위치와 접근성 계약을 보존한다.

3설계

카드와 세션의 기존 계약을 유지하면서 “내용이 길어지면 내용 영역만 스크롤되고 조작 컨트롤은 고정”되는 방향을 선택한다. DOM을 전면 재구성하거나 채점 정규화를 UI에 복사하지 않는다. 길이 판단은 문자열 이터레이터를 사용해 #173/기존 hanziFontSize의 코드 포인트 기준을 계승한다.

  • 모드1 원문 표시: src/lib/hanziSize.ts의 짧은 1~2자 84px, 3자 64px, 짧은 4자 이상 52px 결과를 보존하고, 문장 길이 구간에만 추가적인 작은 표시 크기를 제공한다. Mode1Card.tsx는 기존 aria-hidden/inert, flip transition gate, prepare/reveal, O/X 판정을 그대로 두고 길이 결과만 class/custom property에 연결한다. index.css는 긴 앞면·뒷면에 overflow-wrap:anywhere, 줄 높이, min-width:0, 콘텐츠 스크롤을 적용하되 짧은 카드의 중앙 정렬과 #169 병음 grid를 유지한다.
  • 모드2 질문/결과 레이아웃: 긴 뜻을 카드 내부의 min-height:0; overflow-y:auto 콘텐츠 영역에서 읽게 하고, 결과 화면의 기존 .mode2-result-scroll과 “다음” 버튼 분리는 유지한다. 원문 한자·병음·뜻·사용자 입력은 절대 잘라내거나 채점 정규화한 값으로 치환하지 않는다. 결과의 병음 행은 반드시 기존 .pinyin-speaker 아래에 두어 스피커 위치와 키보드 탐색을 보존한다.
  • textarea 입력: Mode2Card.tsx의 inputRef를 textarea ref로 교체하고, 동일한 form submit 경로를 유지한다. Enter는 IME 조합 중이 아니고 Shift가 없을 때만 제출하며, Shift+Enter는 기본 개행을 허용한다. nativeEvent.isComposing과 WebKit/브라우저 호환용 keyCode=229를 함께 확인해 조합 중 Enter가 onJudged를 호출하지 않게 한다. 모바일 명시적 제출 버튼과 aria-label/enterKeyHint는 유지한다.
  • 문제 전환 상태: key={session.pos} 리마운트 계약을 유지하고, 새 textarea가 빈 값·초기 높이·scrollTop=0·입력 포커스로 시작하는지 명시적으로 보장한다. 자동 높이 조정이 추가되면 최대 높이 이후 내부 스크롤을 사용하고, 렌더링 직후 scrollHeight를 기준으로 다시 계산해 긴 입력이 제출 버튼을 밀어내지 않게 한다. #175의 원문 tab+hanzi 기록과 #177의 TTS 입력에는 영향을 주지 않는다.
  • 문구: contentLabels.ts의 zh 모드 칩/힌트/placeholder를 “중국어 → 뜻”, “뜻 → 중국어”, “이 뜻의 중국어 단어·문장을 입력하세요”, “중국어”처럼 범위가 드러나는 표현으로 바꾼다. generic의 “단어” 문구, 시트 헤더(registerTableHeaders)와 데이터 필드명은 변경하지 않는다.
  • 접근성·Speaker Position: flip 전 뒷면의 inert와 공개 후 포커스 이동, 모드2 오답의 발음 버튼 우선 포커스/다음 fallback, 버튼의 30px 시각 크기와 44px hit area를 회귀 테스트로 고정한다. 반응형 CSS는 스피커를 이동시키거나 에러 문구를 가리는 방식으로 문제를 해결하지 않는다.

5리스크

리스크영향완화책
긴 콘텐츠가 카드의 flex 높이를 차지해 판정·제출·다음 버튼을 밀어냄모바일에서 조작 불가 또는 가로/세로 잘림내용 영역에 min-height:0과 내부 세로 스크롤을 두고 버튼/판정 영역을 스크롤 밖에 둔다. 320/375px에서 직접 확인한다.
길이 기반 작은 글자 규칙이 짧은 단어의 기존 강조를 바꿈기존 학습 화면 시각 회귀기존 2/3/4자 경계 테스트를 보존하고 긴 구간만 추가한다. generic에는 zh 전용 크기 함수를 적용하지 않는다.
IME Enter를 일반 제출로 잘못 인식조합 중 문장이 조기 제출되거나 중복 판정isComposing과 keyCode=229를 테스트하고, form 버튼 제출 경로와 onJudged 1회 보장을 유지한다.
textarea 자동 높이 조정이 문제 전환 시 이전 높이/스크롤을 재사용새 문제가 큰 입력란에서 시작하거나 답이 가려짐질문 key 리마운트와 layout effect 초기화를 함께 검증하고 새 ref의 value, 높이, scrollTop, focus를 검사한다.
#169 Speaker Position grid 또는 compact hit area가 긴 병음에서 깨짐발음 버튼이 병음 중심을 흐리거나 접근 불가기존 .pinyin-speaker DOM/CSS를 재사용하고 긴 병음 줄바꿈·발음 버튼 focus/replay 회귀를 확인한다.
UI에서 채점 정규화를 다시 적용해 원문 기록/TTS 텍스트를 훼손시트 행 식별·오답 표시·발음 계약 회귀gradeMode2와 StudyScreen 기록 코드는 수정하지 않고, 기존 #175 원문 키 테스트를 전체 회귀에 포함한다.
