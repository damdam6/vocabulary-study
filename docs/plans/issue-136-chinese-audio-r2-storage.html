#136기능 개선 · TTS-02

중국어 MP3의 비공개 R2 조회·조건부 저장

damdam6/vocabulary-study 브랜치 feat/136-chinese-audio-r2-storage ← feat/ch-sound 라벨 enhancement 2026-09-16

1요약

비공개 R2 저장 경계를 worker/lib/tts/storage.ts에 추가한다. 인증 프로필·시트, 정규화한 A/B열, 음성 설정으로 안정적인 객체 키를 만들고 검증된 MP3만 조회·조건부 저장한다. 조회 실패는 미존재와 구분하고 저장 성공·경합·실패는 호출부가 관측한다. #139가 시간 예산·경합 재조회·백그라운드 회수와 결과 정책을 연결한다.

2현황 분석

  • 조사 기준 HEAD는 be74e1270be127a3252e2143e0b5f1560d21ef9c이며 #135의 공통 계약이 포함돼 있다. GitHub #136 본문과 댓글(0개), PRD, 아키텍처, 17개 태스크 지도를 대조했다. 작업 브랜치는 #136과 일치하고 시작 시 작업 트리는 깨끗했다.
  • worker/lib/tts/storage.ts는 아직 없다. worker/lib/tts/types.ts:95에 NormalizedTtsInput, :117에 동기 boolean ValidateAudio, :150에 비밀 없는 TtsConfig가 있다. 4MiB 음성 상한은 :9를 재사용한다.
  • worker/lib/tts/input.ts:30이 NFC·줄바꿈·trim 및 빈 병음→null을 처리한다. worker/lib/tts/pronunciation.ts:4는 B열을 absent/ignored로 진단한다. 저장 키는 이 정규화 결과를 소비하며 별도 정규화나 병음 파서를 만들지 않는다.
  • worker/lib/profiles.ts:12의 서버 Profile에서 id/sheetId만 사용한다. 인증은 worker/lib/auth.ts:19가 소유한다. 비밀번호가 있는 Profile 전체나 TtsServerDependencies를 직렬화하지 않는다.
  • worker/lib/tts/config.ts:21에서 revision을 영문·숫자·하이픈·밑줄 1~64자로 검증한다. :27은 TTS_ENABLED 미설정/false를 disabled로 처리한다. 현재 Wrangler 설정에 TTS_ENABLED 항목이 없고 이번 작업은 해당 설정을 변경하지 않는다.
  • worker-configuration.d.ts:2021에 R2Bucket과 조건부 put의 nullable 반환 overload가 이미 있다. worker/lib/tts/types.ts:129의 TtsAudioBinding은 설정 존재 검사 전용의 느슨한 경계이므로 저장 모듈의 호출 타입으로 쓰지 않는다.
  • vitest.config.ts:1은 Cloudflare Vite 플러그인을 제외한 테스트 설정이다. package.json:6에 test/lint/build가 있고 tsconfig.worker.json:1이 Worker와 생성 타입을 검사한다. 현재 워크트리에 node_modules는 없다. 구현 단계에서 의존성을 준비한 뒤 검증해야 한다.

범위 근거: 아키텍처 §6.1~6.2 · PRD AC-12·13·19~24 · 태스크 지도 · #139 서비스 소유 경계.

3설계와 모듈 계약

1. 공개 모듈 경계

storage.ts에서 createTtsAudioStorage(bucket, validateAudio)와 비밀 없는 키 입력/결과 타입을 export한다. bucket은 실제 R2Bucket을 받을 수 있는 Pick<R2Bucket, "get" | "put"> 또는 이에 구조적으로 호환되는 최소 포트로 한정한다. 테스트 더블 때문에 generated Env나 공통 타입을 강제 캐스팅·수정하지 않는다. 메서드는 반드시 bucket.get/put(...)로 호출해 receiver를 보존한다.

권장 API는 buildAudioObjectKey(profile: Pick<Profile, "id" | "sheetId">, input: NormalizedTtsInput, config: TtsConfig): Promise<string>, get(key): Promise<StoredAudio | null>, putIfAbsent(key, audio, metadataInput): Promise<"saved" | "conflict">다. StoredAudio는 검증된 Uint8Array와 contentType: "audio/mpeg"를 가진다. metadataInput은 허용한 설정과 문자 수만 받는다. 명칭은 구현자가 조정할 수 있지만 null/오류/경합과 Promise 수명 계약은 유지한다.

2. 키와 데이터 격리

profilePartition = hex(SHA-256(JSON.stringify([profile.id, profile.sheetId]))). 아래 튜플을 JSON으로 직렬화하고 UTF-8 SHA-256 소문자 64자리 hex로 digest를 만든다. 경로는 audio/v1/{profilePartition}/{revision}/{digest}.mp3다. Web Crypto를 사용한다.

[
  "tts-audio-v1", profile.id, profile.sheetId, config.revision,
  config.provider, config.region, config.model, config.voice,
  "zh-CN", config.rate, config.outputFormat, config.audioSettings,
  config.adapterVersion, config.pronunciationPolicy,
  input.text, input.pinyin, null
]

pronunciationPolicy는 #135의 pinyin-none-v1, 마지막 null은 첫 버전 effectiveHint다. audioSettings 순서는 공통 8요소 튜플 그대로다. 설정 객체 전체를 stringify하지 않아 필드 삽입 순서·endpoint·추가 속성이 키를 흔들지 않게 한다. 탭·행·날짜·세션·기기·비밀번호·API 키는 입력에서 제외한다. 서버 검증을 마친 revision과 정규화 입력만 받는 전제를 JSDoc과 테스트에 명시한다.

3. 조회: null만 미존재

조회는 조건·range 없는 단일 get으로 시작한다. httpMetadata.contentType === "audio/mpeg"와 정수 size 1..MAX_TTS_AUDIO_BYTES를 먼저 확인한다. body를 제한된 스트림 읽기로 모으면서 실제 상한을 검사하고 최종 실제 길이와 size를 대조한다. 잘못된 메타데이터로 무제한 arrayBuffer 할당을 유발하지 않는다. 조기 거부/초과 때 읽기를 취소하고 reader lock을 해제하며 정리 오류가 원래 오류를 덮지 않게 한다. 완전한 바이트에만 validateAudio(bytes, contentType)를 호출한다. 손상 객체를 삭제하거나 덮어써 복구하지 않는다.

4. 조건부 저장

쓰기 전에도 MIME·비어 있지 않음·4MiB 상한·주입 검사기로 완성 음성을 확인하고 실패하면 put 0회다. 성공한 바이트와 httpMetadata: { contentType: "audio/mpeg" }, onlyIf: new Headers({ "If-None-Match": "*" })를 단 한 번 전달한다. 바이트 view의 byteOffset/byteLength를 보존해 backing buffer 전체를 저장하지 않는다.

customMetadata는 고정 allowlist provider/model/voice/rate/revision/adapterVersion/characterCount/formatVersion만 문자열로 구성한다. 문자 수는 정규화 text의 코드 포인트 수이며 원문 자체는 저장하지 않는다. 임의 metadata map이나 config/profile/input spread를 받지 않는다. TTL·expires·공개 URL·삭제·일반 put 재시도는 추가하지 않는다.

put 객체 반환→saved, null→conflict, 예외→reject의 세 경로다. 경합을 이미 저장된 성공으로 단정하지 않고 #139가 검증 재조회를 판단한다. 이 동작은 현재 생성 타입 및 Cloudflare R2 공식 API 문서(2026-09-16 확인)와 일치한다.

5. Promise와 후속 이슈 인계

각 메서드는 R2 작업 및 필요한 읽기·검증까지 연결된 완료 Promise를 그대로 반환한다. 저장 모듈 내부에 race·2초 타이머·abort·retry·waitUntil·HTTP 결과 선택을 넣지 않는다. #139는 const putPromise = storage.putIfAbsent(...)를 먼저 보관하고 별도 deadline과 경쟁시킨 뒤, 같은 putPromise를 백그라운드 관측에 등록할 수 있다. 내부 R2 Promise도 반환 체인에 연결하여 resolve/reject가 소실되지 않게 한다. 여기서 “원래 Promise”는 시간 제한 wrapper로 대체되지 않은 저장 연산 완료 Promise이며 native Promise 객체 identity를 요구하는 계약은 아니다.

get에도 동일한 수명 규칙을 적용한다. 경합 재조회는 #139가 새 storage.get(key) 호출로 시작하고 그 Promise를 보관한다. 조회·body·검사 전체 2초, put+경합 재조회 합계 2초, late completion 처리와 GENERATED/STORED 진단은 #139 소유다. 실제 validateMp3 연결은 #137→#139, 인증/공개 응답은 #140, 실제 R2 바인딩은 #149 소유다.

6테스트 계획

  • 키: 고정 합성 입력의 partition/digest 기대값을 독립 SHA-256 계산으로 고정한다. 동일 값의 새 객체·다른 속성 순서·세션/기기/탭·불필요 속성 변경은 동일 키다. id/sheetId/text/pinyin/revision/provider/region/model/voice/rate/outputFormat/audioSettings의 각 요소/adapterVersion/pronunciationPolicy 변경은 새 키다. 구분자 충돌 사례도 포함한다. 현재 allowlist 밖 설정 변경은 해시 회귀 테스트에만 한정하며 운영 설정 허용 범위를 확장하지 않는다.
  • 정규화 연동: 기존 normalizeTtsInput을 거친 NFC/CRLF/trim 및 빈 병음은 같은 키, 行/xíng vs 行/háng은 다른 키다. raw A/B열·sheetId·비밀번호·합성 API 키 표식이 키/메타데이터에 없는지 확인한다. fixture는 임의 문자열이며 실제 비밀을 읽지 않는다.
  • 조회: get null, 정상 바이트, get reject, MIME 누락/오류, size 0/음수/소수/상한 초과, body 빈 값/크기 불일치/실제 초과/읽기 reject, 검사 false/throw를 각각 확인한다. 4MiB 경계값은 통과하고 초과는 실패한다. 초기 거부 때 검사기 호출 0회, 초과 읽기 중단과 lock 해제를 확인한다.
  • 저장: 정확한 Headers 조건과 audio/mpeg metadata, 허용 필드만 기록, Uint8Array subarray 범위 보존을 확인한다. 빈/초과/잘못된 MIME/검사 false·throw는 put 0회다. R2 객체/null/reject 각각 saved/conflict/실패로 관측된다.
  • 경합: 상태를 가진 R2 더블에서 동일 키로 두 조건부 put을 진행해 첫 객체 바이트가 보존되고 두 번째가 conflict인지 확인한다. 저장 모듈이 일반 put·자동 get 재조회·delete·재시도를 실행하지 않는지 검증한다.
  • 늦은 완료: 제어 가능한 deferred Promise와 테스트 소유 deadline을 사용한다. 외부 대기가 끝난 뒤 보관한 get/put 및 명시적 두 번째 get Promise를 늦게 resolve/reject하고 결과가 관측되는지 검사한다. 성공을 조기 확정하지 않고 실패를 삼키지 않으며 unhandled rejection이 없다. 실시간 2초 대기를 쓰거나 #139 타이머 정책을 구현하지 않는다.
  • 검증 명령: 구현 환경 의존성 준비 후 npm test -- worker/lib/tts/storage.test.ts, 이어 npm test, npm run lint, npm run build. 테스트 구성·패키지·lockfile 변경은 필요하지 않다.
  • 계획 단계 검증: 파일/계약/선행 커밋·이슈 본문/댓글·공식 R2 문서 대조, HTML placeholder·필수 섹션·링크·localhost HTTP·cmux 표시·SHA256 검증만 수행한다. 소스 변경 전 test/lint/build는 실행하지 않았다.
  • 후속 미검증: 실제 R2 접근·공개 차단·경합, validateMp3 실제 결합, 제공자 연결·청취·모바일·운영 latency. 더블 통과로 대체하지 않는다. 유료 TTS·리소스 생성·배포 없이 TTS 비활성 상태를 유지한다.

7구현·검증 기록

  • 구현: storage.ts에 비밀 없는 SHA-256 키, bounded R2 조회, 검증 후 If-None-Match: * 조건부 저장을 추가했다. 조회 null·손상·R2 실패와 saved·conflict·put 실패를 서로 축약하지 않는다.
  • 집중 테스트: npm test -- worker/lib/tts/storage.test.ts — 1 파일, 10 테스트 통과.
  • 전체 검증: npm test — 38 파일, 485 테스트 통과; npm run lint 통과; npm run build 통과.
  • 미검증: 실제 비공개 R2 바인딩/권한, 실제 MP3 검사기 연결, 제공자 호출·배포는 수행하지 않았다. TTS_ENABLED와 Wrangler 설정은 변경하지 않았다.

8완료 조건

  • 동일 정규화 내용·설정은 세션·기기와 무관한 키이며 프로필/시트/B열/음성 설정 변경은 키를 바꾼다. 다른 탭의 같은 내용은 재사용한다. (AC-12·13·19·23·24의 저장 경계)
  • 정상 get null만 미존재로 반환한다. 조회 실패·손상·검사기 실패가 호출부에 전달된다. (AC-20)
  • 검증된 MP3만 조건부 저장하며 saved/conflict/reject를 구분한다. 기존 객체를 덮어쓰지 않는다. (AC-21·22)
  • 외부 대기 종료 후에도 원래 저장 연산 Promise와 get Promise를 호출부가 관측한다. 내부 deadline·재조회·waitUntil 정책은 #139에 남긴다.
