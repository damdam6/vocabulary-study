모드2 채점이 대소문자·공백 차이로 오답 처리 — 느슨 채점 도입

damdam6/vocabulary-study 브랜치 feat/123-mode2-loose-grading ← main 라벨 enhancement 2026-07-30

1요약

모드2 채점(gradeMode2)은 트림 후 정확 일치만 보므로 영어 등 generic 콘텐츠에서 Apple/apple, 내부 공백 2칸, NFC/NFD 표기 차이가 전부 오답이 된다. 비교 직전에 입력과 정답 양쪽에 동일한 정규화(NFC → 소문자화 → 트림+내부 공백 축약)를 적용해 의미상 같은 답을 정답 처리한다. 콘텐츠 타입 분기 없이 전 프로필 공통이며, 한자에는 대소문자·공백 개념이 없어 zh 동작은 사실상 불변이다. "느슨 채점 보류"를 명시한 PRD 문구 3곳도 이번 결정으로 개정한다.

2현황 분석

모드2 채점 경로는 단일 지점이다:

  • src/lib/studySession.ts:34-37 — gradeMode2(input, hanzi): const answer = input.trim(); return { correct: answer !== "" && answer === hanzi, answer }. 트림 외 어떤 정규화도 없다.
  • src/screens/Mode2Card.tsx:29 — 유일한 호출처. 제출 시 gradeMode2(value, word.hanzi)를 부르고, 오답이면 반환된 answer(트림된 원입력)를 wrongAnswer로 저장해 결과 화면의 "내 답" 취소선 표시(Mode2Card.tsx:46-50)에 그대로 쓴다.
  • 기존 테스트 src/lib/studySession.test.ts:44-69 — 정확 일치·트림·빈 입력·병음·부분 일치·이체자 케이스가 고정돼 있다. 모두 zh 케이스라 느슨 채점 도입 후에도 판정이 바뀌지 않는다.
  • 문서 3곳이 "느슨 채점 도입 안 함"을 못박고 있다: docs/PRD.md §5.2(3번 단계 "정확 일치"), docs/PRD-general.md:104(§4.2)와 docs/PRD-general.md:202(Q6 — "generic + 모드 2를 실제로 쓰게 되면 재론"), docs/design-prd.md:109(§4.3 채점 줄). 이슈가 바로 그 재론 시점을 선언했다.

3설계

  • 정규화 함수: studySession.ts에 내부 헬퍼로 normalize("NFC") → toLowerCase() → trim() + replace(/\s+/g, " ")를 순서대로 적용하는 함수를 두고, gradeMode2가 입력과 표제어 양쪽에 동일하게 적용한 값으로 비교한다.
  • 반환값 불변: answer는 기존대로 트림된 원입력을 유지한다 — 정규화 값은 비교에만 쓰고, "내 답" 표시(Mode2Card.tsx)는 사용자가 친 표기를 보존한다. 호출부 시그니처 변경 없음.
  • 빈 입력 규칙 유지: 트림 결과가 빈 문자열이면 오답 — 기존 answer !== "" 조건을 그대로 둔다.
  • 분기 없음: contentType을 받지 않는다. 한자는 대소문자·연속 공백이 실질적으로 없고 NFC 정규화는 무해해서 zh 판정 결과가 달라질 입력이 사실상 없다 (기존 테스트가 회귀 방지로 그대로 증명).
  • 기각한 대안 — generic 전용 분기: 채점기가 contentType을 알아야 해 호출 계약이 넓어지는데, zh에 느슨 채점을 적용해도 동작이 변하지 않으므로 분기의 실익이 없다 (이슈도 "분기 없음"을 명시).

4작업 단계

  1. 「구현」 gradeMode2에 느슨 채점 도입 — NFC·소문자화·공백 정규화(트림+내부 연속 공백 1개화)를 입력·표제어 양쪽에 적용하는 내부 헬퍼를 추가하고 비교식을 교체. answer 반환은 트림 원입력 유지, 빈 입력 오답 유지. 함수 주석의 "정확 일치" 서술을 #123 느슨 채점 규칙으로 갱신. src/lib/studySession.ts
  2. 「테스트」 느슨 채점 케이스 추가 — Apple/apple(대소문자), ice  cream/ice cream(내부 공백 축약), NFD 입력/NFC 정답 쌍("café".normalize("NFD") 형태), 그리고 오답 시 answer가 트림 원입력(대소문자 보존)임을 고정. 기존 zh 케이스(병음·부분 일치·이체자·빈 입력)는 그대로 통과해야 한다. src/lib/studySession.test.ts
  3. 「문서」 "느슨 채점 도입 안 함" 문구 3곳 개정 — PRD §5.2 채점 단계를 정규화 후 비교로 갱신, PRD-general §4.2·Q6에 재론 결과(#123 도입) 기록, design-prd §4.3 채점 줄 갱신. docs/PRD.md, docs/PRD-general.md, docs/design-prd.md
  4. 「검증」 전체 테스트·빌드 — npm test(vitest run)와 npm run build(tsc -b + vite build), npm run lint(oxlint) 통과 확인. package.json scripts 참고: 워크트리 node_modules에 jsdom이 빠져 있어 pnpm install 선행 — 이후 32파일 421테스트 전부 통과, 빌드·린트 그린.

5리스크

리스크영향완화책
느슨 채점이 zh 판정을 바꿀 가능성 한자 오답이 정답 처리되면 학습 기록 오염 한자에는 대소문자·연속 공백이 없고 NFC는 무해 — 기존 zh 테스트(병음·부분 일치·이체자) 전부 유지로 회귀 고정
toLowerCase()의 로케일 특수 케이스 (터키어 İ 등) 특정 언어 표제어에서 예상 밖 판정 현재 콘텐츠는 zh·영어뿐이라 실사용 영향 없음 — 로케일 민감 비교(localeCompare)는 과설계로 도입하지 않음

6테스트 계획

  • npm test — 신규 케이스: gradeMode2("Apple", "apple") 정답, gradeMode2("ice cream", "ice cream") 정답, NFD 입력 vs NFC 정답 정답, 오답 시 answer가 트림 원입력 그대로인지.
  • npm test — 기존 회귀: zh 정확 일치·트림·빈 입력·병음·부분 일치·이체자 케이스 전부 통과 (느슨 채점이 zh 판정을 바꾸지 않음을 증명).
  • npm run build + npm run lint — 타입·린트 통과.

7완료 조건

  • gradeMode2가 NFC·소문자화·공백 정규화 후 비교하며, 정규화는 입력·정답 양쪽에 동일 적용된다
  • Apple/apple, ice  cream/ice cream, NFC/NFD 쌍이 정답 처리되는 테스트가 studySession.test.ts에 추가되고 통과한다
  • 오답 결과 화면의 "내 답"은 트림된 원래 입력 그대로 표시된다 (정규화 값은 비교 전용)
  • 빈 입력 = 오답 규칙과 기존 zh 채점 테스트가 전부 유지·통과한다
  • PRD·PRD-general·design-prd의 "느슨 채점 보류" 문구가 #123 결정으로 개정된다
