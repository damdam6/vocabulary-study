#72리팩토링 (동작 불변)

Sheets 접근 sheetId 파라미터화 — env.SHEET_ID 직접 참조 제거

damdam6/vocabulary-study 브랜치 feat/72-sheets-sheetid-parameterization ← main 라벨 enhancement 2026-07-26

1요약

멀티 프로필 범용화(PRD-general §5·§6, docs/plans/service-generalization.md 작업 2 전반부)의 선행 작업. worker/lib/sheets.ts의 모든 Sheets API 래퍼와 worker/lib/words.ts의 헬퍼가 URL 조립에 env.SHEET_ID를 암묵적으로 읽는 대신 sheetId를 명시 인자로 받도록 바꾼다. 토큰 발급(google-auth.ts)은 프로필 공용이므로 env를 그대로 쓴다. 이 이슈 범위에서 모든 호출부는 env.SHEET_ID를 그대로 넘겨 관측 가능한 동작 변화는 없다 — 프로필의 sheetId 주입은 후속 이슈(#70·#71 계열).

2현황 분석

sheets.ts — 전 함수가 내부 sheetsFetch를 거치고, 이 함수가 URL을 직접 조립한다:

  • worker/lib/sheets.ts:128 — sheetsFetch가 fetch(`${API_BASE}/${env.SHEET_ID}${path}`, ...)로 시트 ID를 URL에 하드코딩.
  • 공개 함수 6개가 전부 env만 받고 그대로 sheetsFetch에 전달: getValues(sheets.ts:39), getSheetTitles(:46), addSheet(:56), updateValues(:63), batchUpdateValues(:82), appendValues(:95).

words.ts — sheets.ts 함수를 감싸는 3개 헬퍼가 env만 전달:

  • getWordTabTitles(worker/lib/words.ts:12) → getSheetTitles(env)
  • findWordRow(:51) → getValues(env, tab, WORD_ROW_RANGE)
  • findRowNumber(:73) → getValues(env, tab, "A2:A")
  • parseWordRow는 순수 파서라 env를 아예 쓰지 않음 — 변경 불필요.

호출부(라우트) 13곳 — 전부 env만 넘기고 있어, 파라미터화 후에는 env.SHEET_ID를 명시 인자로 추가 주입해야 한다:

  • worker/routes/words.ts:11,14 — getWordTabTitles(env), getValues(env, tab, WORD_ROW_RANGE)
  • worker/routes/review-fail.ts:39,49 — findWordRow(env, body.tab, body.hanzi), updateValues(env, body.tab, ...)
  • worker/routes/register.ts:46,60,61,62,68,77 — getWordTabTitles·getValues·addSheet·updateValues 6회 호출
  • worker/routes/tabs.ts:6 — getWordTabTitles(env)
  • worker/routes/answer.ts:54,59,74 — findRowNumber·getValues·batchUpdateValues

테스트 — worker/routes/register.test.ts·tabs.test.ts는 env = { APP_PASSWORD, SHEET_ID }를 만들어 worker.fetch(req, env)로 라우트 전체를 통과시키고 전역 fetch를 모킹한다 — sheets.ts/words.ts 함수를 직접 호출하지 않으므로, 호출부 시그니처만 맞추면 테스트 코드 자체는 변경 불필요(회귀만 확인).

3설계

채택: sheetId: string을 모든 함수에 두 번째 위치 인자로 추가 — (env, sheetId, ...나머지). env는 자리를 유지(토큰 발급용), sheetId가 그 뒤를 잇는다. 근원은 sheetsFetch(env, sheetId, method, path, body?)이고 6개 공개 함수가 각자 받은 sheetId를 그대로 전파한다. words.ts의 3개 헬퍼도 동일하게 sheetId를 받아 sheets.ts 호출에 전파한다.

호출부는 이 이슈에서 전부 env.SHEET_ID를 그대로 새 인자 자리에 주입한다 — 동작 불변.

기각한 대안:

  • env 변조({ ...env, SHEET_ID: profile.sheetId } 재주입) — service-generalization.md §비교표에서도 기각: 타입이 거짓말을 하고("env인데 사실 다른 시트"), 프로필 격리를 "sheetId가 항상 명시 인자"라는 정적 보장으로 검증할 수 없게 됨.
  • 프로필 바인딩 클래스/컨텍스트 객체로 sheetId를 감싸기 — 현재 규모(순수 함수 9개)에 과한 추상화. 이슈 범위(동작 불변, 단독 머지)를 넘어서는 설계 결정이라 후속 프로필 스레딩 이슈로 미룸.
  • sheetId를 첫 인자로 두고 env를 뒤로 — env가 여전히 토큰 발급의 1차 의존성이고, 기존 코드베이스 전반에서 env-first 관례를 따르는 함수가 많아 시그니처 훑어보기 일관성을 위해 기각.

4작업 단계

  1. sheetsFetch 시그니처에 sheetId: string을 두 번째 인자로 추가하고, URL 조립을 env.SHEET_ID에서 sheetId로 변경. worker/lib/sheets.ts:121-140
  2. 공개 함수 6개(getValues·getSheetTitles·addSheet·updateValues·batchUpdateValues·appendValues) 각각에 sheetId: string 두 번째 인자를 추가하고 내부 sheetsFetch 호출에 전파. env.SHEET_ID 직접 참조가 파일에 남지 않는지 확인. worker/lib/sheets.ts:39-108
  3. getWordTabTitles·findWordRow·findRowNumber에 sheetId: string 인자를 추가하고 각각의 sheets.ts 호출(getSheetTitles·getValues)에 전파. parseWordRow·parseNextReview는 손대지 않음. worker/lib/words.ts:12-15, :51-67, :73-86
  4. worker/routes/words.ts 호출부 2곳에 env.SHEET_ID를 새 인자로 주입. worker/routes/words.ts:11, :14
  5. worker/routes/review-fail.ts 호출부 2곳(findWordRow·updateValues)에 env.SHEET_ID 주입. worker/routes/review-fail.ts:39, :49
  6. worker/routes/register.ts 호출부 6곳(getWordTabTitles·getValues×2·addSheet·updateValues×2)에 env.SHEET_ID 주입. worker/routes/register.ts:46, :60-62, :68, :77
  7. worker/routes/tabs.ts의 getWordTabTitles 호출에 env.SHEET_ID 주입. worker/routes/tabs.ts:6
  8. worker/routes/answer.ts 호출부 3곳(findRowNumber·getValues·batchUpdateValues)에 env.SHEET_ID 주입. worker/routes/answer.ts:54, :59, :74
  9. grep -rn "env\.SHEET_ID" worker/lib/sheets.ts worker/lib/words.ts로 두 파일에 직접 참조가 남지 않았는지 확인 (완료 조건 1). worker/lib/sheets.ts, worker/lib/words.ts
  10. 전체 테스트(npm run test)·lint(npm run lint)·타입 체크(tsc -b) 실행, 회귀 없음 확인. worker/index.test.ts, worker/routes/register.test.ts, worker/routes/tabs.test.ts, worker/lib/register.test.ts

5리스크

리스크영향완화책
호출부 13곳 중 하나라도 sheetId 주입을 빠뜨림 해당 경로만 undefined sheetId로 API 호출 → 400, 발견이 늦을 수 있음 TypeScript가 필수 인자 누락을 컴파일 타임에 잡음(선택 인자로 만들지 않음) + 8단계 grep으로 이중 확인
인자 순서 변경(env, sheetId, ...)이 기존 호출부와 안 맞아 타입 에러가 대량 발생 1회성 리팩토링 범위가 커 보일 수 있음 실제로는 각 호출부가 인자 하나만 추가하는 기계적 변경 — 컴파일러가 안 맞는 곳을 전부 지목해줌
동작 변화 없음이 전제인데 테스트가 sheetId 값 자체를 검증하지 않아 회귀를 놓칠 가능성 낮음 — 이번 이슈에서 sheetId 값은 항상 env.SHEET_ID로 동일 기존 테스트가 통과하면 모킹된 fetch가 받는 URL도 기존과 동일 (sheetId 값 자체가 안 바뀜)

6테스트 계획

  • npm run test — 전체 vitest 스위트(worker/index.test.ts, worker/routes/register.test.ts, worker/routes/tabs.test.ts, worker/lib/register.test.ts)가 기존과 동일하게 통과. 라우트 핸들러 경유 테스트라 시그니처 변경이 잘못되면 즉시 실패로 드러남.
  • npm run lint — oxlint 통과, 사용하지 않는 인자·미사용 import 없음.
  • tsc -b (또는 npm run build의 타입 체크 단계) — 새 필수 인자 sheetId가 호출부 13곳에 정확히 주입됐는지 컴파일러가 검증.
  • grep -rn "env\.SHEET_ID" worker/lib/sheets.ts worker/lib/words.ts — 결과 없음 확인 (완료 조건 1의 직접 근거).
