1요약

#172 PRD §4의 중국어 모드2 채점을 현재 공통 정규화에서 콘텐츠 타입별 계약으로 분리한다. zh에서는 NFC·소문자화·공백 제거 뒤 PRD에 고정된 문장부호만 제거하고, 숫자 사이의 마침표·쉼표와 의미를 바꿀 수 있는 기호는 보존한다. generic의 기존 채점은 유지하며, 판정 결과의 사용자 입력과 기록·재시도·시트 행 키는 채점 정규화와 독립된 원문을 사용하도록 회귀를 고정한다.

2현황 분석

  • 상위 #172 본문은 #175를 SENT-03으로 정의하고 #173 병합 후 시작하도록 하며, #176이 직접 후속임을 명시한다. #172와 #175 모두 댓글은 없었다. 현재 브랜치 HEAD는 병합된 #173/#174 이후 main을 기반으로 한다.
  • src/lib/studySession.ts:29-37의 normalizeForGrading은 모든 콘텐츠에 NFC·소문자화·\s+ 제거를 적용한다. src/lib/studySession.ts:49-55의 gradeMode2(input, hanzi)는 콘텐츠 타입을 받지 않고, 빈 문자열만 막은 뒤 동일 정규화 결과를 비교하며 반환 답을 input.trim()으로 잘라낸다.
  • src/screens/Mode2Card.tsx:24-35는 이미 프로필의 contentType을 받지만, src/screens/Mode2Card.tsx:55-65에서 gradeMode2(value, word.hanzi)만 호출한다. 따라서 화면 경계에서 타입 정보가 소실되어 zh 전용 부호 규칙을 선택할 수 없다. 오답 공개는 src/screens/Mode2Card.tsx:68-99에서 반환된 답을 그대로 “내 답”에 렌더링한다.
  • src/screens/StudyScreen.tsx:79-95는 정답 effect에서 word.tab·word.hanzi를 AnswerRecord와 review-fail 요청에 그대로 복사한다. src/lib/api.ts:151-188는 이 필드를 JSON으로 직렬화하고, src/lib/retryQueue.ts:25-27,68-85,102-139는 record를 원래 형태로 저장·FIFO 재전송한다.
  • Worker도 채점 결과를 전달받아 정규화하지 않는다. worker/routes/answer.ts:64-97는 요청의 tab·hanzi로 행을 찾고 현재 행의 원문을 응답하며, worker/lib/words.ts:49-95의 행 탐색은 A열 문자열을 정확히 비교한다. review-fail도 worker/routes/review-fail.ts:44-56에서 같은 원문 키로 F열만 갱신한다.
  • 기존 회귀 기준은 src/lib/studySession.test.ts:44-109에 generic·공백·NFC·빈 입력이 있고, src/lib/api.test.ts:233-297와 src/lib/retryQueue.test.ts:181-227에 API/재시도 payload 검사가 있다. Worker 응답·원문 보존은 worker/routes/answer.test.ts:168-287와 worker/routes/words.test.ts:189-196에서 검증된다.

3원인 분석

직접 원인: 채점 정규화 함수가 콘텐츠 타입을 인자로 받지 않아 문장용 부호 정책과 기존 generic 정책을 분리할 수 없다. 여기에 결과 표시용 answer를 trim()으로 만들고 있어 입력 원문 보존 계약도 깨진다.

  • 버그 재현 근거: 현재 구현은 你好，世界！와 你好, 世界!의 ASCII/전각 부호 차이를 판정하지 못하고, 我有2本书。와 我有3本书 같은 숫자 차이는 유지해야 하는 별도 규칙을 표현하지 못한다. src/lib/studySession.test.ts:70-104의 기존 테스트는 generic/공백/NFC만 다루며 PRD의 숫자·기호 경계를 고정하지 않는다.
  • 원문 손실 근거: gradeMode2가 반환하는 답은 input.trim()이므로 사용자가 앞뒤 공백을 포함해 입력한 오답 원문이 결과 화면에서 바뀐다. 이 값은 Mode2Card의 wrongAnswer로 바로 전달된다.
  • 대안 배제: 모든 Unicode punctuation을 제거하면 PRD가 보존하라고 한 -, —, ·, /, %, +, =, ．까지 삭제되어 숫자·기호 의미가 바뀐다. NFKC로 전각을 일괄 변환하면 전각 숫자·영문을 반각과 자동 동치로 만드는 범위 밖 동작이 된다. 따라서 고정 제거 목록과 숫자 사이 ./, 보존 조건을 명시적으로 스캔한다.
  • 설계 경계: 정규화는 판정 비교에만 사용하고, 반환 답·AnswerRecord·retry record·Worker 행 키에는 적용하지 않는다. zh의 정규화 결과 또는 원문이 비면 오답이며, generic은 현재 NFC·소문자화·공백 제거를 그대로 유지한다.

4작업 단계

  1. src/lib/studySession.tsgradeMode2에 ContentType을 명시적으로 받고 generic 분기는 기존 동작을 보존한다. zh 분기는 NFC→소문자화→모든 공백 제거 후 PRD §4의 고정 문장부호만 제거하며, ASCII/전각 숫자 사이의 ASCII 마침표·쉼표는 보존한다. -, —, ·, /, %, +, =, ．는 무조건 삭제하지 않는다. 비교 전 양쪽의 원문과 정규화 결과가 비었는지 확인하고 answer에는 input 원문을 그대로 반환한다.
  2. src/screens/Mode2Card.tsx, src/screens/StudyScreen.tsxMode2Card의 기존 contentType prop을 gradeMode2(value, word.hanzi, contentType) 호출에 전달한다. StudyScreen은 이미 profile.contentType을 카드에 전달하므로 별도 상태 저장·새 필드·새 퀴즈 모드를 만들지 않는다. 오답 결과는 raw answer를 표시하고 정답/다음 진행과 발음 공개 타이밍은 유지한다.
  3. src/lib/studySession.test.ts모든 호출에 zh/generic 타입을 명시한다. 문장부호 생략, 전각·반각 부호, 내부/앞뒤 공백, 我不喜欢咖啡。의 부정어 누락, 숫자 누락, 어순 변경, 3.5/3,500, 5%/5, 기호 + - / = · — ． 보존, 。？！만 입력한 빈 정규화 결과를 고정한다. generic에서 hello!와 hello가 여전히 오답인지 확인하고 NFD/NFC 기존 회귀도 유지한다. 별도 assertion으로 raw answer의 앞뒤 공백·문장부호가 보존되는지 확인한다.
  4. src/screens/Mode2Card.test.tsx, src/screens/StudyScreen.test.tsx, src/lib/api.test.tszh 카드가 타입별 채점 결과를 사용하고 오답 결과의 “내 답”이 사용자가 입력한 원문과 일치하는지 확인한다. 문장 탭과 我有2本书。를 사용해 정답 effect가 tab+hanzi를 그대로 /api/answer로 보내며 기존 mode/isReview/timestamp 계약도 유지하는지 검사한다. review-fail payload도 동일한 원문 키를 보존한다.
  5. src/lib/retryQueue.test.ts, worker/routes/answer.test.ts, worker/routes/review-fail.test.ts, worker/lib/words.ts문장부호·숫자·공백이 포함된 answer/review-fail record를 enqueue→저장→FIFO 재전송했을 때 JSON body가 변하지 않는지 확인한다. Worker는 정규화된 값이 아니라 요청의 정확한 tab+hanzi로 A열을 찾고 시트 갱신 범위와 응답의 hanzi가 원문을 유지하는지 검증한다. 기존 production 경로가 이미 정확 비교를 사용하므로 worker/lib/words.ts는 변경하지 않고 새 라우트 회귀 테스트로 고정했다.
  6. docs/plans/issue-175-chinese-sentence-grading.html, 위 소스·테스트 파일관련 단위/컴포넌트/Worker 테스트 후 npm test, npm run build, npm run lint를 실행했다. 공유 상위 node_modules/.vite-temp의 최초 EPERM은 권한 확장 실행으로 해결했고 실제 테스트 결과는 모두 성공했다. 실제 Sheets/TTS/배포는 수행하지 않았다.

5리스크

리스크영향완화책
Unicode 문장부호를 넓게 제거함숫자·부호가 포함된 문장의 의미가 바뀌거나 오답이 정답이 된다.PRD의 고정 목록을 상수화하고 숫자 사이 ./, 보존·보존 기호 회귀를 각각 테스트한다.
zh 규칙이 generic에 전파됨기존 영어·한국어 등 generic의 punctuation 채점 계약이 바뀐다.ContentType 분기를 채점 경계에 명시하고 generic 기존 테스트를 모두 유지한다.
정규화 결과를 기록 키에 재사용함문장부호가 있는 실제 A열 행을 찾지 못하거나 다른 행을 갱신할 수 있다.정규화는 boolean 판정 전용으로 제한하고 StudyScreen·API·retry·Worker exact-key payload 테스트를 추가한다.
빈/부호만 입력을 비어 있지 않은 정답으로 취급함문장부호만 입력한 오답이 정답으로 처리된다.입력과 정답 양쪽 normalized-empty guard 및 。？！ 회귀를 둔다.
raw answer 변경으로 UI 결과가 예상과 달라짐앞뒤 공백이 있는 오답 표시의 접근성·레이아웃이 흔들릴 수 있다.Mode2Card에서 raw text를 한 번 검증하고 기존 빈 입력 처리·취소선 결과·긴 문자열 표시 테스트를 유지한다.
테스트 실행 환경이 공유 상위 node_modules를 씀구현과 무관한 Vite 캐시 권한 오류로 검증이 막힐 수 있다.작업 환경의 쓰기 가능한 캐시/로그 경로를 사용해 재실행하고 해결하지 못한 경우 실제 코드 실패와 환경 제한을 분리 기록한다.

6테스트 계획

  • 순수 함수: src/lib/studySession.test.ts에서 PRD 표의 7개 사례를 포함해 문장부호 생략/전각·반각, 공백, 숫자·부정어·어순 차이를 검증한다. 3.5↔35, 5%↔5, +/-/=//·—와 전각 ％＋＝／． 경계를 포함한다.
  • 콘텐츠 타입: zh의 부호 완화와 generic의 기존 strict punctuation 동작을 같은 테스트 묶음에서 비교한다. NFC/NFD, 소문자화, 공백 제거, 빈 문자열·공백만·부호만 입력을 회귀한다.
  • 원문 표시: src/screens/Mode2Card.test.tsx에서 오답 입력의 앞뒤 공백·문장부호가 “내 답”에 그대로 남는지, 빈 입력은 기존처럼 숨겨지는지 확인한다. 기존 TTS/초점/긴 결과 테스트는 유지한다.
  • 기록과 재시도: src/screens/StudyScreen.test.tsx, src/lib/api.test.ts, src/lib/retryQueue.test.ts에서 tab: "문장", hanzi: "我有2本书。" 같은 원문이 answer/review-fail 요청·저장·재전송에서 byte-for-byte로 보존되는지 확인한다. 최초 timestamp와 profile 태깅·FIFO/실패 보존도 유지한다.
  • 시트 갱신: worker/routes/answer.test.ts와 필요한 worker/routes/review-fail.test.ts에서 exact A열 문장 키가 올바른 행의 D/E/F/G를 갱신하고 응답에 원문을 반환하는지 확인한다. 기존 단어 행·탭 분리·활성 모드 검증을 회귀한다.
  • 명령: 구현 후 npm test, npm run build, npm run lint와 관련 파일의 선택 테스트를 실행한다. 계획 단계의 baseline 선택 테스트는 공유 상위 node_modules/.vite-temp 쓰기 권한 EPERM으로 시작하지 못했으므로 이를 코드 실패로 집계하지 않고 구현 세션에서 쓰기 가능한 설정으로 재실행한다.
  • 범위 제한: 실제 Google Sheets 쓰기, 유료 TTS 합성, 배포, 모바일 시각 검증은 이 이슈에서 수행하지 않는다. TTS 원문·긴 화면은 각각 #177·#176 범위로 넘기고, 여기서는 채점 경계와 기록 키 계약만 검증한다.

7완료 조건

  • 채점 호출이 프로필 contentType을 전달하고 zh에만 PRD §4의 고정 부호 제거 규칙을 적용한다.
  • 숫자 사이 마침표·쉼표와 %, +, -, /, =, ·, 전각 대응 기호를 보존하며 Unicode punctuation 전체 제거를 사용하지 않는다.
  • 문장부호 생략·전각/반각 차이와 공백은 허용하지만 한자·숫자·부정어·어순 차이는 오답이고, 빈 정규화 결과·부호만 입력도 오답이다.
  • generic의 기존 NFC·소문자화·공백 제거 채점을 변경하지 않는다.
  • 오답 결과의 “내 답”은 사용자 원문을 보존하고, 정답 API·review-fail·재시도 큐·시트 갱신에는 원래 tab+hanzi를 전달한다.
  • PRD 채점 예시, 단어/generic/숫자 경계와 회귀 테스트가 추가되고 npm test·npm run build·npm run lint 결과가 기록된다.
  • 구현과 ready PR 생성을 완료하고, 독립 Grok 리뷰와 병합은 오케스트레이터 단계로 남긴다.
