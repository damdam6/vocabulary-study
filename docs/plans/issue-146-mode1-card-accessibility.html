3설계

구조와 접근성 상태

  • div.flip-card를 transform을 소유하는 비대화형 래퍼로 두고, 앞면은 명시적 button.flip-face, 뒷면은 내용 영역인 div.flip-face--back으로 분리한다. 두 요소가 형제이므로 후속 이슈가 뒷면에 버튼을 넣어도 중첩 제어가 생기지 않는다.
  • revealed는 플립 시작과 O/X 즉시 노출을, viewReady는 답 영역의 접근성 공개를 뜻한다. 공개 전/전환 중 뒷면에는 aria-hidden과 inert를 적용하고, 공개 후 앞면은 반대로 접근성·키보드 탐색에서 제외한다. CSS backface-visibility는 시각 효과만 담당한다.
  • 공개 버튼에 초점이 있던 키보드 흐름만 기억하고 완료 시 첫 판정 버튼으로 옮긴다. 사용자가 전환 중 종료나 이미 나타난 O/X 등 다른 제어로 초점을 옮겼으면 현재 activeElement를 확인해 빼앗지 않는다. #147은 발음 버튼이 가능할 때 목적지만 확장하고 이 게이트 계산을 재구현하지 않는다.

일회성 완료 게이트

  • transform 래퍼의 onTransitionEnd는 event.target === event.currentTarget 및 propertyName === "transform"일 때만 완료 함수를 호출한다. 완료 함수는 ref 기반 일회성 가드로 중복 event와 fallback 경합을 흡수한다.
  • 플립 클래스가 DOM에 반영된 뒤 getComputedStyle의 comma-separated transition property/duration/delay 목록을 CSS 반복 규칙에 맞춰 읽고, transform 또는 all 항목의 최대 duration+delay에 100ms를 더해 fallback을 예약한다. 계산값이 0 이하이거나 prefers-reduced-motion: reduce이면 뒷면 렌더 뒤 즉시 같은 완료 게이트를 통과시킨다.
  • fallback ID는 ref로 소유하고 완료·판정·effect cleanup에서 해제한다. 빠른 O/X가 먼저 실행되면 게이트도 닫아 늦은 event/timer가 focus나 상태를 바꾸지 못하게 한다.

레이아웃

  • 기존 3D transform·앞면 크기 스케일·공용 뒷면 타이포그래피는 유지한다. 뒷면에 폭 축소 허용, 긴 단어 wrapping, 세로 overflow를 명시해 200자 표제어와 긴 병음이 카드 내부에서 스크롤되게 한다.
  • .flip-stage와 .judge-zone의 flex 경계를 유지해 카드가 늘어날 때 O/X 영역을 밀어내지 않도록 한다. reduced motion media query에서는 transform transition을 제거해 JS의 0초 경로와 시각 동작을 일치시킨다.

기각한 대안: 고정 550ms timer는 CSS 변경과 어긋나고 delay를 무시하므로 사용하지 않는다. transitionend만 의존하면 event 유실·0초 전환에서 영원히 준비되지 않으므로 fallback을 둔다. 답 DOM을 viewReady 때 처음 마운트하면 플립 중 뒷면 시각이 비므로, DOM은 유지하되 접근성 속성으로 비활성화한다. 공용 StudyScreen에 타이밍 상태를 올리는 것은 카드 DOM/CSS와 한 몸인 책임을 불필요하게 확산하므로 피한다.

5리스크

리스크영향완화책
브라우저별 transition 목록·event 차이높음 — 답이 영구 비공개거나 두 번 완료될 수 있음target/property 필터, 목록 반복 규칙 기반 최대 시간, +100ms fallback, ref 일회성 게이트를 각각 테스트한다.
inert와 aria-hidden 상태가 시각 플립과 어긋남높음 — 공개 전 답 노출 또는 공개 후 탐색 불가앞/뒤 상태 행렬을 DOM 단언으로 고정하고, 시각용 backface와 접근성 속성의 역할을 분리한다.
늦은 완료가 사용자 초점을 빼앗음중간 — 종료/OX 키보드 흐름 방해공개 시 초점 출처를 기록하되 완료 시 현재 activeElement를 다시 검사하고, 빠른 판정에서 게이트를 닫는다.
긴 콘텐츠 overflow가 판정 영역을 가리거나 모드2 공용 타이포에 파급중간 — 200자/확대 화면에서 판정 불가모드1 뒷면에만 스크롤·wrapping을 한정하고 judge zone을 비수축 영역으로 유지한다. 실제 390px/200% 확대는 출시 QA로 명시한다.
React StrictMode/effect cleanup에서 timer가 중복됨중간 — 경고·늦은 setState·초점 이동effect마다 이전 timer를 먼저 정리하고 unmount 및 판정 cleanup을 fake timer의 pending count로 검증한다.
후속 #145/#147의 발음 binding과 구조 충돌중간 — 타이밍 계산 중복 또는 다시 DOM 재작성뒷면 제어 슬롯과 내부 viewReady 완료 지점을 명확히 만들고, 발음 prop/API 자체는 후속 소유 범위로 남긴다.

6테스트 계획

  • src/screens/Mode1Card.test.tsx 구조: 전체 카드가 button이 아니고 앞면 공개 버튼과 뒷면 영역이 형제이며 button button이 없다. 공개 전 뒷면은 aria-hidden/inert, 앞면은 접근·활성 가능하고 공개 완료 뒤 상태가 반전된다.
  • transition 필터: 자식에서 버블된 event와 다른 property는 무시하고, 래퍼의 transform event만 완료한다. 같은 event 반복과 fallback 경합에도 접근성 상태 전환은 한 번뿐이다.
  • fake timer: 예시 duration/delay 조합의 최대값+100ms 전에는 준비되지 않고 이후 완료된다. 0초 및 reduced motion은 즉시 완료하며, 정상 완료·빠른 O/X·unmount 뒤 timer가 남지 않는다.
  • 초점: 키보드 공개 버튼에 남은 초점은 viewReady 뒤 첫 판정 버튼으로 이동한다. 전환 중 종료 버튼 또는 이미 노출된 판정 버튼으로 옮긴 초점은 유지한다.
  • 판정 회귀: reveal 직후 transition 완료 전에도 X/O가 각각 onJudged(false/true)를 정확히 한 번 호출한다. generic에서도 고정 크기·언어 규칙·플립·판정이 유지되고 TTS/Audio 호출은 존재하지 않는다.
  • 긴 fixture: 코드 포인트 200개 표제어와 긴 병음/뜻이 손실 없이 뒷면에 렌더되고 모드1 전용 scroll/wrap class를 사용하며 판정 영역은 별도 형제로 유지된다. jsdom이 실제 레이아웃을 계산하지 못하므로 390px/200% 시각 확인은 출시 검증으로 남긴다.
  • 검증 명령: 관련 npm test -- src/screens/Mode1Card.test.tsx 후 npm test, npm run lint, npm run build. 실제 키·청취·음성 API·모바일 실기기 결과로 오인하지 않고, 이 이슈는 음성 더블 없이 독립 검증한다.

7완료 조건

  • 비대화형 플립 래퍼와 앞면 공개 버튼·뒷면 내용 영역이 분리되어 중첩 button이 없고, 후속 뒷면 제어를 위한 합법적인 구조가 확보된다.
  • 공개 전과 플립 중 답 영역은 접근성 트리·키보드 탐색에서 숨겨지고, viewReady 뒤에만 공개된다.
  • transform event 필터와 계산 시간+100ms fallback이 같은 일회성 게이트를 사용해 event 중복·유실·reduced motion·0초 전환을 모두 처리한다.
  • 공개 버튼에 있던 키보드 초점만 viewReady 뒤 첫 판정 제어로 이동하고, 사용자가 다른 곳으로 옮긴 초점은 빼앗지 않는다.
  • O/X는 공개 직후 사용할 수 있고 판정·기록·다음 문제 진행을 기다리지 않는다. 빠른 판정과 unmount 후 timer·늦은 상태 변경이 없다.
  • zh와 generic의 기존 플립·표시·판정이 유지되며, 200자 표제어와 긴 병음은 wrapping/카드 내부 스크롤을 사용하고 판정 영역은 보존된다.
  • 음성 요청·자동재생·스피커·Audio·모드2 CSS를 추가하지 않으며, 구조와 공개 완료 동작을 jsdom/fake timer만으로 검증할 수 있다.
  • 관련 테스트와 전체 npm test, npm run lint, npm run build가 통과하고, 실제 390px/200% 확대는 출시 검증 미확인 항목으로 기록한다.
