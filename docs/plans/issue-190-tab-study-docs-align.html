1요약

#188·#189로 탭 선택 학습(전체 또는 탭 n개 범위로 큐 구성)이 구현됐지만, 기능 PRD와 디자인 PRD는 여전히 "항상 전 탭 통합"을 서술하고 있었다. 이 작업은 코드 변경 없이 세 문서 — docs/PRD.md, docs/design-prd.md, docs/PRD-tab-scoped-study.md — 를 실제 구현과 일치시킨다. PRD.md §4.1·§6.1을 선택 범위 기준으로 개정하고 §11 v2 후보 항목을 삭제했으며, design-prd §3에 범위 선택 UI의 위치·스타일(색 토큰·크기·간격·최대 높이·말줄임)과 세션 수 줄 문구·0개 선택 라벨을 #189 구현에서 실제 쓰인 값 그대로 확정해 적었다. PRD-tab-scoped-study.md 상태도 "구현 완료"로 갱신했다.

3설계

  • PRD.md는 최소 개정 + 위임: §4.1·§6.1 본문을 선택 범위 기준으로 고치되, 세부 동작(초기 선택, 저장, 접근성 등)은 재서술하지 않고 docs/PRD-tab-scoped-study.md 참조로 위임했다. 기존 개정 이력 관행(문서 최상단 blockquote + 문장 끝 (날짜 개정 — 사유, #이슈))을 그대로 따랐다.
  • design-prd.md §3은 스타일 값만 확정: PRD-tab-scoped-study.md §4.1이 이미 "무엇을 어떻게 상호작용하는지"를 완비했으므로, design-prd에는 그 문서가 위임한 "구체 값"(색·px·radius·문구)만 추가했다. 동작 사양을 중복 서술하면 두 문서가 어긋날 여지가 생긴다.
  • 값은 전부 구현 코드에서 그대로 옮김: src/index.css·StudyScopePicker.tsx·HomeScreen.tsx를 읽고 실제 렌더 문구·색 토큰·치수를 추출했다 — 임의로 재확정하지 않았다.
  • 기각한 대안 — design-prd §3에 컴포넌트 단위 상세 스펙(JSX 구조 등)까지 옮겨적기: 기존 design-prd 문서는 항상 "값"만 확정하고 구조/상호작용은 기능 PRD류 문서에 맡기는 관행(§4.1~4.6의 zh/generic 분기 표 등)이라, 그 결을 깨지 않았다.
  • 기각한 대안 — §11 v2 후보 삭제 시 취소선 처리(다른 폐기 항목처럼 ~~텍스트~~ 유지): §11은 "구현하지 않음" 목록이고 이미 구현된 항목은 그 정의상 목록에 있을 이유가 없다. §12 결정표처럼 정정 이력 자체가 의미 있는 곳과 달리, 단순 삭제가 맞다(문서 최상단 개정 note에 삭제 사실을 남겨 이력은 보존).
  • 바로잡은 것 — 문서 내 교차 참조 모호성: 초안에서 design-prd.md에 "§4.2 규칙과 동일 조건"처럼 문서명 없이 쓴 두 곳이 있었는데, design-prd.md 자신도 §4.1·§4.2를 학습 화면(모드1 프레임/UI)에 쓰고 있어 모호했다. 완료 조건 "문서 링크·섹션 번호가 유효하다"에 걸리는 문제라 PRD-tab-scoped-study.md §4.2로 명시했다.

5리스크

리스크영향완화책
코드 변경 없음이라 프로덕션 동작에는 영향 없음없음해당 사항 없음
design-prd에 옮겨 적은 px·색 값이 실제 구현과 나중에 어긋남(구현이 먼저 바뀌고 문서가 안 따라감)문서 신뢰도 저하값을 src/index.css에서 그대로 복사했고, 다음에 스타일을 바꾸는 이슈가 design-prd §3을 함께 개정하는 관행(이 저장소 기존 패턴)을 따르면 됨 — 이번 작업 범위 밖
문서 간 교차 참조가 섹션 번호 변경에 취약(향후 §4.x 삽입 시 어긋날 수 있음)낮음 — 문서 전용, 빌드 실패 없음이번에 추가한 참조는 모두 대상 문서명을 명시(PRD-tab-scoped-study.md §4.2 형태)해 같은 문서 내 번호와 혼동되지 않게 했음
