정리 — 폴백 합성·구 변수(APP_PASSWORD·SHEET_ID) 제거

damdam6/vocabulary-study 브랜치 feat/82-remove-fallback-legacy-vars ← main 라벨 enhancement 2026-08-02

1요약

범용화 전환(#81)이 끝나 프로덕션이 PROFILES로 돌고 있으므로, 전환 안전장치였던 폴백 합성 경로와 구 변수를 걷어낸다. worker/lib/profiles.ts의 synthesizeFallbackProfile을 제거해 PROFILES 미설정을 인증 불능이 아닌 설정 오류(500, fail closed)로 확정하고, wrangler.jsonc의 SHEET_ID var를 지운 뒤 worker-configuration.d.ts를 재생성한다. 폴백 env로 워커를 통과시키던 테스트 3개 파일(index.test.ts · routes/register.test.ts · routes/tabs.test.ts)은 단일 PROFILES 구성으로 옮겨야 하며 — 이게 이 작업에서 가장 실질적인 변경분이다 — 문서(PRD-general §3.2·§5.1·§9, 범용화 플랜 작업 7)에 제거 완료를 반영한다. 프로덕션 APP_PASSWORD 시크릿 삭제는 소유자 수동 단계로 PR 본문에 남긴다.

2현황 분석

인증 흐름. worker/index.ts:20이 모든 /api/*에서 resolveProfile(worker/lib/auth.ts:19)을 부르고, 그 안에서 getProfiles(env)(worker/lib/profiles.ts:67)가 isolate 캐시에 프로필 배열을 고정한다. ProfileConfigError는 worker/index.ts:22-32에서 500으로, 비밀번호 불일치는 401로 갈린다 — 이 계약은 이미 완성돼 있고 이번 작업이 건드리지 않는다.

남아 있는 폴백. parseProfiles(worker/lib/profiles.ts:75-78)는 env.PROFILES가 없으면 synthesizeFallbackProfile (worker/lib/profiles.ts:100-118)로 APP_PASSWORD+SHEET_ID에서 { id: "default", name: "단어 암기", modes: ["m1","m2"], contentType: "zh" }를 합성한다. 두 값 중 하나라도 없을 때만 ProfileConfigError다. 폴백 env 조각은 ProfilesEnv(worker/lib/profiles.ts:48-52)에도 선언돼 있다.

설정 잔재. wrangler.jsonc:26-29의 vars 블록이 SHEET_ID 하나만 담고 있고, 생성 파일 worker-configuration.d.ts:4-22의 __BaseEnv_Env·NodeJS.ProcessEnv에 SHEET_ID 리터럴 타입과 APP_PASSWORD가 박혀 있다. 코드에서 env.SHEET_ID를 읽는 곳은 폴백 합성이 유일하다 — 모든 Sheets 호출은 이미 profile.sheetId 파라미터를 받는다.

테스트가 실제 제약이다. 워커를 통과하는 테스트 중 세 파일이 아직 폴백 env로 인증을 통과한다:

  • worker/index.test.ts:14 — 파일 전체가 폴백 스위트다 (makeEnv({ APP_PASSWORD, SHEET_ID })). 다만 담고 있는 커버리지는 폴백 고유가 아니라 인증 게이트 순서(#23)·X-Worker-Version 헤더·health 응답 형태로, 폴백을 지운 뒤에도 남겨야 할 계약이다.
  • worker/routes/register.test.ts:122, worker/routes/tabs.test.ts:9 — { APP_PASSWORD, SHEET_ID } as unknown as Env 손수 캐스트. Sheets 스텁은 URL의 시트 ID를 보지 않으므로(stubSheetsFetch는 경로 패턴만 분기) 프로필 env로 갈아끼우면 그만이다.
  • worker/lib/profiles.test.ts:129-151 — 폴백 합성 단위 테스트 3개.

나머지 워커 테스트(index.profiles · index.sheet-isolation · index.config-error · routes/answer · routes/words · routes/settings · routes/*.generic)는 이미 makeEnv({ PROFILES })를 쓴다 — 옮길 때 그 형식을 그대로 따르면 된다. worker/index.config-error.test.ts:47은 이미 "PROFILES 미설정 → 500"을 검증하지만 구 변수가 함께 없을 때만 확인한다 — 폴백 제거 후에는 구 변수가 있어도 500이어야 한다.

파일당 단일 구성 규약. getProfiles와 비밀번호 다이제스트 캐시가 isolate 수명 동안 첫 성공 구성을 고정하므로, 워커 통합 테스트는 "파일 = isolate = 구성 하나" 규약을 따른다(worker/test-utils.ts:1-5의 주석). 테스트 이관은 이 규약을 깨지 않아야 한다.

문서. docs/PRD-general.md의 §3.1 contentType 행(60행대) · §3.2 폴백 항목(74행) · §5.1 환경변수 표(134행) · §9 전환 순서(186·188행)와 docs/plans/service-generalization.md(37·71·80·86·88·92·93·100행)가 폴백을 현재 사양으로 서술한다. docs/PRD.md는 v1 문서로, 상단(8행)에 "충돌 시 PRD-general 우선"이 이미 명시돼 있다.

3설계

결정 1 — PROFILES 미설정 = 설정 오류. parseProfiles의 첫 분기를 폴백 합성 대신 ProfileConfigError("PROFILES가 설정되지 않았습니다")로 바꾼다. 500 변환·로그·캐시 정책(실패는 캐시하지 않음)은 이미 상위에 있으므로 이 한 줄로 fail closed가 완성된다. ProfilesEnv는 { PROFILES?: string }만 남긴다 — 선택 필드를 유지하는 이유는 미설정 경로를 단위 테스트에서 그대로 표현하기 위함이다.

결정 2 — 폴백 테스트는 지우지 말고 이관한다. worker/index.test.ts는 파일을 삭제하는 대신 단일 프로필 PROFILES 구성으로 갈아끼운다. 담긴 계약(무헤더 401 · 틀린 토큰 401이 health 분기보다 먼저 · 401/200 모두 X-Worker-Version · CF_VERSION_METADATA 부재 시 "unknown" · 응답에 sheetId/비밀번호 미노출)은 폴백과 무관하게 지켜야 하는 것들이고, index.profiles.test.ts(2프로필 해석)와도 역할이 겹치지 않는다. 대안(파일 삭제 후 커버리지를 index.profiles.test.ts에 합치기)은 한 파일이 두 구성을 갖게 돼 isolate 캐시 규약과 충돌하므로 기각.

결정 3 — 생성 타입은 재생성하되 PROFILES를 포함시킨다. wrangler types는 wrangler.jsonc의 vars와 로컬 .dev.vars의 키로 Env를 만든다. 워크트리에는 .dev.vars가 없으므로(메인 체크아웃에만 존재, gitignore됨) 그대로 돌리면 GOOGLE_SERVICE_ACCOUNT_KEY까지 사라진 잘못된 타입이 나온다. 실제 운영 시크릿 구성(GOOGLE_SERVICE_ACCOUNT_KEY + PROFILES)을 담은 워크트리 로컬 .dev.vars(gitignore 대상, 커밋 금지)를 두고 재생성해 Env를 CF_VERSION_METADATA · GOOGLE_SERVICE_ACCOUNT_KEY · PROFILES로 맞춘다. PROFILES가 생성 타입에 들어오면 "생성 파일에 PROFILES가 아직 없다"는 worker/lib/profiles.ts:44-47 주석도 사실이 아니게 되므로 함께 고친다. wrangler 버전은 메인 체크아웃과 동일한 4.110.0이라 런타임 타입 본문 diff는 발생하지 않아야 한다 — 발생하면 리스크 표의 완화책을 따른다.

결정 4 — 프로덕션 시크릿 삭제는 자동화하지 않는다. wrangler secret delete APP_PASSWORD는 되돌리기 어려운 운영 변경이고 이슈에도 "(수동)"으로 적혀 있다. PR 본문에 배포 후 체크리스트로 남기고, 코드가 그 시크릿을 더는 읽지 않으므로 삭제 시점에 제약이 없다는 점을 명시한다.

결정 5 — docs/PRD.md는 개정하지 않는다. v1 사양의 역사 기록이고 상단에 우선순위 선언이 있다. 다만 §7.2 환경변수 표에 "현재는 PROFILES로 대체(PRD-general §5.1)" 한 줄 주석만 더해 grep 잔재가 현행 사양으로 오독되지 않게 한다.

4작업 단계

  1. ✔폴백 합성 제거 — synthesizeFallbackProfile 삭제, parseProfiles의 !env.PROFILES 분기를 ProfileConfigError로 전환, ProfilesEnv에서 APP_PASSWORD·SHEET_ID 제거. 모듈 헤더 주석과 contentType의 "폴백 프로필 포함 하위 호환" 문구도 현행화. worker/lib/profiles.ts
  2. ✔파서 단위 테스트 이관 — "폴백 합성" describe를 "PROFILES 미설정 = 설정 오류"로 교체: parseProfiles({})가 던지는 것에 더해 APP_PASSWORD·SHEET_ID가 있어도 던진다는 회귀 방지 케이스를 넣는다. worker/lib/profiles.test.ts
  3. ✔인증 게이트 스위트 이관 — makeEnv({ APP_PASSWORD, SHEET_ID })를 단일 프로필 makeEnv({ PROFILES: JSON.stringify([...]) })로 교체하고 헤더 주석의 "폴백 경로(#70)" 설명을 "단일 프로필 구성"으로 갱신. health 응답의 profile 기대값도 그 프로필로 맞춘다. worker/index.test.ts
  4. ✔라우트 테스트 env 이관 — 손수 캐스트한 폴백 env를 ../test-utils.ts의 makeEnv({ PROFILES })로 교체(비밀번호·시트 ID 값은 유지해 스텁·단언 무변경). worker/routes/register.test.ts, worker/routes/tabs.test.ts
  5. ✔fail closed 계약 보강 — "PROFILES 미설정 + 구 변수 존재 → 여전히 500" 케이스 추가, 기존 47행 케이스의 폴백 언급 주석 현행화. test-utils.ts 주석의 SHEET_ID 리터럴 타입·파일별 구성 목록도 갱신. worker/index.config-error.test.ts, worker/test-utils.ts 실행 노트 — index.test.ts의 지역 상수 SHEET_ID도 SHEET로 개명했다(값 상수일 뿐이지만 완료 조건의 grep 확인을 흐리지 않도록).
  6. ✔SHEET_ID var 제거 — vars 블록을 통째로(주석 포함) 삭제. wrangler.jsonc
  7. ✔생성 타입 재생성 — npm ci 후 워크트리 로컬 .dev.vars (GOOGLE_SERVICE_ACCOUNT_KEY·PROFILES, 커밋 금지)를 두고 npm run cf-typegen. diff가 Env 헤더 블록에 한정되는지 확인. worker-configuration.d.ts 실행 노트 — 값은 자리표시자("{}"·"[]")로 충분했고, diff는 __BaseEnv_Env·ProcessEnv·해시 3줄에 한정됐다(런타임 타입 변동 없음).
  8. ✔검증 — npm run test · npm run lint · npm run build (tsc -b 포함) 전부 통과. 이어서 APP_PASSWORD/SHEET_ID grep으로 코드·설정 잔재 0 확인.
  9. ✔문서 개정 — PRD-general §3.1 contentType 문구 · §3.2 폴백 항목 제거(제거 완료 기록) · §5.1 표에서 구 변수 행 삭제 · §9 전환 순서 4단계 완료 표기, 범용화 플랜의 작업 7·폴백 서술에 완료 반영, PRD.md §7.2 표에 대체 주석 한 줄. docs/PRD-general.md, docs/plans/service-generalization.md, docs/PRD.md 실행 노트 — 계획에 없던 두 곳을 함께 고쳤다: PRD-general §9의 롤백 문구 (폴백 전제가 깨졌으므로 "코드 롤백만으로 v1 복귀"는 더 이상 사실이 아니다)와, 범용화 플랜 §5의 "작업 6(구 변수·폴백 제거)" 오기를 작업 7로 정정.
  10. ✔커밋·PR — 레포 스타일(한국어 요약 + (#82))로 파일 단위 커밋, 플랜 HTML 최종 상태 포함. PR 본문에 배포 후 수동 단계(프로덕션 APP_PASSWORD 시크릿 삭제 + 프로필 로그인·학습·기록 스모크)를 체크리스트로 남긴다.

5리스크

리스크영향완화책
프로덕션 PROFILES가 어떤 이유로 비면 전 /api/*가 500 서비스 전면 중단 (폴백이 있던 지금은 구 변수로 연명) #81에서 PROFILES 설정·스모크 완료 확인됨(2026-07-27 클로즈). 이 PR은 시크릿을 건드리지 않으며, APP_PASSWORD 삭제는 배포 후 수동 단계로 분리해 되돌릴 여지를 남긴다. 사고 시 롤백은 이 PR revert(폴백 복귀)로 가능.
wrangler types가 로컬 .dev.vars에 좌우돼 엉뚱한 Env를 생성 GOOGLE_SERVICE_ACCOUNT_KEY가 타입에서 사라져 tsc -b 실패 또는 거짓 통과 재생성 전 워크트리 로컬 .dev.vars에 운영과 동일한 키 집합을 채운다. 생성 후 git diff로 Env 헤더 블록만 바뀌었는지 눈으로 확인.
wrangler/workerd 버전 차이로 런타임 타입 55만 줄이 통째로 재작성 리뷰 불가능한 diff 메인 체크아웃과 같은 4.110.0을 npm ci로 설치. 그래도 대량 diff가 나면 재생성을 버리고 __BaseEnv_Env·ProcessEnv 두 블록만 손으로 수정한 뒤 그 사유를 플랜에 기록.
테스트 이관 시 한 파일에 두 프로필 구성이 섞임 isolate 캐시가 첫 구성을 고정해 이후 테스트가 헛통과 "파일 = 구성 하나" 규약 준수 — index.test.ts는 단일 프로필, index.config-error.test.ts에는 성공 구성을 넣지 않는다.
구 비밀번호 사용자 재로그인 필요 여부 사용자 이탈 없음 — #81에서 1번 프로필에 기존 APP_PASSWORD 값을 그대로 옮겼으므로 비밀번호는 동일하다(PRD-general §9).

6테스트 계획

  • ✔단위(파서) — parseProfiles({}) → ProfileConfigError, parseProfiles({ APP_PASSWORD, SHEET_ID }) → 합성하지 않고 ProfileConfigError. 정상 PROFILES 파싱·검증·캐시 테스트는 무변경 통과.
  • ✔통합(fail closed) — makeEnv({}) 및 구 변수만 있는 env로 /api/health, /api/words 호출 → 토큰 유무와 무관하게 500 + console.error + X-Worker-Version 헤더. 이슈 완료 조건 "PROFILES 미설정 시 500 fail closed"의 직접 근거.
  • ✔통합(정상 경로 회귀) — 이관한 worker/index.test.ts가 단일 프로필로 무헤더 401 · 틀린 토큰 401(health 분기보다 먼저) · 정상 토큰 200 + profile 블록 · 응답 본문에 sheetId/비밀번호 미포함 · CF_VERSION_METADATA 부재 시 "unknown"을 그대로 검증.
  • ✔라우트 회귀 — routes/register.test.ts·routes/tabs.test.ts가 env만 바꾼 채 전부 통과(단언·스텁 무변경). 나머지 워커·클라 스위트도 전체 통과.
  • ✔전체 — npm run test(vitest 전 파일) · npm run lint(oxlint) · npm run build(tsc -b + vite) 그린.
  • ✔grep — grep -rn "APP_PASSWORD\|SHEET_ID" --exclude-dir=node_modules 결과가 docs/PRD.md(v1 역사 기록 + 대체 주석)와 플랜 HTML 외에는 없어야 한다.
  • ☐배포 후(수동, PR 본문 체크리스트) — 프로덕션 APP_PASSWORD 시크릿 삭제 후 각 프로필 로그인 → 학습 1문제 → 기록 반영까지 확인. 무인증 401 스모크(#23/#67)는 자동으로 돈다.

7완료 조건

  • 코드·설정에 APP_PASSWORD/SHEET_ID 참조 없음 — grep으로 확인 (예외: docs/PRD.md의 v1 사양 기록, 대체 주석 병기).
  • PROFILES 미설정이 500 fail closed임을 단위·통합 테스트가 고정. 구 변수가 있어도 합성되지 않는다는 회귀 케이스 포함.
  • wrangler.jsonc에 vars 없음, worker-configuration.d.ts의 Env가 CF_VERSION_METADATA·GOOGLE_SERVICE_ACCOUNT_KEY·PROFILES만 선언.
  • npm run test·npm run lint·npm run build 그린.
  • PRD-general §3.2·§5.1·§9와 범용화 플랜에 폴백·구 변수 제거가 반영됨.
  • PR 본문에 배포 후 수동 단계(프로덕션 APP_PASSWORD 시크릿 삭제 + 프로필 스모크)가 체크리스트로 남아 있음 — 이 항목만 머지 후 소유자 확인 사항이다.
