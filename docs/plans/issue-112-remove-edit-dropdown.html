홈 수정 아이콘 드롭다운 제거

1요약

홈 유틸 바의 수정 아이콘(#105)은 현재 팝오버 메뉴를 열어 "단어 등록"·"1회 문제 수 수정"(#110) 두 옵션을 보여준다. #111에서 문제수 편집이 등록 화면 상단 필드로 흡수되면서 두 옵션의 목적지가 완전히 같아졌고, 메뉴는 클릭 한 번을 더 요구하는 무의미한 중간 단계가 됐다. 이 작업은 메뉴·바깥 클릭 닫힘·포커스 전달 배선을 모두 제거하고 수정 아이콘을 사람 아이콘과 동일하게 즉시-동작 버튼으로 단순화한다. 사람 아이콘(프로필 전환)은 이미 메뉴 없는 즉시 동작이라 변경이 없다.

2현황 분석

src/components/HomeUtilBar.tsx:8-14 — 수정 버튼은 onNavigateRegister·onEditSessionLimit 두 콜백을 받고, 내부 menuItems(68-71)가 "단어 등록"/"1회 문제 수 수정" 두 항목으로 각각 연결한다.

메뉴 상태·상호작용 로직이 전체의 절반 이상을 차지한다: menuOpen/menuWrapRef/triggerRef/itemRefs/menuId(61-65), 바깥 pointerdown·Escape 닫힘 이펙트(73-97), 첫 항목 자동 포커스 이펙트(99-102), selectItem(104-107), 화살표 키 이동 moveFocus(111-122)와 그 트리거(124-139), role="menu" 마크업(158-176).

포커스 대상 배선은 HomeUtilBar 밖, 상위 두 곳에 흩어져 있다: src/App.tsx:33의 registerFocusLimit state, App.tsx:49-52의 navigateRegister(focusLimit), App.tsx:78-79에서 HomeScreen에 내려주는 두 콜백, App.tsx:104에서 RegisterScreen에 넘기는 focusSessionLimit={registerFocusLimit}. src/screens/HomeScreen.tsx:17-19,102-106은 이 두 콜백을 그대로 HomeUtilBar까지 통과시킬 뿐이다.

src/screens/RegisterScreen.tsx:44,66,89-90,117-124,304 — focusSessionLimit prop과 limitInputRef/hasFocusedLimitRef, 그리고 값이 준비되는 순간 입력란에 포커스·스크롤하는 이펙트. 같은 파일 293-326을 보면 문제수 필드는 애초에 헤더 바로 아래 항상 렌더되는 독립 섹션이라(#111), 포커스 이동이 없어도 필드는 이미 보인다 — 이 배선은 순수하게 "메뉴에서 어떤 옵션을 골랐는지"를 화면 간에 전달하는 용도였다.

src/index.css:901-942 — .home-util-menu-wrap/.home-util-menu/.home-util-menu-item(+hover/focus-visible) 규칙은 메뉴 전용. .home-util-bar(863-867)·.home-util-button 계열(869-894)·.home-util-icon(896-899)은 수정·사람 버튼이 공유하므로 유지 대상.

사람 버튼은 이미 메뉴가 없다 — HomeUtilBar.tsx:179-183는 onClick={onSwitchProfile} 직결 버튼이고 menuOpen 등 어떤 상태도 참조하지 않는다. 이번 변경의 목표 형태와 정확히 같은 패턴이다.

테스트는 세 파일에 걸쳐 메뉴 동작을 검증한다: src/components/HomeUtilBar.test.tsx(메뉴 열기/항목 순서/첫 항목 포커스/바깥 pointerdown 닫힘/Escape 닫힘/항목 선택 2건), src/screens/HomeScreen.test.tsx(메뉴 두 옵션이 App까지 이어지는지 2건), src/screens/RegisterScreen.test.tsx:159-171(focusSessionLimit 포커스 이동 2건).

docs/design-prd.md §3(85-87행)이 메뉴 스펙(위치·애니메이션·role·닫힘 방식·두 옵션)을 규정하고, §6(151행 "진입", 154행 문제수 필드 마지막 문장)이 그 메뉴를 전제로 진입 경로를 설명한다. §9 결정 로그(204행 "수정 메뉴 형태")와 §10 이슈 매핑(222행 #105 행)도 메뉴를 언급한다.

3설계

채택: 수정 버튼을 사람 버튼과 동일한 형태로 맞춘다 — role="menu"·팝오버·바깥 클릭 닫힘·포커스 이동을 통째로 제거하고, onClick 하나가 곧바로 등록 화면으로 이동시킨다. onNavigateRegister/onEditSessionLimit 두 콜백을 onNavigateRegister 하나로 합친다. App.tsx의 registerFocusLimit/navigateRegister(focusLimit)와 RegisterScreen의 focusSessionLimit은 필드가 이미 화면 상단에 항상 보이므로(§2, #111) 존재 이유가 사라져 함께 삭제한다.

기각한 대안 1 — 메뉴 구조는 남기고 옵션을 하나로 줄인다: 옵션이 하나뿐인 메뉴를 열기 위해 한 번 더 클릭하게 만드는 건 이슈가 지적한 문제(무의미한 선택 단계)를 그대로 남긴다.

기각한 대안 2 — focusSessionLimit 배선은 남기고 메뉴만 제거해 수정 버튼이 항상 포커스+스크롤과 함께 진입하게 한다: 필드가 이미 헤더 바로 아래 있어 스크롤할 거리가 사실상 없고, "왜 등록 화면인데 포커스가 강제로 옮겨가는지" 설명하기 어려운 동작만 남는다. 단순 이동이 더 정직하다.

4작업 단계

  1. 수정 버튼을 사람 버튼과 같은 즉시-클릭 구조로 재작성: props를 onNavigateRegister·onSwitchProfile 둘로 축소하고, menuOpen/menuWrapRef/triggerRef/itemRefs/menuId/menuItems, 바깥 pointerdown·Escape 닫힘 이펙트, 첫 항목 포커스 이펙트, selectItem/moveFocus/handleTriggerKeyDown/handleMenuKeyDown, role="menu" 마크업을 모두 제거. 수정 버튼은 aria-label="수정"·onClick={onNavigateRegister}만 남긴 단순 버튼으로. 관련 파일 상단 주석(#105·#110 설명)도 현재 구조에 맞게 정리. src/components/HomeUtilBar.tsx
  2. 메뉴 전용 CSS 삭제: .home-util-menu-wrap·.home-util-menu·.home-util-menu-item(+hover/focus-visible) 규칙 제거. .home-util-bar·.home-util-button·.home-util-icon은 유지. src/index.css (901~942행 부근)
  3. HomeScreen의 props를 onNavigateRegister 하나로 축소하고 HomeUtilBar로 그대로 전달. src/screens/HomeScreen.tsx
  4. App.tsx에서 registerFocusLimit state와 navigateRegister(focusLimit) 헬퍼를 제거하고, HomeScreen에는 onNavigateRegister={() => setScreen('register')}를 직접 연결. RegisterScreen에 넘기던 focusSessionLimit={registerFocusLimit} prop도 제거. src/App.tsx
  5. RegisterScreen에서 focusSessionLimit prop, limitInputRef, hasFocusedLimitRef, 관련 포커스·스크롤 useEffect를 제거하고 입력란의 ref={limitInputRef}도 정리. 필드 자체(프리필·저장·검증)는 변경 없음. src/screens/RegisterScreen.tsx
  6. HomeUtilBar.test.tsx를 새 구조에 맞게 재작성: 메뉴 열기/항목 순서/첫 항목 포커스/바깥 pointerdown 닫힘/Escape 닫힘 테스트는 제거, "수정 버튼 클릭 시 즉시 onNavigateRegister 호출" 테스트로 대체. 사람 버튼 테스트와 aria-label·SVG 접근성 테스트는 새 props에 맞춰 유지. src/components/HomeUtilBar.test.tsx
  7. HomeScreen.test.tsx에서 "1회 문제 수 수정" prop 전달 테스트를 제거하고, "수정 메뉴의 '단어 등록'…" 테스트를 "수정 버튼 클릭이 onNavigateRegister까지 이어진다"로 단순화. setup()의 mock·쿼리 헬퍼도 갱신. 사람 버튼·로딩 상태 테스트는 그대로. src/screens/HomeScreen.test.tsx
  8. RegisterScreen.test.tsx에서 focusSessionLimit 관련 테스트 2건과 setup()의 focusSessionLimit 매개변수를 제거. 문제수 필드 자체의 프리필/저장/검증/독립성 테스트는 영향 없음. src/screens/RegisterScreen.test.tsx
  9. docs/design-prd.md §3 개정: 85-86행의 메뉴 스펙(위치·애니메이션·role·닫힘·두 옵션)을 "수정 버튼 클릭 시 팝오버 없이 등록 화면으로 즉시 이동"으로 교체. §6 151행에서 "→ 메뉴 '단어 등록'" 문구 삭제, 154행 마지막 문장(메뉴 옵션으로 진입 시 포커스+스크롤)을 삭제. §9 결정 로그의 "수정 메뉴 형태(#105)" 행에 취소선·개정 각주를 추가(기존 "프로필 전환 링크 위치·스타일" 행의 표기 패턴 재사용, #112 언급). §10 이슈 매핑에 #112 행 추가. docs/design-prd.md

5리스크

리스크영향완화책
메뉴 전용 테스트를 지우며 실제로 검증하던 접근성 속성(예: aria-label)까지 함께 잃는다회귀를 못 잡음새 단순 버튼에 대해서도 aria-label·클릭→콜백 테스트를 남겨 커버리지 공백 방지
design-prd §9 결정 로그가 과거 결정("메뉴 채택")과 현재 상태가 어긋난 채로 남음문서 신뢰도 저하기존 "프로필 전환 링크 위치·스타일" 행이 쓰던 취소선+개정 각주 패턴을 그대로 적용
미사용 CSS 규칙이 남아 이후 개발자가 착각낮음 — 코드 정리 이슈4단계에서 메뉴 전용 규칙을 명시적으로 삭제
